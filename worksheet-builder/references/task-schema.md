# Схема данных рабочего листа

Рабочий лист живёт как папка с JSON-файлами, а не как HTML. Ты (Claude) читаешь и
правишь только эти файлы во время диалога с учителем. HTML появляется позже, его
генерирует `scripts/render_worksheet.py` — не пиши HTML руками.

Почему так: правка одного задания не должна требовать чтения/переписывания всего
документа. Задание — отдельный маленький файл, значит правка — маленький, дешёвый диф.

## Структура папки

```
<slug-темы>/
├── meta.json
└── tasks/
    ├── task-01.json
    ├── task-02.json
    └── ...
```

`<slug-темы>` — короткое имя латиницей/цифрами по теме (`kinematics-9th-grade`),
создаётся в текущей рабочей директории teacher'а.

## meta.json

```json
{
  "title": "Кинематика: равномерное и равноускоренное движение",
  "subject": "Физика",
  "grade": "9",
  "language": "ru",
  "school": "",
  "date": "",
  "duration_minutes": 40,
  "instructions": "Необязательное вступление под шапкой (например, инструкция по выполнению).",
  "order": ["task-01", "task-02", "task-03"]
}
```

- `language`: только `"ru"` — служебные подписи листа (шапка, "Ответ:",
  "Верно"/"Неверно", подписи тулбара) через словари `STRINGS`/`UI_STRINGS` в
  рендерере.
- `order` — явный список id заданий в нужном порядке. Менять порядок = менять только этот массив, файлы заданий не трогать.
- Поля `school`, `date` можно оставить пустыми — рендерер выведет их как прочерк для заполнения от руки.

## Модель: задание = список компонентов

Каждое задание — это не один монолитный "тип", а **плоский упорядоченный список
компонентов** (`components`). У каждого компонента — `type`, один из 5
структурных **форматов** (не педагогических категорий — см. "Форматы
компонентов" ниже), и независимое булево поле `answerable`, которое решает,
несёт ли компонент ответ для тичер-версии и получает ли букву `a)/b)/в)`.
Один формат может использоваться и для информационного, и для отвечаемого
компонента — форматы про *структуру рендера*, `answerable` — про *роль в
задании*, это две независимые оси.

Один график/таблица/схема, за которым идёт несколько разноформатных вопросов
— это просто такой компонент один раз в списке (`answerable: false`), а
дальше несколько отвечаемых компонентов подряд. Дублировать
`chart_spec`/`svg_snippet` под каждый вопрос не нужно.

```json
{
  "id": "task-01",
  "points": 2,
  "prompt": "Общее вступление, показывается один раз до всех компонентов (необязательно).",
  "layout": [1, 2],
  "components": [
    { "type": "...", "answerable": false, "...": "..." },
    { "type": "...", "answerable": true, "...": "..." },
    { "type": "...", "answerable": true, "...": "..." }
  ]
}
```

- `id`, `components` — обязательны. `components` — минимум один элемент, даже
  для самого простого "один открытый вопрос" задания (единая форма файла, без
  сокращённой записи для тривиального случая).
- `points` — опционально, общий балл рядом с номером задания. Независим от
  `points` внутри отдельных компонентов (см. ниже) — не суммируется автоматически.
- `prompt` — опционально, общий контекст/вступление, выводится один раз перед
  всеми компонентами. Если у задания всего один компонент и объяснять нечего —
  не указывай, тогда компонент показывается сразу с номером задания.
- `layout` — опционально, раскладка компонентов по строкам, см. "Раскладка:
  `layout`" ниже. По умолчанию (не указано) — каждый компонент в своей
  полноширинной строке (всё "в столбик").

Каждый компонент — свой JSON-объект с обязательными `type`, `prompt` и
специфичными для формата полями. `points` — опционален на уровне компонента: если
задан, балл печатается рядом с буквой компонента (см. "Буквы" ниже).

```json
{
  "type": "prompt_response",
  "answerable": true,
  "points": 2,
  "prompt": "Текст задания. Простые обозначения — обычным текстом: υ₀, α, ≠, м/с². Формулы — LaTeX, только когда это оправдано: блоком $$E_k = \\frac{m\\upsilon^2}{2}$$.",
  "...": "поля конкретного формата"
}
```

Приоритет для любого символа/обозначения — **текст → `<sup>`/`<sub>` → LaTeX**,
подробно и с таблицей готовых символов в `references/symbols.md`. LaTeX
(`$...$`/`$$...$$`) подключается через KaTeX и оправдан только для настоящих
составных выражений (дробь, корень с содержимым, система уравнений) — не для
одной греческой буквы или значка сравнения.

## Буквы и баллы

Буквы `a)`, `b)`, `в)`... получают **только компоненты с `answerable: true`**,
по порядку следования в списке `components` (не по строкам `layout` — нумерация
сквозная по документу), и только если таких компонентов в задании больше
одного. Компоненты с `answerable: false` (или без этого поля — по умолчанию
`false`) буквы никогда не получают. Если в задании всего один отвечаемый
компонент — он рендерится без буквы, как обычное простое задание (буква не
нужна, отвечать больше не на что).

Букву можно задать явно через `label` на самом компоненте (`"label": "a"`); если
не задано — рендерер проставляет `a, b, c...` сам по порядку. Не дублируй букву
внутри `prompt` компонента — рендерер выводит её отдельным элементом перед
текстом, а не как часть текста.

Явный `label` всегда побеждает — даже если это единственный отвечаемый
компонент в задании (правило "один отвечаемый компонент — без буквы" выше
описывает поведение по умолчанию, а не запрет: если ты явно попросил букву
через `label`, она покажется). Автоматические буквы при этом пропускают
значения, уже занятые явными `label` на других компонентах того же задания
— так что `label: "z"` на первом компоненте не приведёт к тому, что второй
получит `"b"` вместо `"a"`.

`answerable` не зависит от того, заполнены ли `answer`/`answers`/`correct` и
т.п. — эти поля управляют только тем, что показывается в тичер-версии.
Компонент с `answerable: true`, но без реально заданного `answer`, всё равно
получит букву (пустая тичер-подсказка) — так проще, чем ловить рассинхрон
между "явно отвечаемый" и "случайно заполненный".

Баллы — независимо на двух уровнях: `points` всего задания (общий балл рядом с
номером) и `points` отдельного компонента (балл рядом с его буквой, если у
компонента есть буква). Суммирование не проверяется автоматически.

## Раскладка: `layout`

По умолчанию (поле `layout` не задано) все компоненты идут один под другим на
всю ширину — так же, как сегодня выглядит любое простое задание.

`layout` — массив, партиционирующий `components` по порядку на строки. Каждый
элемент массива — это либо:
- **целое число N** — следующие N компонентов идут в одну строку, поровну
  делят ширину (для двух — 50/50, для трёх — по ~33% и т.д.);
- **список процентов**, например `[40, 60]` — следующие столько же компонентов
  (сколько чисел в списке) идут в одну строку с явно заданной шириной каждого
  (сумма должна быть 100).

Сумма количества компонентов по всем элементам `layout` обязана равняться
длине `components`.

```json
{
  "id": "task-13",
  "prompt": "Идеальный газ переходит из состояния 1 в 2, из 2 в 3 согласно графику V-T. Постройте графики этого же процесса в координатах p-V и p-T.",
  "layout": [1, 2],
  "components": [
    { "type": "visual", "answerable": false, "chart_spec": { "...": "дан V-T график с тремя состояниями" } },
    { "type": "visual", "answerable": true, "prompt": "Постройте график в координатах p-V.", "chart_spec": { "...": "только оси" }, "answer_chart_spec": { "...": "правильная ломаная p-V" } },
    { "type": "visual", "answerable": true, "prompt": "Постройте график в координатах p-T.", "chart_spec": { "...": "только оси" }, "answer_chart_spec": { "...": "правильная ломаная p-T" } }
  ]
}
```
Здесь `layout: [1, 2]` — первая строка из 1 компонента (дан V-T на всю
ширину), вторая строка из 2 компонентов (p-V и p-T бок о бок, по 50%
каждый). Первый компонент без буквы (`answerable: false`), второй и третий
получают `a)` и `b)` (`answerable: true`).

В браузере любое задание, где на экране в итоге больше одной строки, получает
hover-кнопки "+"/"-" на каждой строке (появляются при наведении на строку,
строка при этом подсвечивается) — учитель может прямо на экране
перегруппировать компоненты по строкам/колонкам точечно, без правки JSON:
"+" забирает первый компонент следующей строки как новую колонку текущей,
"-" выселяет последний компонент текущей строки в новую строку в конце
документа. Как и остальные переключатели тулбара (ниже), это состояние
экрана — что видно на момент печати (Ctrl+P), то и печатается; при
пересборке из JSON раскладка возвращается к значению `layout`. Кастомные
проценты (`[40, 60]`) переживают рендер, но не переживают первый клик по
"+"/"-" в этом задании — после него колонки этой строки делят ширину поровну.

Шапка задания (номер + `prompt`) для этой раскладки — тоже компонент: если
задание не сведено к "одна строка = один вопрос без вступления" (см.
`single_component` в рендерере), шапка занимает свою строку 0 сверху,
независимо от `layout` (который партиционирует только `components`, шапку не
считает). Её тоже можно смёрстить через "+" с первой строкой компонентов —
например, чтобы короткий текст задания встал рядом с графиком, а не над ним.

## Форматы компонентов

5 форматов, сгруппированных по структуре данных, которую рендерер реально
потребляет, а не по педагогическому смыслу. Каждый может быть и
информационным (`answerable: false`), и отвечаемым (`answerable: true`) —
исключение см. в описании `prompt_response`.

### `text` — текст, опционально с пропусками
```json
{ "type": "text", "answerable": false, "prompt": "Свободный текст-связка между другими компонентами." }
```
Без `text_template`/`blanks` — обычный информационный абзац. Для отдельного,
самостоятельного абзаца, когда task-level `prompt` уже занят общим
вступлением, а между компонентами нужен ещё один кусок пояснения.

Как и `prompt_response`/`visual`, поддерживает опциональное `answer` —
текстовая тичер-заметка, полезна, когда `text` используется как
`answerable: true` без `text_template` (чисто устный/письменный вопрос без
пропусков и без разлинованного места под решение — ответ обсуждается устно
или пишется на отдельном листе, а здесь нужна только шпаргалка для учителя).
`list` (plain/`statement_bool`) и `table` это поле не читают — у них свои
механизмы разметки правильного ответа (`correct` на пунктах, `answers` по
ячейкам), добавлять туда `"answer"` бессмысленно.

```json
{
  "type": "text",
  "answerable": true,
  "prompt": "Заполните пропуски.",
  "text_template": "Единица измерения силы в СИ — ___1___. Она названа в честь ___2___.",
  "blanks": {"1": "ньютон", "2": "Исаака Ньютона"}
}
```
С `text_template`+`blanks` — заполнить пропуск в тексте. Каждый пропуск —
плейсхолдер `___N___`, рендерер заменит его на подчёркнутую линию нужной
ширины (либо на ответ, в тичер-версии).

**Важно:** никогда не размещай `___N___` внутри математических `$...$`/`$$...$$`.
Рендерер вставляет пропуск как отдельный HTML-элемент, из-за этого разрывается
текстовый узел, и KaTeX перестаёт видеть закрывающий `$` — формула не
отрендерится, а на листе останутся сырые доллары. Пиши пропуск рядом с
формулой, а не внутри неё:
- Плохо: `"$F = m___1___$"` (пропуск внутри математики ломает формулу)
- Хорошо (здесь LaTeX вообще не нужен — уравнение простое): `"Согласно F = ma, если m = 2 кг и a = 3 м/с², то F = "` + пропуск `___1___`
- Хорошо, если формула действительно составная: `"Согласно $$E_k=\frac{m\upsilon^2}{2}$$, если m = 2 кг и υ = 3 м/с, то $E_k=$ "` + пропуск `___1___` (пропуск всё равно снаружи `$...$`)

### `list` — массив пунктов, форма и режим ответа заданы `item_style`

`items` — всегда основной (левый) список; `item_style` — единственное поле,
которое решает, как рендерится список и что значит "правильный ответ" в нём
(по умолчанию `"plain"`). Форма пункта внутри `items` зависит от `item_style`:

```json
{ "type": "list", "answerable": false, "prompt": "Перечислите основные величины кинематики.", "items": ["Путь", "Перемещение", "Скорость", "Ускорение"], "ordered": false }
```
`item_style` не задан (по умолчанию `"plain"`) — голый маркированный/
нумерованный список, `items` — массив строк. `ordered` — опционально, по
умолчанию `false` (`<ul>`), `true` — `<ol>`.

```json
{
  "type": "list",
  "answerable": true,
  "item_style": "statement_bool",
  "prompt": "Отметьте, верны ли утверждения.",
  "items": [
    {"text": "Скорость — скалярная величина.", "correct": false},
    {"text": "1 Н = 1 кг·м/с².", "correct": true}
  ]
}
```
`item_style: "statement_bool"` — верно/неверно: каждый пункт `{"text", "correct"}`,
рендерится строкой с отметкой Верно/Неверно у каждого утверждения (только в
тичер-версии).

```json
{
  "type": "list",
  "answerable": true,
  "item_style": "ranking",
  "prompt": "Расставьте перечисленные скорости движения тел в порядке возрастания (1 — наименьшая скорость).",
  "items": [
    {"text": "Автомобиль в городе: 60 км/ч", "rank": 3},
    {"text": "Пешеход: 5 км/ч", "rank": 1},
    {"text": "Скорый поезд: 120 км/ч", "rank": 4},
    {"text": "Велосипедист: 20 км/ч", "rank": 2}
  ]
}
```
`item_style: "ranking"` — упорядочивание: каждый пункт `{"text", "rank"}`, где
`rank` — верная позиция (1..N, обязана быть перестановкой без повторов и
пропусков — рендерер проверяет это и падает с понятной ошибкой, если нет).
Порядок показа — это порядок `items` в JSON (обычно специально перемешанный
относительно `rank`), рендерер сам не перемешивает и не сортирует. Рядом с
каждым пунктом печатается пустой квадрат для ответа (в тичер-версии — с
верным номером позиции) — тот же визуальный язык, что у `statement_bool`, но
отдельные CSS-классы (`.rank-row`/`.rank-square`), не переиспользующие
`.tf-row`/`.tf-square`, чтобы будущая правка стиля true/false не задела
ranking незаметно.

```json
{
  "type": "list",
  "answerable": true,
  "item_style": "choice",
  "prompt": "Автомобиль движется равномерно прямолинейно. Как изменяется его скорость со временем?",
  "items": [
    {"text": "Увеличивается пропорционально времени"},
    {"text": "Уменьшается пропорционально времени"},
    {"text": "Не изменяется", "correct": true},
    {"text": "Изменяется случайным образом"}
  ],
  "variants_layout": "single-column",
  "answer": "При равномерном движении скорость постоянна по определению"
}
```
`item_style: "choice"` — вопрос с вариантами ответа: каждый пункт `{"text"}`,
у правильного(ых) — `"correct": true` (можно на нескольких пунктах сразу для
множественного выбора, отдельного флага для этого не нужно — форма ответа
и так видна по количеству `correct: true` среди `items`). Рендерятся буквами
`a) b) c)...` (тем же `LOWER_LETTERS`, что и буквы отвечаемых компонентов
задания — независимая нумерация, не путать одно с другим), верный вариант
отмечается галочкой и жирным только в тичер-версии. `variants_layout` —
опционально, по умолчанию `"single-column"`. Варианты: `"single-column"`
(каждый вариант на своей строке), `"two-column"` (CSS-колонки), `"inline"`
(варианты друг за другом в строку). В сгенерированном HTML под компонентом
есть тулбар "Варианты: 1 колонка / 2 колонки / В строку" — можно переключать
прямо в браузере (см. "Интерактивные элементы вёрстки" в
`design-system.md`); поле в JSON задаёт только начальную раскладку. `answer`
— опционально, текстовое пояснение к ответу.

```json
{
  "type": "list",
  "answerable": true,
  "item_style": "matching",
  "prompt": "Установите соответствие между величиной и её единицей измерения.",
  "items": [
    {"text": "Сила", "match": "Н"},
    {"text": "Работа", "match": "Дж"},
    {"text": "Мощность", "match": "Вт"}
  ],
  "right_items": ["Вт", "Н", "Дж"]
}
```
`item_style: "matching"` — сопоставление: каждый пункт `{"text", "match"}`,
`match` — значение из `right_items`, которое ему соответствует (тот же
принцип, что `correct` у `statement_bool`/`choice` — ответ размечается прямо
на пункте, а не в отдельной структуре сбоку). `right_items` — обязательное
отдельное поле, задаёт и порядок/состав правого столбца — рендерер нумерует
левый список (`items`) цифрами, правый (`right_items`) буквами, ученик пишет
буквы рядом с цифрами. Количество элементов слева и справа не обязано
совпадать: `right_items` может содержать лишние варианты-дистракторы, не
встречающиеся ни в одном `match`, — просто продумай тогда явно, какие
варианты дистракторы, при написании. `right_items` не выводится
автоматически из `match`-значений намеренно: порядок показа (обычно
перемешанный, не совпадающий с порядком `items`) — это самостоятельное
решение автора, а не производная информация.

**Composite-рецепт: подпись рисунка по банку слов.** Не отдельный
`item_style`, а `matching` в паре с `visual`-компонентом: рисунок с
пронумерованными точками/стрелками (`answerable: false`) сразу над списком, а
`items` — с **пустым `"text": ""`** у каждого пункта, `match` — верный термин.
Левая колонка `matching` и так нумеруется автоматически (`<ol type="1">` →
`1.`, `2.`, `3.`...) — если порядок `items` в JSON совпадает с порядком цифр
на самом рисунке, эта авто-нумерация и есть привязка к картинке, дублировать
цифру ещё и текстом не нужно:
```json
[
  {
    "type": "visual",
    "answerable": false,
    "raw_svg": "<svg>...рисунок с кружками-цифрами 1,2,3,4 у нужных точек...</svg>"
  },
  {
    "type": "list",
    "answerable": true,
    "item_style": "matching",
    "prompt": "Подпишите обозначенные на схеме силы, используя слова из списка справа.",
    "items": [
      {"text": "", "match": "Сила тяжести"},
      {"text": "", "match": "Сила реакции опоры"},
      {"text": "", "match": "Сила трения"},
      {"text": "", "match": "Сила тяги"}
    ],
    "right_items": ["Сила трения", "Сила тяги", "Сила тяжести", "Сила реакции опоры"]
  }
]
```
**Важно:** соответствие "N-й пункт `items` = точка с цифрой N на рисунке"
ничем не проверяется кодом — только порядком, в котором ты сам перечислил
`items`. Расставляй пункты в том же порядке, что и цифры на картинке, и
дважды сверься глазами перед показом учителю; рендерер не знает, что вообще
изображено на `raw_svg`, и не может поймать рассинхрон.

### `table` — headers + rows
```json
{
  "type": "table",
  "answerable": false,
  "prompt": "Плотности некоторых веществ.",
  "headers": ["Вещество", "ρ, кг/м³"],
  "rows": [["Вода", "1000"], ["Сталь", "7800"], ["Воздух", "1.29"]]
}
```
Без `null`-ячеек — обычная справочная таблица, которая просто дана.

```json
{
  "type": "table",
  "answerable": true,
  "prompt": "Заполните таблицу значений.",
  "headers": ["t, с", "υ, м/с", "s, м"],
  "rows": [
    ["0", "0", "0"],
    ["1", null, "1"],
    ["2", "2", null]
  ],
  "answers": {"1,1": "1", "2,2": "4"}
}
```
`null` в `rows` — пустая ячейка для заполнения. `answers` — ключ `"row,col"`
(0-индексация), используется только в тичер-версии, нужен только если в
`rows` вообще есть `null`.

### `prompt_response` — вопрос + место под ответ
```json
{
  "type": "prompt_response",
  "answerable": true,
  "prompt": "Тело движется со скоростью 5 м/с. Найдите путь за 10 с.",
  "response": "lines:4",
  "answer": "s = vt = 5 * 10 = 50 м"
}
```
`response` — обязательное поле, один из трёх видов места под ответ:
- `"lines:N"` — N разлинованных строк под решение (обычно 3-6). `show_response`
  — опционально, по умолчанию `true`; если `false`, область под решение
  рендерится сразу скрытой (`display:none`). В сгенерированном HTML под
  компонентом есть тулбар "Место для решения: Показать/Скрыть" — учитель
  может включить/выключить прямо в браузере перед печатью, не трогая JSON
  (см. "Интерактивные элементы вёрстки" в `design-system.md`); поле в JSON
  задаёт только начальное состояние при рендере.
- `"blank"` — короткая подчёркнутая линия для ответа в одну строку.
- `"none"` — ничего под вопросом (ответ устный/для обсуждения, либо есть
  только `answer` для тичер-версии без визуального места под ответ).

Этот формат — единственный, где почти всегда стоит `answerable: true` (это и
есть "явный вопрос"), но технически `answerable: false` тоже допустимо для
чисто риторического вступления без ожидаемого ответа.

### `visual` — SVG, опционально + второй "ответный" SVG
```json
{
  "type": "visual",
  "answerable": false,
  "prompt": "На графике показана зависимость скорости тела от времени.",
  "chart_spec": {
    "chart_type": "line",
    "x_label": "t, с",
    "y_label": "υ, м/с",
    "x_range": [0, 10],
    "y_range": [0, 20],
    "series": [
      {"label": "Тело A", "points": [[0,0],[5,10],[10,20]], "style": "solid"},
      {"label": "Тело B", "points": [[0,5],[10,15]], "style": "dashed"}
    ]
  }
}
```
Ровно одно из трёх полей задаёт основной визуал:
- `chart_spec` — не рисуй SVG сам, дай данные, рендерер строит единообразный
  ч/б-график по `charts-and-graphs.md`. `style`: `solid`/`dashed`/`dotted` —
  так серии различаются без цвета. `chart_type`: `line`/`bar`/`scatter`.
- `svg_snippet`: `{"name": "...", "params": {...}}` — сначала проверь словарь
  `SVG_SNIPPETS` в `scripts/visuals.py` (сейчас: `inclined_plane`,
  `simple_circuit`).
- `raw_svg`: `"<svg ...>...</svg>"` — как исключение, если готового генератора
  нет, строго следуя стилю из `charts-and-graphs.md` (толщина линий, шрифт
  подписей, отсутствие цвета, разумный размер под колонку).

Опционально ровно одно из `answer_chart_spec`/`answer_svg_snippet`/
`answer_raw_svg` — второй визуал, тот же механизм, показывается только в
тичер-версии (например, график с достроенной кривой или схема с дорисованными
силами). Плюс опциональное текстовое `answer`, независимо от ответного
визуала (можно дать оба, можно только текст). Без основного визуала совсем
(и без ответного) — ученику показывается просто подписанное пустое место
(например, под свободное рисование схемы).

```json
{
  "type": "visual",
  "answerable": true,
  "prompt": "Постройте график зависимости давления от объёма (изотерма).",
  "chart_spec": { "chart_type": "line", "x_label": "V, м³", "y_label": "p, Па" },
  "answer_chart_spec": {
    "chart_type": "line", "x_label": "V, м³", "y_label": "p, Па",
    "series": [{"label": "1→2", "points": [[1, 6],[2, 3],[3, 2]], "style": "solid"}]
  }
}
```
Здесь `chart_spec` без `series` (только оси/диапазон) — ученику даются пустые
оси, чтобы начертить график самостоятельно; `answer_chart_spec` — полноценный
`chart_spec` с `series`, рисуется тем же генератором, но только в
тичер-версии, поверх тех же осей — это и есть эталонный ответ.

## Пример: один график, два разных вопроса по нему

График — один компонент (`answerable: false`), а вопросы — любое число
отвечаемых компонентов после него в том же списке:

```json
{
  "id": "task-10",
  "points": 5,
  "prompt": "Велосипедист разгоняется равноускоренно из состояния покоя. На графике показана зависимость его скорости от времени.",
  "components": [
    {
      "type": "visual",
      "answerable": false,
      "chart_spec": {
        "chart_type": "line",
        "x_label": "t, с",
        "y_label": "υ, м/с",
        "x_range": [0, 5],
        "y_range": [0, 10],
        "series": [{"label": "Велосипедист", "points": [[0, 0], [4, 8]], "style": "solid"}]
      }
    },
    {
      "type": "prompt_response",
      "answerable": true,
      "prompt": "Найдите ускорение велосипедиста.",
      "response": "lines:3",
      "points": 2,
      "answer": "a = Δυ/Δt = 8/4 = 2 м/с²"
    },
    {
      "type": "prompt_response",
      "answerable": true,
      "prompt": "Используя график, определите путь, пройденный велосипедистом за первые 4 с.",
      "response": "blank",
      "points": 3,
      "answer": "s = υt/2 = 8*4/2 = 16 м"
    }
  ]
}
```
Первый компонент (`visual`, `answerable: false`) без буквы — он
информационный. Второй и третий — `a)` и `b)`, оба видят один и тот же
график выше по документу (`layout` не задан — все три компонента идут в
столбик, график сверху, вопросы под ним).

## Мини-превью одного задания

Не обязательно собирать весь лист, чтобы проверить одно задание:
```
python scripts/render_worksheet.py <папка> --task task-04
```
выводит `task-04.preview.html` — маленький HTML с одним этим заданием в реальных
стилях. Используй это после каждой правки задания вместо полной сборки — дешевле
и быстрее.
