# Worksheet Builder

Собирает учебный документ в два слоя: **контент — маленькие JSON-файлы**
(по одному на верхнеуровневый блок), **вёрстка — детерминированный
рендерер**, который превращает их в самодостаточный HTML (центрированная
колонка ~800px, открывается в любом браузере). Единый стиль всех документов
гарантирует код рендерера, а не память между сообщениями.

Документ универсален: конспект, объяснение, набор заданий или всё вместе —
теория и задачи свободно перемежаются в одном файле. Ответы заданий не
печатаются в теле — рендерер собирает их в секцию «Ответы» в конце
документа; раздаточный вариант без ответов — один флаг. Отдельный сценарий
с тем же ядром: **отдельная SVG-иллюстрация** — раздел «Отдельная
иллюстрация».

## Запуск рендерера

Ставить ничего не нужно, все команды — так:

```
python <путь-к-skill>/scripts/render.py <папка-черновика>
```

При первом запуске в сессии `render.py` сам доустановит pydantic (несколько
секунд, нужна сеть); дальше рендеры мгновенные. Если установка не удалась —
он напечатает понятную ошибку, сообщи её учителю.

## Жёсткие правила

1. **Никогда не пиши итоговый HTML документа или SVG иллюстрации руками** —
   твоя работа только контент в JSON по схеме
   `references/document-schema.md`; вёрстку и рисунки делает рендерер.
   В сгенерированных HTML/SVG ничего не редактируется — любая правка идёт
   через JSON и пересборку.
2. **Перед созданием или правкой JSON читай
   `references/document-schema.md`** — там вся схема: манифест
   `document.json`, верхнеуровневые блоки, дерево блоков задания, все виды
   вопросов и контейнеры. Схема строго проверяется при сборке: опечатка в
   поле, неизвестное значение, битая ссылка — ошибка с точным путём до
   блока, все ошибки перечисляются разом.
3. **Файлы сессии эфемерны.** Итог отдавай учителю на скачивание. В
   `document.html` рендерер встраивает исходный черновик
   (`<script type="application/json" id="document-source">` в конце файла)
   — этого одного файла достаточно, чтобы вернуться к правкам в другой
   сессии: извлеки из него JSON и разложи обратно в `document.json` +
   `blocks/*.json`.
4. **Правка = редактирование одного файла в `blocks/`.** Не перечитывай и
   не переписывай остальные файлы или собранный HTML ради одной правки.
5. **У вопроса всегда есть условие — блок `text` рядом.** Вопрос несёт
   только аппарат (варианты, утверждения, оси, пропуски), формулировку
   несёт соседний `text`; у `open` тело вообще пустое, и без условия от
   задания остаётся один номер. Достаточно одного `text` на уровне задания
   — повторять его в каждом `part` не нужно, но задание без единого `text`
   рендерер отвергает. Это относится и к «самоочевидным» видам: у `match`
   пишется «Сопоставьте…», у `fill_text` — «Вставьте пропущенные слова».

## Обратная связь разработчику (фаза тестирования — удалить перед распространением)

Учитель, с которым ты работаешь, — одновременно разработчик этого скилла и
тестирует его. Поэтому, как только просьба упирается в границы скилла,
сообщай об этом **сразу, в том же ответе**, а не после уточняющего вопроса:

- **Просьба выполнима наполовину** (нет подходящего вида вопроса/компонента/
  поля; визуал не поддерживается; валидация запрещает нужную комбинацию) —
  сделай выполнимую часть и явно скажи, какая часть не выражается и почему.
  Никогда не подменяй молча: не упрощай просьбу до ближайшей выразимой и не
  выдавай приближение за точное выполнение.
- **Называй ограничение конкретно**: какой справочник/правило схемы его
  фиксирует (например: «иллюстрации-схемы вне scope — только `graph` и
  `instrument`», «`row` не вкладывается в `row`»), а не общее «так нельзя».
- **Предлагай улучшение в терминах схемы**: новое поле, новый вид вопроса,
  новый `kind` прибора — одной-двумя фразами, чтобы разработчик мог оценить
  и завести доработку.
- **Сообщай и о подозрениях на баг**: непонятная ошибка валидации, результат
  рендера, противоречащий справочнику, нечитаемый/некрасивый фрагмент SVG —
  это сигнал разработчику, даже если задачу удалось обойти.

Формат: в конце ответа компактный блок «⚠️ Для разработчика: …» (2–5 строк:
что упёрлось, во что именно, идея доработки). Если границ не встретилось —
блок не нужен; не выдумывай замечания ради блока.

## Фаза 1 — обсуждение и черновик

1. Проясни тему, класс/возраст и состав документа: только задания, только
   теория или вперемешку (объяснение + задачи — нормальный документ). Можно
   начинать с одного-двух блоков и добавлять по ходу разговора.
2. Заведи папку черновика (слаг по теме, например `kinematics-9th-grade/`)
   с `document.json` и по файлу `blocks/<id>.json` на верхнеуровневый блок:
   `id` совпадает с именем файла, `order` в `document.json` перечисляет все
   файлы. Анкета-шапка («Школа/класс … Фамилия Имя …») — опциональный
   `header` в `document.json`: нужен самостоятельной работе, не нужен
   конспекту. Если учитель продолжает ранее начатый документ — попроси
   загрузить его `document.html` (внутри встроен черновик, см. правило 3)
   либо папку-черновик.
3. Верхнеуровневые блоки: подзаголовок раздела `heading`, чистые компоненты
   (`text`/`table`/`graph`/`list`/`instrument`) для теории, `row` для
   компонентов бок о бок и `task` — нумерованное задание. Внутри `task` —
   дерево блоков: компоненты, один из 9 видов вопросов (`open`, `choice`,
   `match`, `fill_text`, `fill_table`, `plot`, `true_false`, `rank`,
   `classify` — ответ инлайн, печатается в секции «Ответы»),
   контейнер-подзадание `part` для пунктов а)/б)/в) и layout-контейнер
   `row`. Задания нумеруются сквозняком сами — теория между ними нумерацию
   не сдвигает. Состав и инварианты — в `references/document-schema.md`.
   Готовую задачу учителя просто оформи подходящим видом вопроса; «придумай
   задачи по теме» — сочиняй сам под класс/уровень.
4. Место, где ученик пишет, — **отдельный блок рядом с вопросом**, а не
   поле вопроса. Выбирай по тому, что ученик будет делать:
   - расчёт, вывод формулы, развёрнутый ответ →
     `{"type": "paper", "ruling": "lines", "rows": 3}` (2–3 строки на
     короткую подстановку, 4–6 на вывод);
   - короткий ответ числом или словом → `{"type": "answer_line"}`
     (строка «Ответ: ______»);
   - «постройте график» без заданных осей → квадратная миллиметровка
     `{"type": "paper", "ruling": "mm", "rows": 12, "cols": 12}` (единицы —
     сантиметровые клетки, не миллиметры!); если оси с диапазонами задаёшь
     ты — это вопрос `plot`, там оси уже нарисованы;
   - чертёж, схема опыта → `{"type": "paper", "ruling": "plain", "rows": 6}`
     или `"dots"`;
   - отвечают устно / пишут в соседней таблице → блока нет вообще.
   Подробности и ограничения размеров — `references/artifacts/paper.md`.
5. Обозначения и формулы: обычный текст и Unicode-символы (`α`, `≠`, `м/с²`,
   `υ₀`), LaTeX — только для действительно сложного (дроби, корни). Скорость
   — греческая `υ`, не латинская `v`. Перед формулами сверься с
   `references/symbols.md`.
6. Графики (`graph`/`plot`) — не рисуй SVG сам, задай данные
   (`x_range`/`y_range`/`series`) по `references/charts-and-graphs.md`.
   Измерительные приборы (линейка, мензурка, термометр, динамометр,
   амперметр, вольтметр, манометр, весы циферблатные и рычажные с гирями,
   спидометр, секундомер, штангенциркуль с нониусом, цифровые
   мультиметр/весы/секундомер; классы точности и многопредельные шкалы —
   задачи на цену деления и погрешности) — компонент `instrument`, тоже
   только данными, по `references/artifacts/instruments.md`. Остальные
   иллюстрации/схемы (наклонная плоскость, электрическая цепь) не
   поддерживаются — опиши условие текстом.
7. Быстрый просмотр одного блока без сборки всего документа:
   ```
   python <путь-к-skill>/scripts/render.py <папка> --block task-03
   ```
   даёт `task-03.preview.html` в реальных стилях (задание — под своим
   настоящим номером и со своей строкой ответов).

## Скелеты документов

Типовой состав `order` под жанр — отправная точка, а не форма: блоки
свободно добавляются, убираются и перемешиваются.

- **Конспект / объяснение темы.** `heading` → `text` → `graph` или `table`
  → `heading` → `text`… Заданий нет, `header` не нужен, секция «Ответы» не
  печатается сама собой (пустая не выводится).
- **Лист заданий.** `header`-анкета в `document.json` + подряд `task`-блоки.
  В каждом: `text` с условием, при необходимости компонент (`graph`,
  `instrument`, `table`), вопрос, место под ответ (`paper`/`answer_line`).
- **Смешанный документ** (самый частый). Теория и задания вперемежку:
  `heading` → `text` → `task` → `task` → `heading` → `graph` → `task`…
  Нумерация заданий сквозная, теория её не сдвигает. Образец —
  `examples/kinematics-9th-grade/`.
- **Лабораторная работа.** `heading` «Цель» → `text`; `heading` «Ход
  работы» → `text` с шагом → `table` для измерений → `paper` под расчёты;
  `heading` «Вывод» → `paper`. Ответов у такого листа обычно нет — собирай
  сразу с `--no-answers`.

## Что решаешь ты

Схема проверяет структуру, а не методику. Эти решения — за тобой, по
содержанию, и переспрашивать по каждому не нужно:

- **какой вид вопроса** подходит учебной цели (`choice` — проверить
  понимание, `open` — расчёт с решением, `match` — термины и единицы,
  `rank`/`classify` — систематизация, `plot`/`fill_table` — работа с
  данными);
- **разлиновка и размер** места под ответ — по объёму решения
  (`references/artifacts/paper.md`);
- **дробить ли задание на `part`** или оставить одним вопросом;
- **сколько заданий и в каком порядке** — от простого к сложному;
- **нужна ли анкета-шапка** и **нужен ли `explanation`** (только там, где
  ответ неочевиден).

Общее правило: у `open` почти всегда есть соседнее место под ответ
(`paper` или `answer_line`). Исключение — когда одна разлиновка стоит на
несколько подпунктов сразу или отвечают устно.

## Фаза 2 — сборка и выдача

Когда учитель говорит «собери документ» — запусти команду запуска на папке
черновика. Появится `<папка>/output/document.html`: тела всех блоков +
секция «Ответы» в конце + встроенный черновик. Ошибки схемы печатаются все
разом с путями до блоков — исправь указанные JSON и собери снова.

Если документ раздаётся ученикам, собери дополнительно раздаточный вариант:

```
python <путь-к-skill>/scripts/render.py <папка> --no-answers
```

— появится `output/document-no-answers.html` без секции ответов и без
встроенного черновика (иначе ответы были бы видны через исходный код
страницы).

Отдай на скачивание `document.html` (и раздаточный вариант, если нужен) и
объясни учителю: чтобы вернуться к правкам в другой сессии, достаточно
принести `document.html` — в нём встроен весь черновик. Папку JSON отдельно
отдавать не обязательно (но можно, если учитель попросит). Правки после
просмотра: измени нужный файл в `blocks/` (или `document.json`) и
пересобери — это мгновенно и бесплатно, повторяй сколько угодно.

## Отдельная иллюстрация (без документа)

Когда нужна только картинка — график или измерительный прибор для
презентации, отдельной задачи, любых целей учителя:

1. Составь JSON-спеку **одного визуального блока** — та же схема, что у
   блока внутри документа: `graph` — по `references/charts-and-graphs.md`,
   `instrument` — по `references/artifacts/instruments.md`, `paper` (лист
   миллиметровки, клетки) — по `references/artifacts/paper.md`. Сохрани в файл
   (например `visual.json`).
2. Отрендери самодостаточный SVG:
   ```
   python <путь-к-skill>/scripts/render.py --visual visual.json -o velocity-graph.svg
   ```
   Файл несёт шрифт, размеры и белую подложку в себе — его можно вставлять
   в презентацию как есть. Подпись прибора (`caption`) и легенда серий
   графика дорисовываются внутрь SVG автоматически. Нужна иллюстрация
   крупнее (слайд, учебник) — добавь `--scale 2` (любой множитель; шрифты
   и линии растут пропорционально).
3. **Сразу покажи получившийся SVG учителю прямо в диалоге.** Правки — по
   словам учителя: меняешь спеку → перегенерируешь → показываешь снова.
   Файл на скачивание отдавай, когда результат утверждён.

Других видов иллюстраций (схемы, чертежи и т.п.) пока нет: не рисуй SVG
руками — скажи учителю, что такой вид визуала ещё не поддерживается.

## Справочники — когда какой читать

- `references/document-schema.md` — **перед любым созданием/правкой JSON.**
- `references/symbols.md` — перед записью формул и обозначений.
- `references/charts-and-graphs.md` — перед созданием графика.
- `references/artifacts/instruments.md` — перед созданием прибора со шкалой
  (виды, типичные шкалы, задачи на погрешности).
- `references/artifacts/paper.md` — перед выбором места под ответ
  (разлиновки, единицы `rows`/`cols`, что когда ставить).
- `references/artifacts/` — нюансы конкретного вида визуала
  (`README.md` — индекс, `graphs.md` — разбор по типам графиков).
- `references/design-system.md` — только для вопросов о внешнем виде; стиль
  зафиксирован кодом рендерера и в сессии не меняется.
- `examples/kinematics-9th-grade/` — проработанный образец: смешанный
  документ (теория + 15 заданий), все 9 видов вопросов, задание с двумя
  `part` вокруг общего графика (task-10), `row` из двух `part` с `plot`
  (task-13), иерархия символов (task-09), приборы с погрешностями в `row`
  из двух `part` (task-15).
