# Архитектура

Проект — Claude-скилл для учителей физики. Ядро — **библиотека
SVG-иллюстраций** (графики, приборы, бумага, векторы, механика, цепи,
оптика); конструктор учебных документов (задания, конспекты, рабочие
листы) — её потребитель, а не наоборот.

Документ описывает целевое устройство репозитория. Принципы схемы данных
живут отдельно, в [schema-design-principles.md](schema-design-principles.md).

## Зафиксированные решения

| решение | выбор | почему |
|---|---|---|
| центр тяжести | иллюстрации — ядро, документ надстроен сверху | новые типы картинок — основной вектор развития; их цена должна быть минимальной |
| зависимости в бандле | ноль (stdlib) | учителю не нужны ни сеть, ни pip; скилл работает офлайн и в любой песочнице |
| валидация | одна декларативная модель на `dataclass` + аннотациях, своё ядро в `schema/` | нет второй копии моделей и нет кодогенерации; сообщения об ошибках наши, JSON Schema генерируется из тех же аннотаций |
| независимая проверка схемы | dev-тест: сгенерированной JSON Schema валидируются все спеки сторонней библиотекой | проверка без второго набора моделей |
| сложные иллюстрации | параметрические типы поверх общего слоя элементов | предсказуемый и аккуратный результат при дешёвом добавлении типа |
| бандл | артефакт сборки `tools/build_skill.py`, а не подкаталог репо | SKILL.md, справочники и примеры генерируются; расхождение невозможно по построению |
| публикация | push в `main` → свежий zip по стабильной ссылке; тег `v*` → GitHub Release | учитель берёт последнюю версию одной ссылкой, форкающий видит стабильные версии |
| жанр документа | типа документа нет: шапка, название и разделители — обычные блоки | рабочий лист, конспект и объяснение равноправны; рендерер не дорисовывает ничего сам, поэтому у конспекта не заводится анкета, а у листа — оглавление |
| оценивание | баллов в схеме нет | вес задания живёт в журнале учителя, а не на бумаге; поле, которое никто не заполняет, модель заполняет за него |
| KaTeX | остаётся с CDN | осознанный компромисс; офлайн-фолбэки не добавляем, защита `if (window.renderMathInElement)` остаётся |
| язык | код и комментарии — английский; сообщения об ошибках, справочники, сайт — русский | открытый проект: контрибьютор читает код, учитель читает ошибку |

## Слои

```
draw/       холст, геометрия, трансформации, якоря, bbox -> viewBox,
            путь/дуга/текст, скоупинг id, стили. Про физику не знает ничего.
elements/   физический словарь поверх draw: поверхность, тело, вектор-стрелка,
            дуга угла, размерная линия, пружина, нить, блок, опора, ось,
            выноска, провод + условные обозначения, луч + линза/зеркало.
schema/     ядро валидации (dataclass + аннотации), пути ошибок, JSON Schema.
visuals/    библиотека иллюстраций: одна папка = один тип.
document/   блоки, виды вопросов, part/row, нумерация, секция «Ответы», CSS,
            встроенный черновик. Иллюстрации берёт через реестр.
            domain.py — набор, из которого ученик выбирает ответ (общие
            проверки и понятие дистрактора); answers.py — форма ответа
            (`Inline`/`Rows`/`Block`), вёрстку выбирает секция.
cli/        единый вход с подкомандами.
```

Зависимости строго вниз: `document -> visuals -> elements -> draw`,
и `visuals -> schema`. Обратных импортов нет; приватные имена через
границу слоя не ходят.

Нативный выход типа иллюстрации — **самодостаточный SVG**. HTML-обёртка
документа надстраивается сверху; иллюстрация никогда не извлекается из
HTML обратно.

## Контракт типа иллюстрации

```
src/physics_svg/visuals/<тип>/
  model.py      dataclass-спека + инварианты
  render.py     (model, canvas) -> None — рисует элементами, не строками SVG
  specs/*.json  примеры
  doc.md        фрагмент справочника для модели (плотный, токен-экономный)
  card.md       карточка для сайта учителя: что это, когда нужно,
                что сказать Claude
```

Папка саморегистрируется в реестре. **Спеки кормят четырёх потребителей**:
golden-тест SVG, страницу галереи на сайте, библиотеку заготовок внутри
бандла (модель берёт ближайшую и правит, а не сочиняет с нуля) и contact
sheet для глазной проверки.

`tests/visuals/test_conformance.py` падает, если у зарегистрированного
типа нет спеки, `doc.md`, `card.md`, golden'а или записи в JSON Schema;
плюс для каждой спеки автоматически проверяется, что она рендерится,
что viewBox покрывает содержимое и что авторский текст экранирован.

## Контракт вида задания

```
src/physics_svg/document/questions/
  <вид>.py       спека + инварианты + тело + форма ответа + register(order=)
  <вид>.md       фрагмент справочника для модели: поля и рабочие примеры
  <вид>.card.md  карточка для сайта учителя
```

Четыре решения, зафиксированные для всех видов сразу:

| решение | где | почему так |
|---|---|---|
| два рендера, а не флаг режима | `register(body=, answer=)` | тело никогда не содержит ответов; раздаточный вариант — документ без секции, а не второй режим рендера тел |
| ответ — форма, а не разметка | `answers.py`: `Inline` / `Rows` / `Block`, `None` — ответа нет | вёрстку выбирает секция, поэтому ответы разных видов согласованы, а чертёж не попадает в слот для «б» |
| набор для выбора — общее понятие | `domain.py`, вид проецирует своё поле | уникальность, принадлежность ответа набору и предел букв — один раз; «лишнее значение — дистрактор» одно на все виды |
| порядок для человека — авторский | `order` в `register(...)` | страница сайта и индекс справочника идут по частоте вида, а не по алфавиту латинского тега |

Пример из `<вид>.md` — целое задание, и он же фикстура: `tests/document/
test_questions.py` рендерит его, проверяет, что ответ дошёл до секции и не
просочился в тело, и фуззит эскейпинг по всем строкам payload сразу.

## Структура репозитория

```
src/physics_svg/     пакет (см. слои выше)
tests/               тесты; golden — в tests/golden/
docs/                источник сайта: рукописные страницы + этот документ
                     (галерея и справочники генерируются и гитигнорятся)
tools/               build_skill.py, build_site.py, dev.py, contact_sheet.py,
                     release.py, release_notes.py
.github/workflows/   checks -> build -> deploy
dist/                артефакты сборки (гитигнор)
```

## Сборка бандла

`tools/build_skill.py` собирает `dist/skill/physics-materials/` и zip.
Руками в репозитории лежит только то, что нельзя вывести: `skill/SKILL.md`
с плейсхолдерами, `skill/references/document.md` (проза схемы),
`skill/references/symbols.md`, `skill/scripts/render.py`. Остальное —
производная реестров:

| в бандле | откуда |
|---|---|
| `references/questions.md` | склейка `document/questions/<вид>.md` |
| `references/visuals.md` | склейка `visuals/<тип>/doc.md` |
| таблицы типов в `document.md` и счётчики в SKILL.md | реестры |
| `library/<тип>/*.json` | те же спеки, что рендерят тесты и галерея |
| `schema.json`, `VERSION` | модели и `__version__` |

Расхождение «SKILL.md обещает файл, которого нет» роняет сборку.
`tests/test_bundle.py` дополнительно распаковывает бандл и запускает его
`scripts/render.py` в подпроцессе с чистым окружением — то есть проверяет
ровно то, что получит учитель, включая обещание «ноль зависимостей»
(импорты бандла сверяются со списком стандартной библиотеки).

`tools/dev.py` — живой просмотр: контрольный лист иллюстраций и пример
документа пересобираются при изменении исходников, страница сама
перезагружается.

## Публикация

| событие | что происходит |
|---|---|
| push в любую ветку | проверки, сборка бандла (артефакт), сборка сайта `--strict` |
| push в `main` | плюс деплой сайта на Pages вместе со свежим архивом в `assets/` |
| тег `v*` | проверки, бандл, GitHub Release с архивом и разделом `CHANGELOG.md` |

`tools/release_notes.py` режет раздел из `CHANGELOG.md` и заодно сверяет тег
с `__version__`: релиз, чей `VERSION` расходится с тегом, невозможно потом
сопоставить с багом. Ссылка на скачивание на сайте относительная, поэтому
переезд домена или переименование репозитория её не ломают.

## Сайт

`tools/build_site.py` генерирует всё, что дублирует существующий источник:

| страница | откуда |
|---|---|
| `gallery/<тип>.md` | `card.md` типа + SVG из его спек + свёрнутые спеки |
| — с разбором случаев | тот же `card.md`, если он сам расставляет картинки блоком ```` ```spec ```` с именем спеки: тогда страница — экскурсия по случаям, а не список файлов (так сделан `graph`) |
| `questions.md` | `card.md` вида + его примеры-задания из `doc.md`, отрисованные **настоящим рендерером документа** |
| `reference/*.md` | зеркало справочников из бандла |
| `assets/*.html`, `assets/*.zip` | пример документа и скачиваемый бандл |

Скриншотов на сайте нет — поэтому они не могут устареть. Превью задания
показывается стилями самого документа, сведёнными под один класс-обёртку.
Рукописные страницы: `index.md`, `install.md`, `contribute.md` и два
проектных документа. Страница галереи, не попавшая в `nav`, роняет сборку.

## Наследство

Старый пакет `worksheet-builder/`, `gallery/`, `build_docs.py`, старые
тесты и зависимость от pydantic удалены в Ф5: их работу закрыли Ф4 и Ф5.
До конца Ф3 старый пакет служил эталоном невырождения — новый рендер сверен
с ним попримитивно, все расхождения не больше одной единицы viewBox.

Проработанный пример переехал в `examples/kinematics-9th-grade/` и грузится
новым загрузчиком без единой правки JSON: схема данных осталась
совместимой. Обратная совместимость как обязательство не декларируется —
это была разовая удача переноса.
