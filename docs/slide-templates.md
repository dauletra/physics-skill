# Шаблоны слайдов

План четвёртого слоя презентации: **шаблон** — именованная заготовка
существующего вида слайда. Читать после [презентации](presentation.md):
контракт `presentation.json` (§4 того документа) этот план не трогает
вовсе, а словарь слайдов (§5) трогает по одному строгому правилу.

Статус: **Ш1 и Ш2 сделаны** — механизм живёт, типы переехали в папки,
у каждого вида есть заготовки. Дальше Ш3–Ш5 режутся на отдельные выпуски.

## 1. Задача

Слайдов у урока много, а видов — восемь. Разница между «титульный слайд»,
«задача с ответом», «задача без ответа», «объяснение с картинкой» — это не
разница видов, а разница **заполнения** одного вида. Сегодня такая
заготовка у вида ровно одна и лежит прозой: блок ` ```json ` внутри
`<вид>.md`, который реестр выковыривает регуляркой. Скопировать её файлом
нельзя, назвать нельзя, второй такой завести некуда.

У иллюстраций эта задача решена давно: `visuals/<тип>/specs/*.json` едут в
бандл как `library/<тип>/*.json`, и модель правит готовое вместо того,
чтобы сочинять. Слайдам нужно то же самое.

## 2. Шаблон — не вид слайда

Разделение, без которого словарь расползётся на «слайд под каждый приём»
(риск, записанный в [presentation.md §12](presentation.md)):

| | вид слайда | шаблон |
|---|---|---|
| что это | контракт: поля, валидатор, эмиттер, ветка плеера | заполненный слайд существующего вида + строка «когда брать» |
| цена | схема, плеер, справочник, тесты | один JSON-файл |
| кто знает | схема и плеер | никто: к сборке шаблон уже обычный слайд |
| темп изменений | редко и осознанно | свободно |

**Гейт.** Новый вид заводится, только когда плеер не может вывести
структуру из существующих полей. Три задачи с тремя ответами — это не
`items`: у каждой задачи свой ответ и своя картинка, и такой формы в
`content` нет. А «титульный слайд» или «задача с ответом» — это заполненные
поля видов, которые уже есть.

Тот же гейт словами [example.py](../src/physics_svg/presentation/slides/example/__init__.py):
форму несёт поле, а не оформление. Если новая просьба не приносит новой
формы — она приносит шаблон.

## 3. Зафиксированные решения

| решение | выбор | почему |
|---|---|---|
| где живёт шаблон | `slides/<вид>/templates/<слаг>.json`, рядом со своим видом | шаблон — экземпляр вида; хранить его отдельно значит развести источник и его владельца |
| вид слайда | пакет `slides/<вид>/` вместо плоского модуля | появилась папка `templates/`; заодно слайды сравнялись с `visuals/<тип>/` |
| форма файла | конверт `{template, when, slide}` | схема строгая: лишний ключ рядом со слайдом — ошибка, а имя и «когда брать» хранить где-то надо |
| что едет в бандл | распакованный слайд `library/slides/<вид>/<слаг>.json` | модель копирует файл в `slides/<id>.json` и правит; снимать обёртку по дороге ей не нужно |
| индекс | генерируемый `references/templates.md`: таблица «шаблон / вид / когда брать / файл» | выбор шаблона — дешёвое чтение; поля видов лежат в `slides.md` и на этом шаге не нужны |
| справочник вида | `doc.md` расставляет шаблоны фенсом ` ```template `, нерасставленные приписываются в конец | зеркало ` ```spec ` в карточках иллюстраций: добавить шаблон — по-прежнему добавить файл, но проза вправе поставить его в нужное место |
| единый источник | ` ```json ` из `<вид>.md` уезжают в `templates/`; `SlideType.examples` читает шаблоны | иначе у «примера слайда» два источника, и они разъедутся — принцип «спеки и примеры — единый источник» |
| версия контракта | `format` не меняется | шаблон не доезжает до `presentation.json`: к сборке это обычный слайд |
| плеер | не знает о шаблонах ничего | шаблон кончается в момент валидации; на проводе — тот же слайд |

## 4. Контракт файла шаблона

```json
{
  "template": "with-answer",
  "when": "одна задача классу, ответ открывается щелчком по плашке",
  "slide": { "type": "board_task", "text": "…", "answer": "…" }
}
```

* `template` — слаг, совпадает с именем файла (то же правило, что `id` и имя
  файла слайда: иначе адресная правка становится угадайкой);
* `when` — одна строка, по которой модель выбирает шаблон; она же — ячейка
  в таблице индекса;
* `slide` — **целый валидный слайд**, а не фрагмент: слайд — наименьшее,
  что валидируется и что показывает плеер.

Порядок шаблонов вида — по имени файла. Он же определяет «канонический»
пример вида (первый) там, где нужен ровно один.

## 5. Что становится шаблоном, а что видом

Разбор первой партии просьб через гейт §2:

| просьба | решение |
|---|---|
| титульная страница | шаблоны `title/` |
| задача с ответом / без | шаблоны `board_task/` |
| объяснение с картинкой, со списком | шаблоны `content/` |
| цели, вопросы, рефлексия, разделитель | шаблоны своих видов |
| **формула с объяснением** | **вид `formula`**: `formula`, `text?`, `terms[]{symbol, meaning}` — плеер обязан знать, что это формула-герой, иначе она приедет абзацем в 3.2cqh и с задней парты не читается |
| **несколько задач на экране** | **вид `tasks`**: `heading?`, `tasks[]{text, visual?, answer?}` — у каждой задачи свой ответ и свой спойлер |
| **сравнение в колонках** | **вид `compare`**: `heading?`, `cases[]{label, text?, items?, visual?}` — поля называются смыслом («случаи»), колонки или строки решает плеер; «с иллюстрацией и без» — два шаблона одного вида |

Дальше список растёт **только шаблонами**, пока просьба не приносит формы,
которой в полях нет.

Проверено глазами на контрольном листе шаблонов (все заготовки одной
презентацией): инлайновая дробь KaTeX внутри абзаца `content` мельче
строки, а курсивный ипсилон KaTeX почти неотличим от латинской `v`. Отсюда
два следствия — формуле-герою действительно нужен свой вид (Ш3), а простые
обозначения в тексте слайда пишутся юникодом (`υ₀`, `м/с²`), и LaTeX
остаётся дробям и корням, как и велит `references/symbols.md`.

| фаза | содержание | статус |

| **Ш1** | механизм: виды слайдов → пакеты, конверт шаблона, `SlideType.templates`, `examples` от шаблонов, `library/slides/`, `references/templates.md`, шаг в SKILL.md | готово |

| **Ш3** | виды `formula`, `tasks`, `compare` + раскладки плеера; scope визуала становится пошаговым (`s3v2`) — на слайде появляется больше одной картинки; глазами по `evals/presentation.md` | |
| **Ш4** | сайт: страница шаблонов с настоящим превью — мини-презентация из одного слайда в `iframe` (рисует плеер, не Python) | |

## 7. Проверки

| что | как |
|---|---|
| шаблон валиден | конформанс от реестра: конверт разбирается, `slide` проходит союз видов, `template` совпадает с именем файла |
| шаблон принадлежит своему виду | `slide.type` == тег папки |
| у вида есть хотя бы один шаблон | тот же конформанс: вид без заготовки нечем показать модели |
| шаблон доезжает до модели | `test_bundle`: файл лежит в `library/slides/<вид>/`, распакованный и валидный; строка про него есть в `references/templates.md` |
| шаблон эмитируется | существующий `test_emit`: каждый шаблон собирается в проводной JSON и переживает фузз `PAYLOAD` по строковым полям |
| справочник не теряет шаблон | нерасставленные фенсом приписываются в конец фрагмента — потерять файл нельзя |

## 8. Чего не делаем

- **Не учим плеер шаблонам.** Шаблон кончается на валидации.
- **Не кладём в шаблон раскладку и оформление** — запрет из
  [presentation.md §13](presentation.md) действует и здесь: шаблон
  отличается от шаблона содержимым полей, а не видом на экране.
- **Не заводим вид ради удобной заготовки** — гейт §2.
- **Не тянем механизм в документ** сразу: у `document/questions/` та же
  дыра (пример живёт прозой), но обкатать надо на слайдах.
- **Не делаем шаблон способом продолжить урок** — черновик по-прежнему
  авторские `presentation.json` и `slides/*.json`.
