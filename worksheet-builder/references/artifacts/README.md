# Библиотека SVG-артефактов

Справочники по каждому виду визуального SVG-артефакта рабочего листа. Один
файл на вид, открывается **только когда нужны нюансы этого вида** — при
обычной вёрстке достаточно обзоров (`../charts-and-graphs.md` и т.п.), сюда
заходишь за глубиной: точная форма данных, разбор по подтипам, физические
подсказки, подводные камни.

## Архитектурные ворота (читать до добавления нового артефакта)

Артефакт — это **данные, а не рисунок**. Автор задаёт числа/подписи в JSON;
SVG детерминированно рисует генератор в `worksheet_builder/`. Правило проекта
«не возвращай рукописный HTML/SVG-вывод» действует и здесь: нельзя добавить
новый вид артефакта одним лишь текстовым справочником — **сначала нужен
генератор**.

Поэтому каждый вид артефакта — это четыре вещи вместе:

1. **Компонент или вопрос** (функция рендера в
   `worksheet_builder/components.py` или `worksheet_builder/questions.py`) —
   чистый стимул без ответа → компонент; отвечаемый («постройте…») → вопрос
   с ответом инлайн. Принципы — `docs/schema-design-principles.md` в
   репозитории разработки.
2. **Pydantic-модель** в `worksheet_builder/models.py` — поля, закрытые
   словари, инварианты (валидация при загрузке, с путём до блока).
3. **Генератор SVG** — отдельная функция/модуль по образцу
   `worksheet_builder/visuals.py` (`build_chart_svg`), соблюдающий общие
   конвенции ниже.
4. **Справочник в этой папке** — по шаблону `graphs.md` + строка в индексе.

Пока этих трёх вещей нет, вид артефакта считается **запланированным**, а не
рабочим. Иллюстрации/схемы/чертежи (наклонная плоскость, электрическая цепь и
т.п.) сейчас именно в этом статусе — вне scope, см. «Явно вне scope» в
`../task-schema.md`.

## Общие SVG-конвенции (для всех генераторов)

Единый визуальный код держит все артефакты одного листа согласованными.
Каноничный образец — `worksheet_builder/visuals.py`; при добавлении нового
генератора не переизобретай эти правила, переиспользуй.

- **Только ч/б, никогда цвет.** Различай элементы формой, штриховкой,
  толщиной, маркером — не заливкой цветом (принцип стиля, см.
  `../design-system.md`). Серый `#ccc` допустим только для вспомогательной
  сетки; смысловые линии — `#000`.
- **viewBox `220×124`**, откалиброван под целевую экранную ширину
  `max-width: 330px` у `svg.visual-svg` (см. `../design-system.md`).
  Константы font-size/stroke-width подобраны так, чтобы после масштабирования
  под эту ширину текст читался, а линии не были ни нитяными, ни жирными. При
  другой целевой ширине калибровку надо перепроверять рендером, а не считать
  универсальной.
- **Класс `visual-svg`** на корневом `<svg>` — CSS-ширина висит именно на
  нём (`svg.visual-svg`, не на голом `svg`), чтобы не задеть маленькие
  svg-иконки легенды.
- **Экранирование.** Любой текст из данных (подписи, метки серий) прогоняй
  через `esc()` (`worksheet_builder/render_helpers.py`) — он пропускает
  `<sup>`/`<sub>` по `../symbols.md`, но экранирует остальное. Эскейпит
  генератор, не CSS.
- **Числа** форматируй как в `visuals._fmt_num` (целые без `.0`, дроби без
  хвостовых нулей), чтобы подписи делений выглядели одинаково везде.

## Чек-лист: добавить новый вид SVG-артефакта

По образцу чек-листа нового вопроса из `docs/schema-design-principles.md`
(репозиторий разработки):

1. **Это данные?** Выпиши минимальный набор числовых/текстовых полей, из
   которых рисунок восстановим однозначно. Если рисунок нельзя параметризовать
   данными — это ещё не готовый к схеме артефакт (не заводи «поле под сырой
   SVG»).
2. **Компонент или вопрос?** Стимул без ответа → чистый компонент. Отвечаемый
   → класс вопроса, ответ инлайн внутри содержимого.
3. **Генератор** — отдельный модуль/функция по образцу `visuals.py`; ч/б,
   общие конвенции отсюда, `esc()` на тексте.
4. **Pydantic-модель** в `models.py`: поля, закрытые словари (`Literal`),
   инварианты в `@model_validator` — валидация при загрузке, с путём до
   блока, `extra="forbid"`.
5. **Реестр** — строка в `COMPONENT_TYPES`/`QUESTION_TYPES` и в union
   `AnyBlockModel` (`task-schema.md`).
6. **Справочник** — новый файл в этой папке по шаблону `graphs.md` + строка в
   индексе выше (статус меняется на ✅, когда генератор готов).
7. **Тесты** — golden-снапшот в `tests/` (оба режима) + негативные случаи в
   `tests/test_validation.py`.
