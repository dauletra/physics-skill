# `example` — разбор задачи

Задача, которую разбирает учитель, пока класс следит за ходом решения. От
`board_task` отличается тем, что решение есть в данных: шаги идут списком,
и показ открывает их по одному.

```template
steps
```

| поле | обяз. | значения |
|---|---|---|
| `text` | да | условие разбираемой задачи |
| `steps` | да | шаги решения, минимум один; по строке на шаг |
| `answer` | нет | итог, которого нет в шагах; см. правило ниже |
| `visual` | нет | иллюстрация к условию |

**Шаг — это строка, а не абзац с переносами.** Показ открывает шаги по
одному, и знать, где кончается шаг, он может только из данных: разбор,
слепленный в один `text`, показать по шагам нельзя. Номера шагов в текст не
пишут — их ставит показ, и в колоде PowerPoint пересчитывает сам.

**Иллюстрация в разборе встаёт колонкой рядом с условием и шагами** —
другого места на слайде нет. Замерено: в этой колонке с задней парты
читаются 23 иллюстрации библиотеки из 35, и это приборы и графики без
легенды. Если картинка важнее шагов, слайд для неё — `board_task` или
`content`.

**`answer` — только то, чего в шагах нет.** Ответ открывается после всех
шагов, последним событием слайда. (Порядок жёсткий: поток щелчков один и
клавиши «мимо анимаций» нет, поэтому ответ иначе открылся бы раньше
времени.) Поэтому в разборе, который кончается числом, поля `answer` быть
не должно: строка «Ответ» под строкой, где это число уже вычислено, ничего
не прячет и обесценивает ответ там, где под ним действительно итог. Ставь
`answer` в разборе, только когда шаги — рассуждение, а число приходит в
конце:

```template
reasoning
```

Разбор с картинкой — та же спека визуала, что везде. Здесь `answer` на
месте: шаги показывают, как читать график, а число появляется только в нём.

```template
with-visual
```
