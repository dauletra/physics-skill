# Проект: скилл worksheet-builder

Репозиторий — это один Claude-скилл (`worksheet-builder/`) плюс dev-обвязка
в корне. «Разработка» здесь = правка SKILL.md/references/пакета рендерера и
проверка тестами + рендером примера.

## Ключевое архитектурное правило

Скилл никогда не пишет итоговый HTML руками. Контент живёт в маленьких
JSON-файлах (`document.json` + `blocks/*.json`); пакет `worksheet_builder/`
детерминированно рендерит их в HTML. **Не возвращай рукописный
HTML-вывод** — если нужно новое визуальное поведение, меняй рендерер/CSS,
а не HTML конкретного блока.

Артефакт один — **документ**: конспект, объяснение, набор заданий или их
комбинация (теория и `task`-блоки свободно перемежаются, нумерация заданий
сквозная и теорию пропускает). Режимов student/teacher нет: тела заданий
ответов не содержат, ответы собираются в секцию «Ответы» в конце
(`build_answers_section`); раздаточный вариант — флаг `--no-answers`
(без секции и без встроенного черновика). Второй сценарий с тем же ядром:
`--visual spec.json` рендерит спеку одного визуального блока
(`graph`/`instrument`, схема та же, что внутри документа) в самодостаточный
SVG (`standalone.py`) — для показа в диалоге и вставки в презентацию,
freehand-SVG в проект не входит.

Документ — **сплошной экранный HTML-документ**: колонка 800px, белый фон,
px. Вёрстки под печать/A4 нет вообще (осознанно, не добавляй).
Единственный клиентский JS — KaTeX; никаких тулбаров в HTML. Всё
настраиваемое — поле в JSON, а не клик в браузере. Полный `document.html`
несёт встроенную копию черновика (`<script type="application/json"
id="document-source">`, `{"document": …, "blocks": […]}`, каждый символ
«меньше» в payload эскейпится JSON-последовательностью `<`) — одного
файла достаточно для продолжения правок в новой эфемерной сессии;
`--no-answers`-вариант и `--block`-превью черновик не несут (он раскрыл бы
ответы).

Только русский язык. Служебные строки — плоский словарь `STRINGS`
(`worksheet_builder/strings.py`, без языкового ключа); там же кириллический
ряд `LETTERS` (`а`, `б`, `в`… без ё/й/ъ/ы/ь) — единый источник букв
подзаданий, маркеров списков, сводки `match` и букв в секции «Ответы».
Не хардкодь надписи в разметке.

## Два контракта запуска (одно ядро, разные обёртки)

- **Sandbox (Settings → Skills) — основной таргет**: пользователи без Claude
  Code. `python <путь-к-skill>/scripts/render.py <workspace>`. Без uv и
  установки пакета: `render.py` сам доустанавливает pydantic (только если
  нет; пин `>=2,<3`; один раз на жизнь контейнера; при провале — внятная
  ошибка). Доступ контейнера к PyPI проверен. **SKILL.md ориентирован на эту
  среду** — не «упрощай» его к `uv run`/`pip install`. План «Б», если PyPI
  закроют: переписать валидацию на stdlib.
- **Локальный dev (эта машина)**: из корня репо `uv run render-worksheet
  <workspace>` (uv.lock коммитится, `uv lock` при смене зависимостей) или
  `pip install -e ".[dev]"` + `python -m worksheet_builder …`. Тесты/линт/
  типы гоняются здесь.

## Валидация — pydantic, политика «строго всё»

Вся валидация — pydantic-модели в `worksheet_builder/models.py`, при
загрузке (`parse_document` — манифест, `parse_block` — верхнеуровневый
блок). Модели — **единственное представление данных**: то же дерево идёт в
рендер (сырые dict'ы проносятся только до встраивания черновика в HTML).
Правила:

- `extra="forbid"` везде: неизвестное поле — ошибка; закрытые словари —
  `Literal`: неизвестное значение — ошибка, не фолбэк;
- кросс-инварианты — `@model_validator` (один `correct` при `single`,
  перестановка `position 1..N`, ссылки `match`→`right.id`, плейсхолдеры ==
  `blanks`, `min < max`, инварианты `bar`, уникальные `label` из `LETTERS`,
  состав `part`/вопрос, лимит по алфавиту, уникальность `id` внутри
  задания); вопросы/`part` вне `task` и task/row в верхнеуровневом `row`
  отбиты before-валидаторами с человеческой ошибкой;
- инварианты workspace — в `load_workspace` (`cli.py`): файл вне
  `document.order` — ошибка, `id` ≠ имя файла — ошибка;
- ошибка называет путь до блока (`task-10 -> blocks[2] -> …`; ASCII `->`
  намеренно — `→` роняет cp1251-консоль Windows); CLI собирает ошибки всех
  блоков одним списком, без traceback.

Функции рендера инварианты **не** перепроверяют. Новую проверку добавляй в
модель. Машиночитаемая схема генерируется: `python -m worksheet_builder
--emit-schema docs/document.schema.json` — перегенерируй при любом
изменении моделей (CI сверяет).

**Схема документа** (справочник — `worksheet-builder/references/
document-schema.md`, принципы — `docs/schema-design-principles.md`):
верхний уровень — `document.json` (title, опциональная анкета `header`,
`order`) + по файлу на блок в `blocks/` (`heading` | компонент | `task` |
`row` из компонентов). Внутри `task` — дерево блоков: чистые компоненты
(`text`/`table`/`graph`/`list`/`instrument`, `components.py`) не знают об
ответе; вопросы (9 видов, `questions.py`) несут ответ инлайн, у каждого
пара рендеров — тело (`render_question`) и компактный ответ
(`render_answer`, печатается только в секции «Ответы»); `part` — компоненты
+ ровно один вопрос, буква и `points` на нём; `row` — дети поровну в одну
строку, прозрачен для инвариантов/букв (`iter_flat_models`), вложенный
`row` запрещён. Смысловая связь — вложенностью, не соседством.
Иллюстрации/схемы вне scope; визуальные элементы — только `graph`/`plot`
(одиночный график ограничен `max-width: 330px` в CSS, в `row` не
заворачивается) и приборы со шкалой `instrument` (15 видов, 7 семейств
геометрии — `INSTRUMENT_FAMILIES` в `models.py`; ширина висит на обёртке
`.instrument-wrap.instrument-<семейство>`, масштаб всех SVG документа
единый — ~1.5px на единицу viewBox).

## Где что лежит

- Корень (dev, в бандл не едет): `pyproject.toml` (пакет через
  `package-dir`; конфиги mypy/ruff/pytest), `uv.lock`, `tests/`, `docs/`
  (`schema-design-principles.md` — принципы схемы и чек-лист нового вида
  вопроса; `document.schema.json` — генерируемый), `build_bundle.py`,
  `.github/workflows/ci.yml`, `drafts/` (гитигнорные локальные документы).
- `worksheet-builder/` — **ровно состав бандла** (`build_bundle.py` жмёт всю
  папку минус кэши/`output/`/превью и падает, если SKILL.md ссылается на
  путь, которого нет в архиве; итог — `dist/worksheet-builder-skill.zip`
  для Settings → Skills):
  - `SKILL.md` — рабочий процесс скилла (sandbox-команды, эфемерные файлы,
    карта справочников).
  - `scripts/render.py` — sandbox-точка входа: bootstrap pydantic + проброс
    argv в `cli.main()`. mypy его не видит (вне пакета), ruff — видит.
  - `references/` — `document-schema.md` (схема JSON; читается перед правкой
    блоков), `symbols.md` (текст → `<sup>`/`<sub>` → LaTeX; скорость — `υ`
    ипсилон, не латинская `v` — не «упрощай», не перечитав файл),
    `charts-and-graphs.md` (данные графиков), `design-system.md` (оболочка/
    шрифты/зебра/секция «Ответы» — держи в синхроне с `BASE_CSS` в
    `assets.py`), `artifacts/` (`README.md` — индекс/конвенции
    SVG-артефактов, держи в синхроне при новом генераторе визуала;
    `graphs.md` — per-type разбор; `instruments.md` — приборы со шкалой:
    виды, типичные шкалы, задачи на погрешности).
  - `worksheet_builder/` — пакет: `cli.py` (`load_workspace` +
    workspace-инварианты, `--no-answers`/`--block`, `--visual`/`-o`,
    `--scale` — множитель размера standalone-SVG, `--emit-schema`),
    `models.py` (вся валидация; `iter_flat_models()` — row прозрачен;
    `DocBlockModel` — union верхнеуровневых блоков, `parse_block`/
    `parse_document`; `parse_visual` — спека `--visual` тем же union-ом
    визуальных компонентов), `assets.py` (`KATEX_HEAD`, `BASE_CSS` —
    константа без параметров), `strings.py`, `render_helpers.py` (`esc()`
    пропускает буквальные `<sup>`/`<sub>` — не заменяй голым
    `html.escape()`; модель хранит сырой текст, эскейпит рендер в точке
    интерполяции, забытый `esc()` ловит фузз-тест), `visuals.py`
    (`build_chart_svg`, viewBox 220×124, калиброван под 330px; круглые
    деления — `_tick_positions`; общие `fmt_num`/`svg_label` — в
    `render_helpers.py`), `instruments.py` (`build_instrument_svg` — приборы
    со шкалой, 7 семейств геометрии со своими viewBox; прореживание
    подписей штрихов — `_ticks`), `standalone.py` (`build_standalone_svg` —
    самодостаточный SVG одного визуала для `--visual`: поверх
    `render_component` извлекает `<svg class="visual-svg">` — контракт всех
    генераторов, поэтому новый тип подхватывается без правок; width/height
    по калибровке 1.5px/единицу, font-family, белая подложка; caption/
    легенда дорисовываются `<text>`-ами внутрь SVG), `components.py`
    (+ хелперы `list_html`/`table_html`, принимают готовую безопасную
    разметку), `questions.py` (пары тело/ответ 9 видов;
    `QUESTION_BODY_RENDERERS`/`QUESTION_ANSWER_RENDERERS`), `document.py`
    (сборка: `render_doc_block` — верхнеуровневый диспетчер с нумерацией
    заданий, `compute_part_labels` — чистая функция,
    `build_answers_section` — секция «Ответы» (задания без ответов
    пропускаются, пустая секция не печатается), `render_source_script` —
    встраивание черновика; `build_document(with_answers)` принимает уже
    распарсенные модели; `build_preview` — превью одного блока под его
    настоящим номером).
  - `examples/kinematics-9th-grade/` — проработанный пример: смешанный
    документ (теоретические вставки + 15 заданий), все виды вопросов
    (task-09 — иерархия символов, task-10 — два `part` вокруг общего
    графика, task-13 — `row` из двух `part` с `plot`, task-15 — приборы
    `instrument` с погрешностями). Его `output/` — человеческое превью
    (гитигнорится, перегенерируется).
- `tests/` — golden-снапшоты (тело + строки ответов каждого вида, смешанный
  документ, полный пример), негативная таблица валидации, workspace-ошибки,
  фузз эскейпинга (новый вид вопроса покрывается автоматически через
  `MINIMAL_TASKS` в conftest), round-trip встроенного черновика
  (`test_source_embed.py`; там же — что `--no-answers` и превью черновик не
  несут), смешанный документ и структурные запреты верхнего уровня
  (`test_document.py`), standalone-SVG `--visual` (`test_standalone.py`:
  golden + самодостаточность + совпадение с SVG документа + эскейпинг;
  новый тип визуала покрывается автоматически через `MINIMAL_VISUALS` в
  conftest).

## Как проверять изменения

Из корня репо:

1. **Тесты** (обязательно после любой правки пакета):
   `python -m pytest tests -q`. Если рендер изменился **намеренно** —
   пересними эталоны (`REGEN_GOLDEN=1 python -m pytest tests -q`) и
   просмотри диф глазами перед коммитом.
2. **Рендер + глаза** (после правок CSS/визуала):
   `python -m worksheet_builder worksheet-builder/examples/kinematics-9th-grade`
   и открой `…/output/document.html` (тела и секция «Ответы» в одном
   файле). Слишком широкий CSS-селектор имеет свойство просачиваться (был
   баг `svg { width: 100% }` — чинили узким `svg.visual-svg`).
3. **Линт и типы**: `python -m ruff check . && python -m mypy`. Пакет
   полностью аннотирован (`disallow_untyped_defs`) — новые функции с типами.
4. При изменении `models.py` — перегенерируй `docs/document.schema.json`
   (`--emit-schema`); CI сверяет.
5. **Бандл**: `python build_bundle.py` — собирает zip и падает при
   рассинхроне SKILL.md с составом архива. CI собирает бандл на каждый push.

Открытый follow-up: полный e2e на реальном бандле в Settings → Skills
(загрузить zip → «сделай рабочий лист…» → первый рендер сам ставит pydantic
и отдаёт HTML) — инфраструктурные допущения проверены по отдельности,
целиком прогон не делался.

## Известные компромиссы (не «чини» без согласования)

- **KaTeX с CDN (jsdelivr), не вендорится** — для формул нужен интернет.
  Осознанно; офлайн-фолбэки не добавлять. Но проверка
  `if (window.renderMathInElement)` в `KATEX_HEAD` остаётся — это не
  офлайн-поддержка, а защита от необработанного JS-исключения; не делай
  вызов безусловным.
- **Печать не инженерится** — никаких `@page`/`@media print`/`break-inside`.
- Пример участвует в golden-тестах и одновременно служит человеческим
  превью через свой гитигнорный `output/` — отдельной копии примера в корне
  больше нет.
- **Ответы — только секцией в конце.** Инлайн-вариант «ответ под вопросом»
  сознательно не рендерится; если понадобится — это флаг поверх готовых
  `render_answer`, а не возврат режимов student/teacher.
