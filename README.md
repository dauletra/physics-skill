# worksheet-builder

Claude-скилл для учебных документов: рабочих листов с заданиями,
конспектов, объяснений темы — и любых их комбинаций в одном файле. Делался
под физику, но к предмету не привязан: подходит везде, где нужны единый
визуальный стиль и типовые форматы заданий.

На выходе — один самодостаточный HTML: сплошной документ в центрированной
колонке ~800 px, открывается в любом браузере. Ответы заданий в теле не
печатаются, рендерер собирает их в секцию «Ответы» в конце; раздаточный
вариант без ответов — флаг `--no-answers`. Второй сценарий с тем же ядром:
`--visual spec.json` отдаёт одну SVG-иллюстрацию (график, прибор со шкалой
или разлинованное поле) отдельным файлом — для показа в диалоге или вставки
в презентацию.

Документация сайтом: `python build_docs.py && zensical serve` (см.
[«Сайт документации»](#сайт-документации)).

## Где что лежит

```
worksheet-builder/            — сам скилл (= ровно состав дистрибутива)
├── SKILL.md                  — точка входа: когда триггерить, workflow
├── scripts/render.py         — запуск в sandbox Settings → Skills
│                                (сам доустанавливает pydantic)
├── references/
│   ├── document-schema.md    — схема document.json и всех блоков
│   ├── design-system.md      — оболочка документа/шрифты/секция «Ответы»
│   ├── charts-and-graphs.md  — формат данных графиков
│   ├── symbols.md            — Unicode-символы и когда sup/sub или LaTeX
│   └── artifacts/            — глубокие справочники по SVG-артефактам
├── worksheet_builder/        — пакет рендерера: JSON-черновик → HTML
└── examples/kinematics-9th-grade/ — пример со всеми видами вопросов

Корень репо — dev-обвязка (в дистрибутив не входит):
pyproject.toml + uv.lock, tests/ (golden-снапшоты + валидация),
build_bundle.py (сборка dist/worksheet-builder-skill.zip),
docs/ + gallery/ + zensical.toml + build_docs.py (сайт документации),
.github/workflows/ (CI и публикация сайта).
```

## Как это устроено

Документ собирается в два слоя, а не пишется как единый HTML-файл:

1. **Черновик** — папка с `document.json` (заголовок, опциональная
   анкета-шапка, порядок блоков) и по файлу на блок в `blocks/`. Именно тут
   идёт вся работа в диалоге с Claude: обсуждение темы, формулировки,
   правки. Правка одного задания = правка одного маленького файла, без
   перечитывания всего документа.
2. **Сборка** — детерминированный рендерер превращает черновик в HTML.
   Визуальную консистентность (шрифты, нумерацию, стиль графиков)
   гарантирует код рендерера, а не память о том, что использовалось в
   прошлом сообщении.

Черновик проверяется при сборке (pydantic): опечатка в имени поля,
неизвестное значение, битая ссылка — ошибка с точным путём до блока, все
нарушения перечисляются одним списком.

Внутри документа теория и задания свободно перемежаются: нумерация заданий
сквозная и теорию пропускает. Виды вопросов — `open`, `choice`, `match`,
`fill_text`, `fill_table`, `plot`, `true_false`, `rank`, `classify`;
компоненты без ответа — `text`, `table`, `list`, `graph`, `instrument`,
`paper`, `answer_line`. Подробности workflow — в
[worksheet-builder/SKILL.md](worksheet-builder/SKILL.md).

## Символы и формулы

Приоритет — обычный текст (Unicode-символ) → `<sup>`/`<sub>` → LaTeX, и только
в этом порядке. LaTeX (KaTeX) оправдан лишь для настоящих составных выражений
(дробь, корень с содержимым, система уравнений) — одна греческая буква или
простое уравнение вроде `F = ma` пишутся обычным текстом. Полная таблица
готовых символов и греческого алфавита — в
[references/symbols.md](worksheet-builder/references/symbols.md); там же —
предупреждение о буквах, которые неотличимы от латиницы (например,
скорость в этом проекте обозначается `υ`, а не `v`, потому что `v` неотличима
от `ν`, которой обозначается частота).

## Использование как Claude skill (основной сценарий)

Соберите дистрибутив и загрузите его в Claude Desktop / claude.ai:

```bash
python build_bundle.py   # → dist/worksheet-builder-skill.zip
```

Zip загружается в Settings → Capabilities → Skills. Дальше просто просите в
диалоге: «сделай рабочий лист по теме X», «добавь задание на график»,
«убери третье задание» — Claude заведёт черновик, отредактирует нужные JSON
и соберёт документ. Ставить ничего не нужно: рендерер запускается вложенным
`scripts/render.py`, который сам доустанавливает pydantic в контейнере.

Формулы рендерятся через KaTeX с CDN (jsdelivr) — при просмотре готового
документа нужен интернет.

## Локальная разработка

Вариант с [uv](https://docs.astral.sh/uv/) (Python на машине не нужен —
uv сам скачает управляемый CPython; версии зафиксированы в `uv.lock`):

```bash
# собрать пример целиком → output/document.html
uv run render-worksheet worksheet-builder/examples/kinematics-9th-grade

# раздаточный вариант без секции «Ответы»
uv run render-worksheet worksheet-builder/examples/kinematics-9th-grade --no-answers

# превью одного блока под его настоящим номером
uv run render-worksheet worksheet-builder/examples/kinematics-9th-grade --block task-07

# отдельная иллюстрация: спека одного визуального блока → standalone SVG
uv run render-worksheet --visual spec.json -o illustration.svg
```

Вариант с готовым Python 3.10+: `pip install -e ".[dev]"` из корня репо
даёт те же команды напрямую (`python -m worksheet_builder …`) плюс
dev-инструменты:

```bash
python -m pytest tests -q            # golden-снапшоты + валидация
python -m ruff check . && python -m mypy
python build_bundle.py               # сборка и проверка дистрибутива
```

## Сайт документации

Сайт собирается [Zensical](https://zensical.org/) и живёт в том же репо.
Копий документации он не хранит: галерея иллюстраций рендерится тем же
кодом, что и документы, а справочники скилла зеркалируются из
`worksheet-builder/references/`.

```bash
pip install -e ".[docs]"   # или: uv sync --extra docs
python build_docs.py       # генерирует docs/gallery/ и docs/reference/
zensical serve             # http://localhost:8000
```

`build_docs.py` обязателен перед сборкой сайта: без него сгенерированных
страниц нет и `zensical build --strict` падает.

Что где лежит:

| Путь | Что это |
|---|---|
| `docs/index.md`, `docs/quickstart.md` | Рукописные страницы |
| `docs/schema-design-principles.md` | Принципы схемы (он же — страница сайта) |
| `docs/document.schema.json` | Генерируется `--emit-schema`, CI сверяет |
| `gallery/<семейство>.md` | Рукописное вступление к странице галереи |
| `gallery/<семейство>/*.json` | Спеки экспонатов — источник картинок |
| `docs/gallery/`, `docs/reference/` | **Генерируются**, в гит не коммитятся |

Добавить экспонат в галерею — положить валидную спеку в
`gallery/<семейство>/`; невалидная роняет сборку сайта тем же сообщением,
которое увидел бы автор документа.

CI (GitHub Actions) гоняет линт, типы, тесты, сверку `uv.lock` и
сгенерированной JSON-схемы, сборку бандла и сборку сайта (`--strict`).
Отдельный workflow публикует сайт на GitHub Pages — он начнёт работать
после включения Pages в настройках репозитория.
