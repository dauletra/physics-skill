# PowerPoint: чек-лист ручной проверки

Автотесты доказывают, что пакет собран правильно: части типизированы,
отношения ведут в существующие файлы, ссылки объявлены, сборка
воспроизводима. Чего они не доказывают — что **PowerPoint его откроет** и
что урок читается с задней парты. На непонравившийся пакет PowerPoint
говорит «в презентации обнаружена ошибка» и не называет часть, а часть
ошибок молча чинит при сохранении — оба исхода тест от нормы не отличает.

Поэтому: один проход по этому листу на каждой фазе
([план](../docs/pptx.md)) и перед каждым выпуском, который её трогает.
Промах — дописать строку в «Журнал», дословно.

## Как получить файл

Пока урок в колоду не собирается (это P2 и дальше), проверяется пустая:

```bash
python -c "import sys;sys.path.insert(0,'src');from pathlib import Path;from physics_svg.presentation.pptx import build_pptx;Path('dist').mkdir(exist_ok=True);Path('dist/empty.pptx').write_bytes(build_pptx([],title='Проверка'))"
```

Проверять в **PowerPoint** — адресат один. Дополнительно, но не вместо:
открыть в LibreOffice Impress, чтобы знать, что теряется у учителя без
Office (это ограничение скилла, а не дефект).

Перед тем как открывать — прогнать линтер: он назовёт часть и строку, а
PowerPoint скажет только «в презентации обнаружена ошибка».

```bash
python tools/ooxml_lint.py --fetch
python tools/ooxml_lint.py examples/kinematics-9th-grade/output/presentation.pptx
```

`--fetch` разовый: качает схемы ECMA-376 в `.cache/`. Нужен `lxml`, поэтому
это инструмент, а не тест. Чистый прогон **не** заменяет открытие в
PowerPoint: схема не знает, что колода должна читаться с задней парты, а
PowerPoint придирчив и там, где схема молчит.

## Что смотреть

### P1. Пакет открывается

- [ ] PowerPoint открывает файл без диалога «PowerPoint обнаружил проблему
      с содержимым» и без предложения восстановить
- [ ] в колоде ровно один слайд, и он пустой
- [ ] размер слайда — «Широкоэкранный (16:9)» в «Дизайн → Размер слайда»
- [ ] в «Вид → Образец слайдов» есть один образец и один макет «Пустой»
- [ ] в палитре («Формат фигуры → Заливка → Цвет темы») стоят наши цвета:
      верхний ряд — бумага, чернила, панель, и синий акцент
- [ ] шрифт темы — Segoe UI («Главная → Шрифт», строка «Тема»)
- [ ] в свойствах файла стоит название презентации
- [ ] файл сохраняется из PowerPoint без предупреждений (**это важнее, чем
      кажется**: при сохранении PowerPoint переписывает пакет целиком и
      молча чинит то, что ему не понравилось — если после сохранения файл
      стал сильно больше, значит он дописал то, чего мы не дали)

### P2. Текст

- [ ] кегли различимы по ролям: титул крупнее заголовка, заголовок крупнее
      текста
- [ ] отойти на 6–8 м и прочитать **самый мелкий** текст на слайде
- [ ] надстрочные и подстрочные индексы стоят на месте, а не в строке

### P3. Иллюстрация

- [ ] график — набор фигур, а не картинка: щелчок выделяет фигуру
- [ ] подпись оси читается с 6–8 м
- [ ] «Файл → Печать» даёт читаемый лист в ч/б

### И3. Служебная серая на настоящей панели

Единственное решение всего плана масштаба, которое нельзя снять расчётом:
контраст сетки считается к бумаге слайда, но панель светится, а кабинет
освещён. Числа в `draw/style.py` — расчётные, и подтвердить или подвинуть их
может только эта проверка.

- [ ] **на включённой панели при рабочем свете**, не на ноутбуке: сетка
      графика видна с задней парты, но не спорит с линией данных
- [ ] мелкая сетка (подделения `graph/fine-grid`, миллиметровка
      `paper/mm`) видна как сетка, а не как серая заливка
- [ ] решётка векторной диаграммы считается: клетки можно пересчитать
      глазами с 6–8 м
- [ ] сетка не темнее нужного — по ней не читается «это часть рисунка»
- [ ] распечатать тот же урок: **на бумаге сетка прежняя**, светлее того,
      что по ней чертят (носитель листа не менялся, и это надо увидеть)

### P4. Виды слайдов

Смотреть на контрольной колоде — `python tools/slide_sheet.py --pptx`, она
несёт все заготовки всех разложенных видов и называет неразложенные.

- [ ] у каждого слайда в «Образец слайдов» стоит макет своего вида, а не
      «Пустой»
- [ ] «Главная → Сбросить» возвращает слайд на место макета, ничего не
      теряя: значит текст лежит в местах, а не в свободных надписях
- [ ] заголовок стоит на одной высоте на всех слайдах подряд — глаз не
      ищет его заново
- [ ] у `objectives`, `prompt` и `reflection` заголовок называет жанр
      («Цели урока», «Вопросы классу», «Рефлексия») и не дублируется
      кикером
- [ ] маркированный пункт в две строки не подставляет вторую строку под
      маркер
- [ ] ни один слайд не переполнен: если текст ужался автоподгонкой, это
      видно по кеглю мельче соседей — такую заготовку надо укоротить
- [ ] у `board_task` кикер «Задача» стоит на месте заголовка, а ответ —
      внизу, на одной высоте на всех трёх заготовках
- [ ] задача без `answer` не показывает пустого «Ответ:» ни в показе, ни на
      печати (в режиме правки подсказка места — норма)
- [ ] иллюстрация задачи не наезжает на полосу ответа и читается с 6–8 м:
      это самое тесное место колоды (§7, P4б)
- [ ] у `tasks` и `compare` линейки ячеек стоят на одной высоте, и глаз
      видит границу случая, а не догадывается о ней по расстоянию
- [ ] номера задач набраны акцентом и идут по порядку слева направо,
      сверху вниз — тем же порядком, каким учитель их называет
- [ ] ряд ответов в наборе задач стоит по низу, все на одной высоте,
      даже если у одной задачи ответа нет
- [ ] условие в ячейке с картинкой не ужалось автоподгонкой: если кегль
      мельче соседней ячейки, условие длиннее двух строк (§7, P4в)
- [ ] на слайде с четырьмя картинками ничего не пропало и не съехало —
      это единственное место, где на слайде больше сотни фигур

### P5. Формулы

- [ ] формула открывается редактором формул PowerPoint, а не выделяется
      как текст: двойной щелчок по ней даёт «Работа с формулами»
- [ ] дробь на слайде `formula` стоит в полную высоту, а не строкой
- [ ] обозначения выстроены в два столбца: символы по правому краю,
      расшифровки по левому, строки друг напротив друга
- [ ] шаги разбора пронумерованы самим PowerPoint — вставка шага в середину
      пересчитывает остальные
- [ ] **интернета нет**: отключить сеть и открыть колоду — формулы на месте
      (у плеера в этом месте пусто, это и есть закрытый компромисс)
- [ ] в LibreOffice формула читается или хотя бы виден запасной текст со
      знаками доллара, а не пустое место

### P5а. Анимация

**Самая важная страница этого листа.** Ошибка в `p:timing` роняет не
эффект, а показ целиком, и ни один тест этого не увидит.

- [ ] показ вообще запускается (F5) — по всем слайдам, а не только по
      анимированным
- [ ] прогон урока целиком **пальцем на панели**, а не мышью
- [ ] на слайде задачи ответ не виден сразу и появляется по щелчку
- [ ] у разбора шаги открываются по одному, в порядке записи
- [ ] ответ открывается последним событием слайда: щелчок по шагу не
      раскрывает его раньше времени
- [ ] после последнего события следующий щелчок уходит на следующий слайд,
      а не застревает
- [ ] «Анимация → Область анимации» показывает список эффектов, а не пустоту
      и не ошибку
- [ ] «Назад» (стрелка влево) возвращает шаги, а не ломает очередь
- [ ] печать раздатки печатает **всё**, включая ещё не открытые шаги и
      ответы, — иначе учитель раздаст пустые листы
- [ ] в LibreOffice колода листается, даже если анимации не отработали
- [ ] сохранить из PowerPoint и открыть снова: анимация на месте и не
      размножилась
