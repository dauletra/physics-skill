# Worksheet Builder

Собирает рабочий лист в два слоя: **контент — маленькие JSON-файлы** (по
одному на задание), **вёрстка — детерминированный рендерер**, который
превращает их в самодостаточный HTML (центрированная колонка ~800px,
открывается в любом браузере). Единый стиль всех листов гарантирует код
рендерера, а не память между сообщениями.

Три сценария работы, ядро одно (JSON + рендерер): **отдельная
SVG-иллюстрация** — раздел «Отдельная иллюстрация»; **документ без
вопросов** (конспект, теория, текст с иллюстрациями) — раздел «Документ»;
**рабочий лист** — фазы 1–2.

## Запуск рендерера

Ставить ничего не нужно, все команды — так:

```
python <путь-к-skill>/scripts/render.py <папка-черновика>
```

При первом запуске в сессии `render.py` сам доустановит pydantic (несколько
секунд, нужна сеть); дальше рендеры мгновенные. Если установка не удалась —
он напечатает понятную ошибку, сообщи её учителю.

## Жёсткие правила

1. **Никогда не пиши итоговый HTML листа или SVG иллюстрации руками** —
   твоя работа только контент в JSON по схеме `references/task-schema.md`;
   вёрстку и рисунки делает рендерер. В сгенерированных HTML/SVG ничего не
   редактируется — любая правка идёт через JSON и пересборку.
2. **Перед созданием или правкой JSON читай `references/task-schema.md`** —
   там вся схема: `meta.json`, дерево блоков, все виды вопросов и контейнеры.
   Схема строго проверяется при сборке: опечатка в поле, неизвестное
   значение, битая ссылка — ошибка с точным путём до блока, все ошибки
   перечисляются разом.
3. **Файлы сессии эфемерны.** Итог отдавай учителю на скачивание. В
   `worksheet-teacher.html` рендерер встраивает исходный черновик
   (`<script type="application/json" id="worksheet-source">` в конце файла)
   — этого одного файла достаточно, чтобы вернуться к правкам в другой
   сессии: извлеки из него JSON и разложи обратно в `meta.json` +
   `tasks/*.json`.
4. **Правка = редактирование одного `task-NN.json`.** Не перечитывай и не
   переписывай остальные файлы или собранный HTML ради одной правки.

## Фаза 1 — обсуждение и черновик

1. Проясни тему, класс/возраст, набор и количество заданий. Можно начинать
   с одного-двух заданий и добавлять по ходу разговора.
2. Заведи папку черновика (слаг по теме, например `kinematics-9th-grade/`)
   с `meta.json` и по файлу `tasks/task-NN.json` на задание: `id` совпадает
   с именем файла, `order` в `meta.json` перечисляет все файлы. Если учитель
   продолжает ранее начатый лист — попроси загрузить его
   `worksheet-teacher.html` (внутри встроен черновик, см. правило 3) либо
   папку-черновик.
3. Задание — дерево блоков: чистые компоненты (`text`/`table`/`graph`/
   `list`/`instrument`), один из 9 видов вопросов (`open`, `choice`, `match`, `fill_text`,
   `fill_table`, `plot`, `true_false`, `rank`, `classify` — ответ инлайн),
   контейнер-подзадание `part` для пунктов а)/б)/в) и layout-контейнер `row`
   для блоков бок о бок. Состав и инварианты — в `references/task-schema.md`.
   Готовую задачу учителя просто оформи подходящим видом вопроса; «придумай
   задачи по теме» — сочиняй сам под класс/уровень.
4. Обозначения и формулы: обычный текст и Unicode-символы (`α`, `≠`, `м/с²`,
   `υ₀`), LaTeX — только для действительно сложного (дроби, корни). Скорость
   — греческая `υ`, не латинская `v`. Перед формулами сверься с
   `references/symbols.md`.
5. Графики (`graph`/`plot`) — не рисуй SVG сам, задай данные
   (`x_range`/`y_range`/`series`) по `references/charts-and-graphs.md`.
   Измерительные приборы (линейка, мензурка, термометр, динамометр,
   амперметр, вольтметр, манометр, весы, спидометр, секундомер, цифровые
   мультиметр/весы/секундомер; классы точности и многопредельные шкалы —
   задачи на цену деления и погрешности) — компонент `instrument`, тоже
   только данными, по `references/artifacts/instruments.md`. Остальные
   иллюстрации/схемы (наклонная плоскость, электрическая цепь) не
   поддерживаются — опиши условие текстом.
6. Быстрый просмотр одного задания без сборки всего листа:
   ```
   python <путь-к-skill>/scripts/render.py <папка> --task task-03
   ```
   даёт `task-03.preview.html` в реальных стилях (по умолчанию с ответами;
   `--mode student` — версия ученика).

## Фаза 2 — сборка и выдача

Когда учитель говорит «собери лист» — запусти команду запуска на папке
черновика. Появятся `<папка>/output/worksheet-student.html` (без ответов) и
`worksheet-teacher.html` (с ответами). Ошибки схемы печатаются все разом с
путями до блоков — исправь указанные JSON и собери снова.

Отдай на скачивание **оба HTML** и объясни учителю: чтобы вернуться к
правкам в другой сессии, достаточно принести `worksheet-teacher.html` — в
нём встроен весь черновик. Папку JSON отдельно отдавать не обязательно
(но можно, если учитель попросит). Правки после просмотра: измени нужный
`task-NN.json` (или `meta.json`) и пересобери — это мгновенно и бесплатно,
повторяй сколько угодно.

## Отдельная иллюстрация (без листа)

Когда нужна только картинка — график или измерительный прибор для
презентации, отдельной задачи, любых целей учителя:

1. Составь JSON-спеку **одного визуального блока** — та же схема, что у
   блока внутри задания: `graph` — по `references/charts-and-graphs.md`,
   `instrument` — по `references/artifacts/instruments.md`. Сохрани в файл
   (например `visual.json`).
2. Отрендери самодостаточный SVG:
   ```
   python <путь-к-skill>/scripts/render.py --visual visual.json -o velocity-graph.svg
   ```
   Файл несёт шрифт, размеры и белую подложку в себе — его можно вставлять
   в презентацию как есть. Подпись прибора (`caption`) и легенда серий
   графика дорисовываются внутрь SVG автоматически. Нужна иллюстрация
   крупнее (слайд, учебник) — добавь `--scale 2` (любой множитель; шрифты
   и линии растут пропорционально).
3. **Сразу покажи получившийся SVG учителю прямо в диалоге.** Правки — по
   словам учителя: меняешь спеку → перегенерируешь → показываешь снова.
   Файл на скачивание отдавай, когда результат утверждён.

Других видов иллюстраций (схемы, чертежи и т.п.) пока нет: не рисуй SVG
руками — скажи учителю, что такой вид визуала ещё не поддерживается.

## Документ: текст с иллюстрациями (без листа)

Конспект, теория к уроку, просто текст с графиком или прибором — всё, что
не является листом с вопросами:

1. Составь JSON-файл документа (например `notes.json`):
   `{"title": "…", "blocks": [ … ]}`. `blocks` — те же чистые компоненты,
   что в заданиях (`text`, `table`, `list`, `graph`, `instrument` — схема в
   `references/task-schema.md`), плюс подзаголовок раздела
   `{"type": "heading", "text": "…"}` и `row` для блоков бок о бок.
   **Вопросы и `part` в документе запрещены** — если нужны вопросы, это
   сценарий рабочего листа.
2. Собери HTML:
   ```
   python <путь-к-skill>/scripts/render.py --document notes.json
   ```
   Появится `notes.html`: та же колонка и стиль, что у листов, но без
   анкеты-шапки и нумерации заданий; вариант один — режимов
   student/teacher нет. Исходный JSON встроен в HTML всегда: как и с
   листом, одного файла достаточно, чтобы продолжить правки в новой сессии.
3. Отдай HTML на скачивание; правки — через JSON и пересборку.

## Справочники — когда какой читать

- `references/task-schema.md` — **перед любым созданием/правкой JSON.**
- `references/symbols.md` — перед записью формул и обозначений.
- `references/charts-and-graphs.md` — перед созданием графика.
- `references/artifacts/instruments.md` — перед созданием прибора со шкалой
  (виды, типичные шкалы, задачи на погрешности).
- `references/artifacts/` — нюансы конкретного вида визуала
  (`README.md` — индекс, `graphs.md` — разбор по типам графиков).
- `references/design-system.md` — только для вопросов о внешнем виде; стиль
  зафиксирован кодом рендерера и в сессии не меняется.
- `examples/kinematics-9th-grade/` — проработанный образец: все 9 видов
  вопросов, задание с двумя `part` вокруг общего графика (task-10), `row`
  из двух `part` с `plot` (task-13), иерархия символов (task-09), приборы
  с погрешностями в `row` из двух `part` (task-15).
