# Графики — подробный справочник по типам

Глубокий разбор к обзору `../charts-and-graphs.md`. Обзор читаешь при каждой
вёрстке; сюда заходишь, когда нужны нюансы конкретного типа: точная форма
данных, физические формы кривых, подводные камни. Общие SVG-конвенции (ч/б,
viewBox, `esc`) — в `README.md` этой папки.

Все графики рисует один генератор `scripts/visuals.py` (`build_chart_svg`) из
данных — ты **не пишешь SVG**. Компонент `graph` — график как стимул (без
ответа); вопрос `plot` — «постройте график» (ответ инлайн). Форма полей осей у
них одинаковая.

## Поля, общие для всех типов

| Поле | Обязательно | Что задаёт |
|---|---|---|
| `x_label`, `y_label` | да | подписи осей **с единицами**: `"t, с"`, не `"t"` |
| `x_range`, `y_range` | да | `[min, max]` оси — с запасом за данными (не впритык) |
| `chart_type` | нет | `"line"` (по умолч.) / `"bar"` / `"scatter"` |
| `series` | нет¹ | список серий; без него — пустые подписанные оси |

Серия: `{ "label": "…", "points": [[x, y], …], "style": "solid" }`.

- `points` — список пар `[x, y]` в единицах осей.
- `style` — `"solid"` / `"dashed"` / `"dotted"` (различение линий **без цвета**).
- `label` — подпись серии в легенде. **Легенда рисуется для каждой серии, у
  которой есть `label`** — в том числе единственной. Поэтому у одиночной серии
  `label` обычно **опускают** (легенда из одного пункта избыточна); задавай
  `label` тогда, когда серий несколько и их надо различить.

¹ У компонента `graph` `series` опциональна (пустые оси как заготовка под
ручное построение). У вопроса `plot` — см. раздел `plot` ниже.

## `line` — линейный график (по умолчанию)

**Когда:** зависимости во времени (`υ(t)`, `x(t)`), процессы на диаграммах
состояния (p-V, p-T, V-T) — всё, где точки соединяются отрезками в осмысленную
ломаную.

**Форма:** каждая серия — ломаная по своим `points` по порядку. Несколько
серий различаются `style` (+ автоматическая легенда).

```json
{ "type": "graph", "x_label": "t, с", "y_label": "υ, м/с",
  "x_range": [0, 10], "y_range": [0, 20],
  "series": [
    { "label": "Тело A", "points": [[0, 0], [5, 10]], "style": "solid" },
    { "label": "Тело B", "points": [[0, 4], [5, 4]], "style": "dashed" }
  ] }
```

**Физические формы (справочно):**
- Равномерное движение `x(t)` — прямая; равноускоренное `υ(t)` — прямая под наклоном.
- **Процесс на p-V** — ломаная по узловым точкам. **Замкнутый цикл**: повтори
  первую точку в конце, чтобы контур сомкнулся — `[[2,100],[2,300],[6,300],[6,100],[2,100]]`.
- **Изопроцессы в разных осях** (частая ошибка — перепутать форму):
  - изобара (p=const) в V-T — прямая **в начало координат** (`V/T=const`);
  - изохора (V=const) в p-T — прямая **в начало координат** (`p/T=const`);
  - изотерма в p-V — гипербола; ломаной из 2 точек её не передать, дай
    несколько точек по `pV=const`.

**Подводные камни:**
- Ломаная идёт строго в порядке `points` — для цикла следи за порядком обхода
  (по/против часовой в p-V определяет знак работы).
- Больше ~3 серий на одном графике при ч/б-печати сливаются — дели на два графика.

## `bar` — столбчатая диаграмма

**Когда:** сравнение дискретных величин (молярные массы газов, значения по
категориям). Не для непрерывных зависимостей.

**Форма:** столбики белые с чёрной обводкой. **Только одна серия** — столбики
нескольких серий рисовались бы друг поверх друга (это **проверяется
валидацией**, не молча). `x` каждой точки — позиция столбика по оси, `y` — высота.

```json
{ "type": "graph", "chart_type": "bar",
  "x_label": "№ газа", "y_label": "M, г/моль",
  "x_range": [0, 5], "y_range": [0, 50],
  "series": [{ "label": "Молярная масса",
    "points": [[1, 2], [2, 4], [3, 32], [4, 44]], "style": "solid" }] }
```

**Подводные камни:**
- **Категории — числами, не именами.** Ось X числовая: подписи столбиков — это
  `x`-координаты (`1, 2, 3, 4`), а не «водород/гелий». Расшифровку номеров дай
  в тексте условия рядом («№1 — водород, …»).
- **Подпись оси X** прижата к правому концу оси и может слегка наезжать на
  крайний правый столбик. Оставляй справа запас: если столбики на `x = 1..4`,
  бери `x_range: [0, 5]`, а не `[0, 4]`.
- Высоту не «прибивай» к потолку: при максимуме данных 44 бери `y_range` до 50.

## `scatter` — диаграмма рассеяния (точки)

**Когда:** экспериментальные данные — точки без соединения, чтобы показать
разброс/тренд измерений (проверка газового закона по замерам и т.п.).

**Форма:** только маркеры, без линий. Серии различаются **формой маркера** в
порядке: круг → крест → треугольник (`visuals.MARKER_SHAPES`). Легенда
показывает именно маркер серии, а не образец линии.

```json
{ "type": "graph", "chart_type": "scatter",
  "x_label": "T, К", "y_label": "p, кПа",
  "x_range": [250, 550], "y_range": [0, 300],
  "series": [
    { "label": "Опыт I",  "points": [[300, 100], [350, 117], [400, 133]], "style": "solid" },
    { "label": "Опыт II", "points": [[300, 150], [400, 200], [500, 250]], "style": "solid" }
  ] }
```

**Подводные камни:**
- `style` у scatter **не влияет** на вид (маркер задаётся порядком серии) —
  можно оставлять `"solid"`.
- Больше 3 серий — маркеры начнут повторяться (список из трёх форм зациклен).
- Точки из разных серий с одинаковым `x` не сливаются, если различаются по `y`;
  при совпадении и `x`, и `y` маркеры лягут друг на друга.

## `plot` — вопрос «постройте график»

Тот же генератор, но отвечаемый. Поля осей и `chart_type` — как у `graph`.
Две независимые серии-роли:

- `given` (опционально) — то, что **уже дано** ученику на осях (начальная точка,
  часть кривой). Рисуется и у ученика, и у учителя.
- `answer` — **полная правильная** кривая. Рисуется **только у учителя**.

```json
{ "type": "plot", "x_label": "V, л", "y_label": "p, кПа",
  "x_range": [0, 6], "y_range": [0, 250],
  "given":  [{ "label": "1", "points": [[2, 100]], "style": "solid" }],
  "answer": [{ "label": "1→2→3", "points": [[2, 100], [4, 100], [4, 200]], "style": "solid" }] }
```

- У ученика: оси + `given` (пустые оси, если `given` нет) — место для
  построения. У учителя: оси + `answer`.
- Для `chart_type: "bar"` ограничение «одна серия» действует **и в `given`, и в
  `answer`**.
- Одиночная данная точка (`given` из одной точки) — это `line`-серия с одной
  точкой: рисуется как узел, отрезка нет.

## Целочисленные деления осей (общий камень)

Генератор ставит **6 делений на ось равномерно от `min` до `max`** — то есть
шаг = `(max − min) / 5`. Отсюда правило:

> Чтобы подписи делений были круглыми, делай `(max − min)` кратным 5
> (или дающим круглый шаг при делении на 5).

| `x_range` | шаг | подписи | |
|---|---|---|---|
| `[0, 5]` | 1 | 0,1,2,3,4,5 | ✅ красиво |
| `[0, 10]` | 2 | 0,2,4,6,8,10 | ✅ |
| `[0, 250]` | 50 | 0,50,…,250 | ✅ |
| `[0, 6]` | 1.2 | 0, 1.2, 2.4, … | ⚠️ дробные подписи |
| `[0, 7]` | 1.4 | 0, 1.4, 2.8, … | ⚠️ |

Если данные требуют предела `6` (например, объём до 6 л) — либо расширь до `[0, 5]`
уплотнив данные, либо прими дробные деления осознанно; молчаливого «округления»
осей генератор не делает.

## Единицы измерения

По умолчанию СИ (м, с, кг, Н, Дж, Вт, К, Па…), явно в подписях осей и заголовках.
Если задача традиционно в удобных единицах (объём в литрах, давление в кПа) —
допустимо, но подписи осей должны точно называть используемую единицу.
