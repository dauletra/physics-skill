# Проект: скилл physics-materials

Репозиторий — это **библиотека SVG-иллюстраций по физике** (`physics_svg`)
плюс конструктор учебных документов поверх неё, упакованные в Claude-скилл
для учителей. Целевое устройство и зафиксированные решения — в
[docs/architecture.md](docs/architecture.md), принципы схемы данных — в
[docs/schema-design-principles.md](docs/schema-design-principles.md).
Читай их перед любой структурной правкой.

## Ключевые правила

**Иллюстрации — ядро, документ надстроен сверху.** Зависимости строго вниз:
`document -> visuals -> elements -> draw`, и `visuals -> schema`. Обратных
импортов нет, приватные имена через границу слоя не ходят.

**Ноль зависимостей в пакете.** `physics_svg` импортирует только стандартную
библиотеку — скилл обязан работать офлайн, без pip и без сети. Проверяется
`tests/test_bundle.py`: импорты собранного бандла сверяются с
`sys.stdlib_module_names`. Не добавляй зависимость даже «на время».

**Одна модель данных.** `dataclass` + аннотации + ядро в `schema/` — это
одновременно типизированное дерево для рендера, валидатор и источник
JSON Schema. Второго представления нет и кодогенерации нет.

**Иллюстрация рисуется элементами, а не строками SVG.** Если в новом типе
появляется `f'<line x1=...'` — скорее всего нужного элемента ещё нет,
заведи его в `elements/`. viewBox вычисляется из содержимого, id скоупятся
холстом, `Text` эскейпит авторский текст сам.

**У узла два сериализатора.** `Node.svg()` и перевод в фигуры Word
(`draw/shapes.py`) — новый узел обязан принести оба, иначе тип заработает в
HTML и не заработает в Word. Это не «не забудь», а тест:
`tests/draw/test_shapes.py` сверяет подклассы `Node` с образцами. `Raw` —
только для SVG и в рендерерах типов не используется.

**Никакого рукописного HTML.** Контент — маленькие JSON; вёрстку делает
рендерер. Нужно новое визуальное поведение — меняй рендерер или CSS, а не
разметку конкретного блока.

**Разметку пишет только бэкенд.** Компонент и вид задания говорят на словаре
`document/layout.py` («абзац», «список с буквами», «таблица с пропусками»),
а как это выглядит, решает `document/emit/<формат>.py`. Появился тег выше
этой границы — не хватает элемента вёрстки, заведи его в `layout.py`.
Авторский текст доходит до бэкенда сырым: эскейпит бэкенд, а `<sup>` и
подчёркивания разбирает `inline.py`. См. [docs/word-export.md](docs/word-export.md).

**Бандл и справочники генерируются.** Руками в репозитории лежит только то,
что нельзя вывести. Всё, что дублирует существующий источник, собирается
из реестров — см. «Что где лежит».

**Работа идёт в `next`, `main` — это выпуск.** Push в `main` пересобирает
сайт вместе с архивом скилла, то есть всё, что там лежит, учитель уже
скачал. Не коммить туда по привычке; выпуск делает `tools/release.py`,
порядок — в [docs/contribute.md](docs/contribute.md).

## Что где лежит

```
src/physics_svg/
  draw/       холст, геометрия, трансформации, примитивы, стили;
              nodes.py — узел умеет svg(), bbox() и transformed();
              shapes.py — второй сериализатор: фигуры DrawingML для Word
  elements/   физический словарь: шкалы (Axis + scale_marks), штриховка
  schema/     ядро валидации, пути ошибок, JSON Schema, Deferred
  visuals/    библиотека иллюстраций: одна папка = один тип
  document/   компоненты, вопросы, контейнеры, нумерация, «Ответы»;
              layout.py — словарь вёрстки, на котором говорят все слои выше;
              inline.py — авторский текст -> прогоны (<sup>, подчёркивания);
              emit/     — бэкенды: html.py (страница + CSS из assets.py),
                          docx/ (пакет Word: wml.py, styles.py, package.py);
              domain.py — набор, из которого выбирает ученик;
              answers.py — форма ответа для секции «Ответы»
  cli.py      подкоманды build (--format html|docx|both) / visual / schema
skill/        рукописные исходники бандла: SKILL.md, references/, scripts/
examples/     проработанный пример-черновик
docs/         источник сайта; генерируемые страницы гитигнорятся
tools/        build_skill.py, build_site.py, dev.py, contact_sheet.py,
              docx_dump.py, release.py
tests/        draw/, schema/, visuals/, document/, test_bundle.py, test_site.py
evals/        triggers.md — ручной чек-лист срабатываний скилла
```

**Одна папка = один тип.** Новый тип иллюстрации:
`visuals/<тип>/{model.py, render.py, specs/*.json, doc.md, card.md}` плюс
`register(...)` в `__init__.py`. Новый вид задания:
`document/questions/{<тип>.py, <тип>.md, <тип>.card.md}`, в `register(...)` —
`order` (место вида на сайте и в индексе справочника, кратное десяти). Больше
**нигде** ничего править не нужно — союзы для валидации, JSON Schema,
галерея, golden-тесты, справочники бандла и библиотека заготовок собираются
из реестра. `tests/visuals/test_conformance.py` и
`tests/document/test_questions.py` проверят, что тип принёс всё обещанное.

**Спеки и примеры — единый источник.** `visuals/<тип>/specs/*.json` кормят
golden-тесты, галерею сайта, библиотеку в бандле и контрольный лист. Пример
из `<вид>.md` — он же фикстура тестов и превью на сайте. Поэтому пример
обязан быть рабочим, а не иллюстративным: это **целое задание** (`task`) с
условием, вопросом и местом под запись, а не голый payload. Достаёт их
`QuestionType.examples` — единственное место, которое знает про блоки
```json в справочнике; блоков может быть несколько, на сайт попадут все.

**Два адресата документации.** `doc.md` — для модели (поля, инварианты,
JSON, плотно). `card.md` — для учителя (что это, когда нужно, какую фразу
сказать Claude). Не смешивай. Карточка может расставить свои картинки сама —
блок ```` ```spec ```` с именем спеки заменяется рисунком и свёрнутым JSON,
и страница галереи становится разбором случаев (так сделан `graph`). Кто
расставляет часть — расставляет все: проверяет `tests/test_site.py`.

## Как проверять изменения

Из корня репозитория:

1. **Тесты** — обязательно после любой правки:
   `python -m pytest tests -q`. Рендер изменился намеренно — пересними
   эталоны (`REGEN_GOLDEN=1 python -m pytest tests -q`) и **просмотри диф
   глазами**: тест ловит изменение, но не отвечает, стало ли лучше.
2. **Глаза** — после правок рисования: `python tools/dev.py` (контрольный
   лист иллюстраций и пример документа, пересборка на лету) либо
   `python tools/contact_sheet.py --open`.
3. **Линт и типы**: `python -m ruff check . && python -m mypy`. Пакет и
   `tools/` полностью аннотированы (`disallow_untyped_defs`).
4. **Бандл**: `python tools/build_skill.py` — падает, если SKILL.md
   обещает несуществующий файл или карточка типа открывается не коротким
   описанием.
5. **Сайт**: `python tools/build_site.py && zensical build --clean --strict`
   (нужна экстра `docs`). Смотреть — `zensical serve`.
6. **Word** — после правок бэкенда `emit/docx/`: собрать
   `--format docx` и пройти [evals/word.md](evals/word.md) в Word. Тест
   доказывает, что пакет валиден, но не то, что Word его откроет и что лист
   выглядит как задумано. Что именно записалось —
   `python tools/docx_dump.py <черновик>`.

## Язык

Код, комментарии и докстринги — английский. Сообщения об ошибках,
справочники, сайт и SKILL.md — русский: их читают учитель и модель, а не
контрибьютор. В путях ошибок ASCII-стрелка `->`: `→` роняет печать в
cp1251-консоли Windows.

## Известные компромиссы (не «чини» без согласования)

- **KaTeX с CDN, не вендорится** — для формул нужен интернет. Осознанно;
  офлайн-фолбэки не добавлять. Проверка `if (window.renderMathInElement)`
  остаётся — это защита от необработанного исключения, а не офлайн-режим.
- **Печать не инженерится** — никаких `@page`/`@media print`/`break-inside`.
- **Типа документа нет, и жанры равноправны.** Шапка, название и
  разделители — обычные блоки; рендерер не знает, лист перед ним или
  конспект, и ничего не дорисовывает сам. Поле `header` в манифесте было и
  удалено — не возвращать.
- **Анкеты нет.** Полей «Фамилия», «Класс», «Дата» скилл не ставит ни в
  примере, ни по умолчанию: где подписывается ученик — дело школы. Механизм
  остаётся общим (подчёркивания в `text` — линия под запись), так что по
  прямой просьбе строка соберётся. Не возвращать её в скелеты и примеры.
- **Баллов нет.** Вес задания живёт в журнале учителя, а не на листе.
- **Ответы — только секцией в конце.** Инлайн-вариант «ответ под вопросом»
  сознательно не рендерится; раздаточный вариант — тот же документ без
  секции, а не второй режим рендера тел.
- **Цвет автору недоступен** — иллюстрации чёрно-белые: их печатают и
  копируют. Новый пресет в `draw/style.py` заводится, только если
  существующий действительно неверен.
- **Элемент заводится под первый тип, которому он нужен, а не впрок.**
  Стрелки и дуги углов пришли с векторными диаграммами (`elements/arrow.py`)
  и теперь достались осям графика; размерных линий всё ещё нет — заводить их
  до появления типа, которому они нужны, не надо.

## Фаза тестирования

В SKILL.md стоит временная секция «Обратная связь разработчику»
(пользователь скилла = его разработчик; модель обязана в том же ответе
называть ограничения, полувыполнимость и идеи доработок блоком
«⚠️ Для разработчика»). **Удалить секцию перед распространением скилла** —
она помечена этим прямо в заголовке.
