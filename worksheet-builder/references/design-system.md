# Дизайн-система рабочего листа

Это справочник-описание визуальной системы, которую держит код рендерера
(`BASE_CSS` в `worksheet_builder/assets.py`). Стиль зафиксирован кодом:
во время работы над рабочим листом здесь ничего не редактируется — правь
`tasks/*.json`, а не HTML/CSS. Если учитель просит изменить стиль всех
будущих листов (например, «сделай шрифт крупнее для 5 класса»), объясни,
что стиль встроен в скилл и меняется только новой версией скилла от его
разработчика; в рамках сессии такая правка не сохранится.

## Оболочка листа

Лист — **сплошной экранный документ**, а не имитация бумаги:

- Центрированная колонка читаемой ширины: `body { max-width: 800px;
  margin: 0 auto; padding: 24px 32px; }`.
- Все размеры в CSS — в `px` (экранные единицы); шрифты — в `pt`.
- Никакой вёрстки под печать/A4 нет вообще: ни `@page`, ни `@media print`,
  ни разбивки на страницы, ни настроек полей. Ctrl+P отработает как у
  обычной веб-страницы — браузер сам решит разрывы; проект это осознанно
  не инженерит.
- Клиентского JS в листе нет, кроме подключения KaTeX (формулы).

## Типографика

- Шрифт: `"PT Sans", "Segoe UI", Verdana, Arial, sans-serif` — гарантированная
  поддержка кириллицы даже без PT Sans (запасной стек — системные шрифты)
- Базовый размер текста: 12pt, интерлиньяж 1.4
- Заголовок листа (`title` из meta.json): 16pt, bold
- Текст задания: 12pt normal
- Подписи/мелкий текст (баллы): 9pt

## Фон

Страница — абсолютно белая (`background: #fff` на `html` и `body`), без
серого/кремового оттенка от системной темы браузера. Единственное, что не
подчиняется этому — узкая штриховка внутри `.answer-block` (визуальный акцент
блока с ответом), она не влияет на фон всей страницы.

## Ч/б-принцип: смысл — формой, не цветом

Все смысловые различия задаются **формой**, а не цветом: пунктир/штрихпунктир
для графиков, рамки/заливка-штриховка для акцентов, жирность для номеров
заданий. Это принцип стиля (доступность, единый вид, копируемость на ч/б
ксероксе), а не только наследие печати: лист обязан быть полностью читаем,
даже если цвет пропадёт. Цвет допустим только как декоративный акцент, не
несущий уникальной информации.

## Шапка листа

Слева направо/сверху вниз:
1. Строка метаданных для заполнения от руки: `Школа/класс: _____ Дата: _____`
   и `Фамилия Имя: _______________` — рендерер сам рисует прочерки нужной длины,
   даже если `school`/`date` в meta.json пустые. Подписи здесь — из
   `STRINGS` (см. "Локализация служебных строк" ниже) — не хардкодь
   текст, если правишь рендерер.
2. Заголовок (`title`), под ним — подзаголовок из `subject` и `grade` +
   суффикс "класс" мелким шрифтом. Подзаголовок собирается только из
   заполненных частей: пустые `subject`/`grade` не оставляют висячих
   разделителей; если пусто всё — строки нет.
3. Если есть `instructions` в meta.json — абзац курсивом под заголовком

## Нумерация заданий

- Сквозная нумерация начиная с 1, порядок берётся из `meta.json → order`, а не
  из имени файла
- Номер — просто жирная цифра с точкой (`1.`), без рамки или фона, **всегда
  на своей отдельной строке** сверху задания, без исключений — независимо от
  того, сколько элементов в задании и какого они типа. Если у задания есть
  `points`, баллы показываются мелким текстом сразу рядом с номером на этой
  же строке (`1. (2 б.)`). Суффикс "б." — из `STRINGS["points_suffix"]`,
  не литерал в разметке.
- Задание — это дерево `blocks` (компоненты, вопросы, подзадания-`part`), не
  один монолитный тип (см. `task-schema.md`). Вопрос не хранит ни текста, ни
  буквы, ни баллов: описательный текст (условие, инструкция) — это обычный
  `text`-блок рядом в дереве, а буквы/баллы живут на контейнерах (`Task`,
  `part`).
- Буквы `а)`, `б)`... получают подзадания-`part`, по порядку следования —
  **кириллический** перечислительный ряд (константа `LETTERS` в
  `strings.py`, без ё/й/ъ/ы/ь), как принято в русских учебниках. Тот же ряд
  используют маркеры списков (`marker: "letter"`) и сводка ответа в `match`
  — печатная буква и буква в сводке всегда совпадают, источник один.
  Вычисляются буквы при сборке (`compute_part_labels` в `document.py`,
  чистая функция — без мутации блоков). У `part` — своя маленькая строка
  **только** из буквы и/или баллов (`а) (2 б.)`), без текста; если ни буквы,
  ни баллов нет — строки нет вообще, сразу содержимое. Одиночный вопрос без
  `part` и блоки-компоненты (текст, график, таблица, список) букв никогда
  не получают.

## Раскладка блоков

Блоки задания идут один под другим на всю ширину колонки (`.task-block`).
Единственный способ поставить блоки рядом — layout-контейнер `row` (см.
`task-schema.md`): его дети рендерятся колонками `.task-col` внутри
грид-строки `.task-row` (`grid-auto-flow: column; grid-auto-columns: 1fr;
gap: 23px`) — колонки всегда равные, gap грид учитывает сам, никаких
инлайновых ширин из Python нет. Тем же грид-механизмом свёрстаны колонки
`match` (`.match-columns`) — один CSS-язык для любого "рядом". У `part`
внутри колонки левый отступ подзадания обнуляется (`.task-col .task-part`) —
колонку уже отделяет сама раскладка, а лишний отступ крал бы ширину узкой
колонки.

**Ширина графика:** чтобы график не растягивался на всю колонку, у
`svg.visual-svg` фиксированный `max-width: 330px` — единый размер для всех
графиков листа, ширина не скачет от задания к заданию. Поэтому одиночный
график **не** заворачивают в `row` ради ширины — `row` нужен только для
настоящего "рядом" (два подзадания с графиками и т.п.); внутри колонки
график занимает min(ширина колонки, 330px). SVG-генератор (`build_chart_svg`
в `worksheet_builder/visuals.py`) откалиброван именно под эту ширину
(шрифты, толщина линий, `viewBox` — см. `charts-and-graphs.md`); если
меняешь `max-width` в CSS, перепроверь калибровку рендером, а не считай её
универсальной. Селектор намеренно узкий (`svg.visual-svg`, не голый `svg`)
— чтобы не задевать маленькие svg-иконки легенды графика.

## Списки (`list_html`) — зебра-полоски

Одноколоночные списки (`.list-component.cols-single .list-row`) чередуют
белый фон и `#f2f2f2` (`nth-child(even)`) без зазоров между строками — это
помогает визуально не потерять, какому пункту соответствует какая
отметка/квадрат в длинном списке. Правило действует одинаково для всех видов
вопросов, использующих `list` (`choice`/`true_false`/`rank`/`classify`/
`match`) — единый визуальный язык, а не по одному правилу на каждый вид.
Двухколоночные (`cols-two`) и строчные (`cols-inline`) списки зебру не
получают.

## Настройка вёрстки — только через JSON, не в браузере

Единственный способ что-то настроить — соответствующее поле в JSON
(`response` на `open`, `marker`/`columns` на `list`, контейнер `row` для
раскладки — см. `task-schema.md`) и пересборка `python -m worksheet_builder`.
HTML в браузере — чистый рендер этих значений, без JS-переключателей поверх
них; клиентского JS, кроме KaTeX, в листе нет.

## Локализация служебных строк

Все фиксированные надписи листа (шапка, "Ответ:", "Пояснение:",
"Верно"/"Неверно", суффикс баллов, `<title>`) идут через один плоский словарь
`STRINGS` (`worksheet_builder/strings.py`; лист только русскоязычный, поэтому
без языкового ключа и fallback-логики). Там же — перечислительный ряд букв
`LETTERS`. Не хардкодь эти строки в разметке напрямую.

## Версия для учителя vs ученика

Рендерер собирает оба файла из одних и тех же `tasks/*.json` — учитель не должен
вести два источника правды:
- Студенческая версия: скрывает все инлайн-ответы (`answer`/`correct`/
  `position`/`category`/`match`/значения `blanks`), показывает пустые
  места для решения/ответа
- Учительская версия: показывает те же блоки заданий, но с ответами,
  выделенными визуально (рамка "Ответ:") сразу под условием; `explanation`
  печатается отдельной рамкой "Пояснение:" — без необходимости листать
  отдельный ключ ответов в конце
