# Проект: скилл worksheet-builder

Этот репозиторий *и есть* один скилл Claude (`worksheet-builder/`) плюс папка
для черновых выводов (`preview-worksheet/`). «Разработка» здесь означает
правку SKILL.md/references/пакета рендерера и проверку тестами + рендером
примерного workspace.

## Ключевое архитектурное правило

Скилл никогда не пишет итоговый HTML рабочего листа руками. Контент живёт в
маленьких JSON-файлах (`meta.json` + `tasks/task-NN.json`); пакет
`worksheet_builder/` детерминированно рендерит их в HTML
(`python -m worksheet_builder <workspace>`; тонкий CLI — `cli.py`, вся
логика — в соседних модулях, см. разбор ниже). Это разделение существует,
чтобы правка одного задания не требовала чтения/переписывания всего
документа. **Не возвращай рукописный HTML-вывод** при правке этого скилла —
если для изменения нужно новое визуальное поведение, меняй рендерер/CSS, а
не HTML конкретного задания.

Лист — **сплошной экранный HTML-документ**: центрированная колонка 800px,
белый фон, единицы в px. Вёрстки под печать/A4 нет вообще (ни `@page`, ни
`@media print`, ни пагинации, ни полей печати) — это осознанное упрощение;
Ctrl+P отработает как у обычной веб-страницы, и проект это не инженерит.
Единственный клиентский JS — подключение KaTeX; никаких
тулбаров/hover-контролов в сгенерированном HTML нет и заново их добавлять
не стоит без явного запроса — любая настраиваемая вещь должна быть полем в
JSON, а не кликом в браузере.

Поддерживается только русский язык. Служебные строки листа — в плоском
словаре `STRINGS` (`worksheet_builder/strings.py`, без языкового ключа и
fallback-логики); там же — кириллический перечислительный ряд букв `LETTERS`
(`а`, `б`, `в`… без ё/й/ъ/ы/ь) — единый источник для букв подзаданий,
маркеров списков и сводки `match`. Не хардкодь надписи в разметке.

## Валидация — pydantic, политика «строго всё»

Вся валидация схемы — pydantic-модели в `worksheet_builder/models.py`,
выполняются при загрузке (`parse_task` / `parse_meta` возвращают модель).
Модели — **единственное представление данных**: то же типизированное дерево
идёт в рендер, параллельных классов с повторным парсингом сырых dict'ов не
заводить.

- `extra="forbid"` на каждой модели: **неизвестное поле — ошибка** (опечатка
  вида `"corect"` не игнорируется молча);
- закрытые словари — `Literal` (`marker`, `columns`, `style`, `select`,
  `chart_type`); неизвестное значение — ошибка, а не молчаливый фолбэк;
- кросс-инварианты — `@model_validator` (ровно один `correct` при `single`,
  перестановка `position 1..N`, ссылки `match`→`right.id`, плейсхолдеры ==
  ключам `blanks`, `min < max` в диапазонах, одна серия и `y_range` с нуля у
  `bar`, `points > 0`, явный `label` — уникальная буква из `LETTERS`,
  инварианты состава `part`/вопрос, лимит числа `part`/пунктов по алфавиту
  букв, уникальность `id` блоков);
- инварианты уровня workspace — в `load_workspace` (`cli.py`), не в моделях:
  каждый файл `tasks/*.json` перечислен в `meta.order` (иначе он молча выпал
  бы из листа), `id` задания совпадает с именем файла;
- ошибка называет **путь до блока** (`task-10 -> blocks[2] -> graph ->
  x_range: …`; ASCII-стрелка `->` намеренно — `→` роняет печать в
  cp1251-консоли Windows); CLI собирает ошибки **всех** заданий и печатает
  одним списком, без traceback.

Функции рендера (`components.py`, `questions.py`, `document.py`) инварианты
**не** перепроверяют — им приходит уже валидное дерево моделей. Новую
проверку добавляй в модель, не в рендер. Машиночитаемая схема для редактора
генерируется: `python -m worksheet_builder --emit-schema
references/task.schema.json` — перегенерируй при любом изменении моделей
(CI сверяет её с моделями и падает, если она устарела).

**Архитектура задания — дерево блоков** (см.
`worksheet-builder/references/task-schema.md`; принципы проектирования —
`references/schema-design-principles.md`):
- **Чистые компоненты** (`text`/`table`/`graph`/`list`, функции в
  `worksheet_builder/components.py`) — только отрисовка, никакого знания об
  ответе/правильности/режиме.
- **Вопросы** (функции рендера в `worksheet_builder/questions.py`, по одной
  на педагогический вид: `open`, `choice`, `match`, `fill_text`,
  `fill_table`, `plot`, `true_false`, `rank`, `classify`) — естественные
  поля своего вида в модели, ответ записан **инлайн** внутри элемента
  содержимого; функция сама решает, что показать в режиме
  `student`/`teacher`. Конверт одинаков: `type` + опциональные
  `id`/`explanation`; `label`/`points` на вопросе не живут.
- **Контейнер `part`** (подзадание) — компоненты-контекст + ровно один
  вопрос; буква (`а)`/`б)`) и `points` подзадания — на нём, не на вопросе.
- **Layout-контейнер `row`** — дети стоят колонками в одну строку и всегда
  делят её поровну; поле `width` отклоняется валидацией. `row` **прозрачен**
  для инвариантов состава и букв (`iter_flat`): раскладка меняет только
  геометрию, никогда — смысл/нумерацию. Вложенный `row` запрещён.

`Task { id, points?, blocks: (Component | Question | Part | Row)[] }` —
смысловая связь выражается вложенностью, а не соседством. Инварианты состава:
`part` и голый вопрос не бывают соседями; голый вопрос на уровне задания —
не более одного; вложенные `part`/`row` отклоняются. Одиночный график в
`row` не заворачивается — его ширина всегда ограничена `max-width: 330px` в
CSS. Иллюстрации/схемы намеренно вне scope, см. «Явно вне scope» в
`task-schema.md`; `graph`/`plot` — единственный визуальный элемент.

## Где что лежит

- `worksheet-builder/pyproject.toml` — пакет `worksheet-builder` (зависимость
  pydantic; dev-extra pytest/mypy/ruff и их конфиги `[tool.mypy]`/
  `[tool.ruff]`; entry `render-worksheet`). **Контракт запуска для
  пользователя скилла — uv, без установки Python/пакета**:
  `uv run --project <путь-к-skill> render-worksheet <workspace>` (uv сам
  скачивает managed CPython и зависимости; версии зафиксированы в
  `uv.lock` — коммитится, перегенерация `uv lock` при изменении
  зависимостей). Dev-workflow на этой машине — по-прежнему
  `pip install -e "worksheet-builder[dev]"` и прямые `python -m …`-команды;
  не «упрощай» SKILL.md обратно к pip — пользователи скилла на Windows без
  Python.
- `worksheet-builder/SKILL.md` — рабочий процесс скилла.
- `worksheet-builder/references/task-schema.md` — человеческая схема JSON;
  `task.schema.json` — генерируемая машиночитаемая копия (не редактируй
  руками).
- `worksheet-builder/references/schema-design-principles.md` — принципы
  проектирования схемы + чек-лист нового вида вопроса.
- `worksheet-builder/references/design-system.md` — оболочка листа, шрифты,
  нумерация, зебра списков, ширина графика. Держи в синхроне с `BASE_CSS`
  (`worksheet_builder/assets.py`) при изменении любого из них.
- `worksheet-builder/references/charts-and-graphs.md` — формат данных графика;
  `references/artifacts/` — глубокие справочники по SVG-артефактам
  (`README.md` — индекс/конвенции/чек-лист, `graphs.md` — per-type разбор).
  Держи индекс в синхроне при добавлении нового генератора визуала.
- `worksheet-builder/references/symbols.md` — правило текст → `<sup>`/`<sub>`
  → LaTeX и таблица греческих букв. Специфика проекта: скорость — `υ`
  (ипсилон), не латинская `v` (`v` неотличима от `ν`-ню в шрифтовом стеке).
  Не «упрощай» обратно к `v`, не перечитав этот файл.
- `worksheet-builder/worksheet_builder/` — пакет рендерера:
  - `cli.py` — CLI (`load_workspace` — плюс workspace-инварианты: файл вне
    `order` и `id` ≠ имя файла — ошибки; `parse_tasks` — сбор всех ошибок,
    `--task`/`--mode`, `--emit-schema`); `__main__.py` — `python -m`.
  - `models.py` — вся валидация и типизированное дерево данных (см. раздел
    выше); `iter_flat_models()` — сплющенный обход (row прозрачен).
  - `assets.py` — `KATEX_HEAD` и `BASE_CSS` (константа, без параметров).
  - `strings.py` — `STRINGS`/`t()`/`LETTERS`.
  - `render_helpers.py` — `esc()` + хелперы «места под ответ» (`lines`/
    `blank`/`blank_cell`/`answer_block`/`bank_list`). `esc()` намеренно
    пропускает буквальные `<sup>`/`<sub>` — не заменяй на голый
    `html.escape()`. Правило экранирования: модель хранит **сырой**
    авторский текст — эскейпит функция рендера в точке интерполяции;
    забытый `esc()` ловит фузз-тест (`tests/test_escaping.py`).
  - `visuals.py` — генератор графиков (`build_chart_svg`, принимает
    `SeriesModel`), viewBox 220×124, калиброван под ширину 330px
    (`max-width` у `svg.visual-svg`); меняешь ширину — перепроверь
    font-size/stroke-width рендером. Круглые деления — `_tick_positions`.
  - `components.py` — функции рендера чистых компонентов + хелперы
    `list_html`/`table_html` (принимают уже готовую безопасную разметку —
    ими пользуются и вопросы).
  - `questions.py` — функции рендера 9 видов вопросов (`render_<вид>(model,
    mode)`); общий конверт (`explanation`-рамка «Пояснение:» в тичер-режиме)
    — в `render_question`.
  - `document.py` — сборка задания и документа; буквы `а)/б)` считает
    `compute_part_labels` (чистая функция, без мутации блоков);
    `build_document(meta, tasks, is_teacher)` принимает уже распарсенные
    `TaskModel` — парсинг один на оба варианта листа.
- `worksheet-builder/tests/` — pytest: golden-снапшоты (9 видов × 2 режима +
  составные + полный пример), негативная таблица валидации, ошибки уровня
  workspace и фузз эскейпинга (автоматически покрывает новый вид вопроса,
  как только он добавлен в `MINIMAL_TASKS`).
- `.github/workflows/ci.yml` — CI: ruff, mypy, pytest, сверка
  `task.schema.json` с моделями.
- `worksheet-builder/examples/kinematics-9th-grade/` — проработанный пример
  (14 заданий, все виды вопросов; task-09 — иерархия символов, task-10 —
  два `part` вокруг общего графика, task-13 — `row` из двух `part` с
  `plot`).
- `preview-worksheet/` — сгенерированная копия примера в корне проекта, чтобы
  человек мог открыть HTML. **Не часть скилла**, можно перегенерировать.

## Как проверять изменения

1. **Тесты** (обязательно после любой правки пакета):
   ```bash
   python -m pytest worksheet-builder/tests -q
   ```
   Golden-тесты сравнивают HTML с эталонами в `tests/golden/`. Если рендер
   изменился **намеренно** — пересними эталоны
   (`REGEN_GOLDEN=1 python -m pytest worksheet-builder/tests -q`) и просмотри
   диф глазами перед коммитом.
2. **Рендер + глаза** (после правок CSS/визуала):
   ```bash
   python -m worksheet_builder preview-worksheet
   ```
   и открой `preview-worksheet/output/worksheet-teacher.html` (в нём и
   вопросы, и ответы — один файл показывает всё) в Preview-тулзе. Особенно
   после правок CSS: слишком широкий селектор имеет свойство просачиваться
   (был баг, когда `svg { width: 100% }` растягивал иконки легенды —
   починили узким `svg.visual-svg`).
3. **Линт и типы** (быстро, из папки `worksheet-builder/`):
   ```bash
   python -m ruff check . && python -m mypy
   ```
   Конфиги — в `pyproject.toml`; CI гоняет то же самое. Пакет полностью
   аннотирован (`disallow_untyped_defs`) — новые функции пиши с типами.
4. При изменении `models.py` — перегенерируй
   `references/task.schema.json` (`--emit-schema`); CI сверяет.

## Известные компромиссы (не «чини» их без согласования)

- **KaTeX грузится с CDN (jsdelivr), не встроен локально** — сгенерированный
  HTML маленький, но для просмотра формул нужен интернет. Осознанное
  допущение, не недосмотр: не вендорь ассеты и не добавляй офлайн-фолбэки.
- Исключение: проверка `if (window.renderMathInElement)` в `KATEX_HEAD`
  (`worksheet_builder/assets.py`) остаётся — это не «офлайн-поддержка»
  (формулы отрендерятся сырым `$...$`, если CDN не пришёл), она просто
  избегает необработанного JS-исключения. Оставь эту проверку; не делай
  вызов безусловным.
- **Печать не инженерится.** Никаких `@page`/`@media print`/`break-inside`
  нет намеренно — лист экранный. Не добавляй печатный CSS «на всякий
  случай»; если понадобится печать — это отдельное продуктовое решение.
- Пример в `examples/` и `preview-worksheet/` дублируются осознанно: первый —
  часть скилла и участник golden-тестов, второй — человеческое превью в
  корне. Не переноси второй внутрь скилла.
