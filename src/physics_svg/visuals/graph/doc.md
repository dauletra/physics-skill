# `graph` — график с осями

Задаются **данные**, не рисунок: диапазоны осей и точки серий. Раскладку и
легенду выбирает рендерер; деления — тоже он, пока их не задали явно.

```json
{
  "type": "graph",
  "x_label": "t, с",
  "y_label": "υ, м/с",
  "x_range": [0, 8],
  "y_range": [0, 20],
  "series": [
    { "points": [[0, 4], [8, 20]], "label": "тело 1" },
    { "points": [[0, 0], [8, 12]], "label": "тело 2", "style": "dashed" }
  ]
}
```

| поле | обяз. | значения |
|---|---|---|
| `x_label`, `y_label` | да | подпись с единицей: `«t, с»`, `«υ, м/с»` |
| `x_range`, `y_range` | да | `[min, max]`, `min < max` |
| `x_step`, `y_step` | нет | цена деления оси — шаг засечек |
| `x_label_step`, `y_label_step` | нет | шаг подписанных засечек; кратен цене деления |
| `chart_type` | нет | `line` (по умолчанию), `bar`, `scatter` |
| `grid` | нет | `ticks` (по умолчанию), `fine`, `none` |
| `series` | нет | список серий; пустой — только оси и сетка |

Серия: `points` (список `[x, y]`, хотя бы одна точка), `label` (подпись в
легенде), `style` (`solid`/`dashed`/`dotted`).

## Деления, засечки, подписи

Ось всегда несёт засечки: подписанная длиннее, остальные короче. **Подписано
не каждое деление** — числа по вертикали стоят в столбик, и их помещается
заметно меньше, чем по горизонтали; неподписанная засечка нормальна, по ней
считают клетки. Ось выходит за последнее деление и заканчивается стрелкой, а
название величины стоит в ряду её же чисел — за стрелкой по X, над столбцом
чисел по Y. Ноль в начале координат печатается один раз, его подписывает
ось Y.

Диапазон может уходить в минус. Если ноль **внутри** диапазона, ось проводится
через ноль и выходит координатная плоскость с четырьмя четвертями (`F = −kx`,
проекция скорости, координата слева от начала отсчёта); числа тогда стоят
внутри поля у своих осей и печатаются поверх кривой, не давая себя перечеркнуть.
Если диапазон начинается с нуля или не доходит до него, оси идут по краю поля,
и внутри не рисуется ничего, кроме данных.

- ничего не задано — рендерер берёт круглое деление (1/2/5 × 10ⁿ) и сам
  решает, каждое ли подписывать: по X помещается до девяти чисел, по Y — до
  семи;
- задан `x_step` — засечки через него, подписи он прореживает так же;
- заданы оба — засечки через `x_step`, числа через `x_label_step`.

Мельче читаемого шаг подписей задать нельзя: по Y это отвергается примерно с
девяти чисел, по X — с четырнадцати.

`grid` решает отдельно, что тянется линиями через всё поле:

| `grid` | линии |
|---|---|
| `none` | никаких: голые оси с засечками |
| `ticks` | на подписанных делениях |
| `fine` | на всех делениях; если подписано каждое, деление дробится на 5 |

`"x_range": [0, 40], "x_step": 5, "x_label_step": 10` — засечки каждые 5,
числа 0, 10, 20, 30, 40; с `grid: "fine"` между числами ещё и тонкая линия.
Оси независимы: по X можно задать шаг, по Y оставить автоматический.

## Правила

- **Шаг задавай, когда он часть задания** («цена деления 5 м/с», «сетка, по
  которой снимают показания»). В остальных случаях бери круглые границы —
  `[0, 8]`, а не `[0, 7.3]`, — и доверься рендереру.
- Явный шаг обязан укладываться в диапазон нацело, а шаг подписей — быть
  кратным цене деления: число стоит на засечке. Иначе — ошибка.
- Слишком мелкий шаг тоже отвергается: засечки сольются, числа налезут.
- `grid: "fine"` — когда по графику **снимают** значения между подписями или
  строят точки. Полноразмерная миллиметровка — это `paper`, а не график.
- `grid: "none"` — иллюстрация к теории, где по графику ничего не считывают:
  форма кривой, а не числа.
- `chart_type: "bar"` — только одна серия и `y_range` строго от нуля:
  столбик, растущий не от нуля, врёт о соотношении высот.
- Точки серии соединяются в порядке списка — сортируй по x сам.
- Пустой `series` — нормальный график: оси с сеткой под построение от руки.
- Легенда рисуется сама, если у серий есть `label`; для одной серии подпись
  обычно не нужна.
