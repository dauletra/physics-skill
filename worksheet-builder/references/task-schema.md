# Схема данных рабочего листа

Рабочий лист живёт как папка с JSON-файлами, а не как HTML. Ты (Claude) читаешь и
правишь только эти файлы во время диалога с учителем. HTML появляется позже, его
генерирует `scripts/render_worksheet.py` — не пиши HTML руками.

Почему так: правка одного задания не должна требовать чтения/переписывания всего
документа. Задание — отдельный маленький файл, значит правка — маленький, дешёвый диф.

## Структура папки

```
<slug-темы>/
├── meta.json
└── tasks/
    ├── task-01.json
    ├── task-02.json
    └── ...
```

`<slug-темы>` — короткое имя латиницей/цифрами по теме (`kinematics-9th-grade`),
создаётся в текущей рабочей директории teacher'а.

## meta.json

```json
{
  "title": "Кинематика: равномерное и равноускоренное движение",
  "subject": "Физика",
  "grade": "9",
  "language": "ru",
  "school": "",
  "date": "",
  "duration_minutes": 40,
  "instructions": "Необязательное вступление под шапкой (например, инструкция по выполнению).",
  "order": ["task-01", "task-02", "task-03"]
}
```

- `language`: только `"ru"` — служебные подписи листа (шапка, "Ответ:",
  "Верно"/"Неверно", подписи тулбара) через словари `STRINGS`/`UI_STRINGS` в
  рендерере.
- `order` — явный список id заданий в нужном порядке. Менять порядок = менять только этот массив, файлы заданий не трогать.
- Поля `school`, `date` можно оставить пустыми — рендерер выведет их как прочерк для заполнения от руки.

## Модель: задание = список компонентов

Каждое задание — это не один монолитный "тип", а **плоский упорядоченный список
компонентов** (`components`). Часть компонентов — информационные (текст, график,
таблица, схема, справочные данные), они просто показываются как есть, никогда не
несут ответа. Часть — отвечаемые (открытый вопрос, выбор, сопоставление,
заполнение...), они всегда несут ответ для тичер-версии. Какой компонент из
какой группы — фиксировано его `type`, отдельного поля "это вопрос или нет" в
JSON нет.

Один график/таблица/схема, за которым идёт несколько разноформатных вопросов —
это просто такой компонент один раз в списке, а дальше несколько отвечаемых
компонентов подряд. Дублировать `chart_spec`/`svg_snippet` под каждый вопрос не
нужно.

```json
{
  "id": "task-01",
  "points": 2,
  "prompt": "Общее вступление, показывается один раз до всех компонентов (необязательно).",
  "layout": [1, 2],
  "components": [
    { "type": "...", "...": "..." },
    { "type": "...", "...": "..." },
    { "type": "...", "...": "..." }
  ]
}
```

- `id`, `components` — обязательны. `components` — минимум один элемент, даже
  для самого простого "один открытый вопрос" задания (единая форма файла, без
  сокращённой записи для тривиального случая).
- `points` — опционально, общий балл рядом с номером задания. Независим от
  `points` внутри отдельных компонентов (см. ниже) — не суммируется автоматически.
- `prompt` — опционально, общий контекст/вступление, выводится один раз перед
  всеми компонентами. Если у задания всего один компонент и объяснять нечего —
  не указывай, тогда компонент показывается сразу с номером задания.
- `layout` — опционально, раскладка компонентов по строкам, см. "Раскладка:
  `layout`" ниже. По умолчанию (не указано) — каждый компонент в своей
  полноширинной строке (всё "в столбик").

Каждый компонент — свой JSON-объект с обязательными `type`, `prompt` и
специфичными для типа полями. `points` — опционален на уровне компонента: если
задан, балл печатается рядом с буквой компонента (см. "Буквы" ниже).

```json
{
  "type": "text_with_solution",
  "points": 2,
  "prompt": "Текст задания. Простые обозначения — обычным текстом: υ₀, α, ≠, м/с². Формулы — LaTeX, только когда это оправдано: блоком $$E_k = \\frac{m\\upsilon^2}{2}$$.",
  "...": "поля конкретного типа"
}
```

Приоритет для любого символа/обозначения — **текст → `<sup>`/`<sub>` → LaTeX**,
подробно и с таблицей готовых символов в `references/symbols.md`. LaTeX
(`$...$`/`$$...$$`) подключается через KaTeX и оправдан только для настоящих
составных выражений (дробь, корень с содержимым, система уравнений) — не для
одной греческой буквы или значка сравнения.

## Буквы и баллы

Буквы `a)`, `b)`, `в)`... получают **только отвечаемые компоненты**, по
порядку следования в списке `components` (не по строкам `layout` — нумерация
сквозная по документу), и только если отвечаемых компонентов в задании больше
одного. Информационные компоненты (текст, график, таблица...) буквы никогда не
получают. Если в задании всего один отвечаемый компонент — он рендерится без
буквы, как обычное простое задание (буква не нужна, отвечать больше не на что).

Букву можно задать явно через `label` на самом компоненте (`"label": "a"`); если
не задано — рендерер проставляет `a, b, c...` сам по порядку. Не дублируй букву
внутри `prompt` компонента — рендерер выводит её отдельным элементом перед
текстом, а не как часть текста.

Баллы — независимо на двух уровнях: `points` всего задания (общий балл рядом с
номером) и `points` отдельного компонента (балл рядом с его буквой, если у
компонента есть буква). Суммирование не проверяется автоматически.

## Раскладка: `layout`

По умолчанию (поле `layout` не задано) все компоненты идут один под другим на
всю ширину — так же, как сегодня выглядит любое простое задание.

`layout` — массив, партиционирующий `components` по порядку на строки. Каждый
элемент массива — это либо:
- **целое число N** — следующие N компонентов идут в одну строку, поровну
  делят ширину (для двух — 50/50, для трёх — по ~33% и т.д.);
- **список процентов**, например `[40, 60]` — следующие столько же компонентов
  (сколько чисел в списке) идут в одну строку с явно заданной шириной каждого
  (сумма должна быть 100).

Сумма количества компонентов по всем элементам `layout` обязана равняться
длине `components`.

```json
{
  "id": "task-13",
  "prompt": "Идеальный газ переходит из состояния 1 в 2, из 2 в 3 согласно графику V-T. Постройте графики этого же процесса в координатах p-V и p-T.",
  "layout": [1, 2],
  "components": [
    { "type": "chart", "chart_spec": { "...": "дан V-T график с тремя состояниями" } },
    { "type": "chart_fill", "prompt": "Постройте график в координатах p-V.", "chart_spec": { "...": "только оси" }, "answer_chart_spec": { "...": "правильная ломаная p-V" } },
    { "type": "chart_fill", "prompt": "Постройте график в координатах p-T.", "chart_spec": { "...": "только оси" }, "answer_chart_spec": { "...": "правильная ломаная p-T" } }
  ]
}
```
Здесь `layout: [1, 2]` — первая строка из 1 компонента (дан V-T на всю
ширину), вторая строка из 2 компонентов (p-V и p-T бок о бок, по 50%
каждый). Первый компонент без буквы (это `chart`, информационный), второй и
третий получают `a)` и `b)` (это `chart_fill`, отвечаемые).

В браузере, если `layout` содержит хотя бы одну строку шире 1 компонента, под
заданием появляется переключатель "Как в JSON" / "Всё в столбик" — аварийный
сброс к полностью вертикальной раскладке прямо на экране (например, если на
конкретном принтере/экране составная раскладка не помещается), без правки
JSON. Как и остальные переключатели тулбара (ниже), это состояние экрана —
что видно на момент печати (Ctrl+P), то и печатается; при пересборке из JSON
раскладка возвращается к значению `layout`.

## Информационные компоненты (без ответа)

### `text` — абзац
```json
{ "type": "text", "prompt": "Свободный текст-связка между другими компонентами." }
```
Для отдельного, самостоятельного абзаца, когда task-level `prompt` уже занят
общим вступлением, а между компонентами нужен ещё один кусок пояснения.

### `list` — список
```json
{
  "type": "list",
  "prompt": "Перечислите основные величины кинематики.",
  "items": ["Путь", "Перемещение", "Скорость", "Ускорение"],
  "ordered": false
}
```
`ordered` — опционально, по умолчанию `false` (маркированный список), `true` —
нумерованный.

### `table` — справочная таблица
```json
{
  "type": "table",
  "prompt": "Плотности некоторых веществ.",
  "headers": ["Вещество", "ρ, кг/м³"],
  "rows": [["Вода", "1000"], ["Сталь", "7800"], ["Воздух", "1.29"]]
}
```
Для табличных данных, которые просто даны, а не заполняются учеником — если
нужна именно заполняемая таблица, см. `fill_blank_table` ниже.

### `reference_data` — блок "Дано:"
```json
{
  "type": "reference_data",
  "prompt": "",
  "items": [
    {"symbol": "m", "value": "2 кг"},
    {"symbol": "υ₀", "value": "0"},
    {"symbol": "g", "value": "9.8 м/с²"}
  ]
}
```
Компактный блок известных величин в традиционной для физики форме "Дано:" —
альтернатива перечислению этих же значений прозой внутри `prompt`, когда их
несколько и хочется единообразного вида.

### `chart` — дан график
```json
{
  "type": "chart",
  "prompt": "На графике показана зависимость скорости тела от времени.",
  "chart_spec": {
    "chart_type": "line",
    "x_label": "t, с",
    "y_label": "υ, м/с",
    "x_range": [0, 10],
    "y_range": [0, 20],
    "series": [
      {"label": "Тело A", "points": [[0,0],[5,10],[10,20]], "style": "solid"},
      {"label": "Тело B", "points": [[0,5],[10,15]], "style": "dashed"}
    ]
  }
}
```
Не рисуй SVG графика сам — просто дай данные (`chart_spec`), рендерер строит
единообразный ч/б-график по `charts-and-graphs.md`. `style`: `solid` / `dashed`
/ `dotted` — так серии различаются без цвета. `chart_type`: `line` / `bar` /
`scatter`. Это чистый stimulus — график просто дан, ответа у самого этого
компонента нет; вопрос "прочитай график и ответь" — это отдельный отвечаемый
компонент после него в том же списке `components` (см. пример с task-10 ниже).

### `illustration` — дана иллюстрация/схема
```json
{
  "type": "illustration",
  "prompt": "На рисунке изображён брусок на наклонной плоскости.",
  "svg_snippet": {"name": "inclined_plane", "params": {"angle": 30, "mass_label": "m = 2 кг"}}
}
```
Сначала проверь словарь `SVG_SNIPPETS` в `scripts/render_worksheet.py` — если
там уже есть подходящий генератор (сейчас: `inclined_plane`, `simple_circuit`),
используй `svg_snippet`. Если нужной схемы нет — как исключение можно дать
`"raw_svg": "<svg ...>...</svg>"` с рукописным SVG, строго следуя стилю из
`charts-and-graphs.md` (толщина линий, шрифт подписей, отсутствие цвета,
разумный размер под колонку). Как и `chart`, это чистый stimulus — без ответа.

## Отвечаемые компоненты

### `text_with_solution` — текст с местом для решения
```json
{
  "type": "text_with_solution",
  "prompt": "Тело движется со скоростью 5 м/с. Найдите путь за 10 с.",
  "solution_lines": 4,
  "answer": "s = vt = 5 * 10 = 50 м"
}
```
`solution_lines` — сколько разлинованных строк оставить под решение (обычно 3-6).
`show_solution` — опционально, по умолчанию `true`; если `false`, область под
решение рендерится сразу скрытой (`display:none`). В сгенерированном HTML под
компонентом есть тулбар "Место для решения: Показать/Скрыть" — учитель может
включить/выключить прямо в браузере перед печатью, не трогая JSON (см.
"Интерактивные элементы вёрстки" в `design-system.md`); поле в JSON задаёт
только начальное состояние при рендере.

### `text_no_solution` — текст с коротким ответом
```json
{
  "type": "text_no_solution",
  "prompt": "Чему равно ускорение свободного падения на Земле (округлённо)?",
  "answer_blank": true,
  "answer": "9.8 м/с²"
}
```
`answer_blank` — рисовать ли короткую подчёркнутую линию для ответа (true для
задач в одну строку, false если ответ — просто устный/для обсуждения).

### `matching` — соответствие
```json
{
  "type": "matching",
  "prompt": "Установите соответствие между величиной и её единицей измерения.",
  "left_items": ["Сила", "Работа", "Мощность"],
  "right_items": ["Вт", "Н", "Дж"],
  "answer_map": {"Сила": "Н", "Работа": "Дж", "Мощность": "Вт"}
}
```
Рендерер нумерует левый список цифрами, правый — буквами; ученик пишет буквы
рядом с цифрами. `answer_map` используется только в тичер-версии. Количество
элементов слева и справа не обязано совпадать: `right_items` может содержать
лишние варианты-дистракторы, не встречающиеся в `answer_map` — это уже
поддержано (ключ `answer_map` не обязан покрывать весь `right_items`), просто
не забудь тогда явно продумать, какие варианты — дистракторы, при написании.

### `multiple_choice` — вопрос с вариантами ответа
```json
{
  "type": "multiple_choice",
  "prompt": "Автомобиль движется равномерно прямолинейно. Как изменяется его скорость со временем?",
  "options": ["Увеличивается пропорционально времени", "Уменьшается пропорционально времени", "Не изменяется", "Изменяется случайным образом"],
  "correct": 2,
  "variants_layout": "single-column",
  "answer": "При равномерном движении скорость постоянна по определению"
}
```
- `options` — список вариантов, рендерятся буквами `a) b) c)...` (тем же
  `LOWER_LETTERS`, что и буквы отвечаемых компонентов).
- `multi_select` — опционально, по умолчанию `false`. При `false` — один
  правильный вариант, `correct` — 0-индексный номер (int), рендер — как выбор
  одного варианта. При `true` — несколько правильных, `correct` — список
  0-индексных номеров, рендер — чекбоксы вместо отметки одного варианта.
- `correct` — используется только в тичер-версии (отмечается галочкой и
  жирным, без цвета); форма (int или список int) зависит от `multi_select`.
- `variants_layout` — опционально, по умолчанию `"single-column"`. Варианты:
  `"single-column"` (каждый вариант на своей строке), `"two-column"`
  (CSS-колонки), `"inline"` (варианты друг за другом в строку). В
  сгенерированном HTML под компонентом есть тулбар "Варианты: 1 колонка / 2
  колонки / В строку" — можно переключать прямо в браузере; это поле задаёт
  только начальную раскладку (см. "Интерактивные элементы вёрстки" в
  `design-system.md`).

### `true_false` — правда/ложь
```json
{
  "type": "true_false",
  "prompt": "Отметьте, верны ли утверждения.",
  "statements": [
    {"text": "Скорость — скалярная величина.", "answer": false},
    {"text": "1 Н = 1 кг·м/с².", "answer": true}
  ]
}
```

### `fill_blank_text` — заполнить пропуск в тексте
```json
{
  "type": "fill_blank_text",
  "prompt": "Заполните пропуски.",
  "text_template": "Единица измерения силы в СИ — ___1___. Она названа в честь ___2___.",
  "blanks": {"1": "ньютон", "2": "Исаака Ньютона"}
}
```
Каждый пропуск в `text_template` — плейсхолдер `___N___`, рендерер заменит его на
подчёркнутую линию нужной ширины (либо на ответ, в тичер-версии).

**Важно:** никогда не размещай `___N___` внутри математических `$...$`/`$$...$$`.
Рендерер вставляет пропуск как отдельный HTML-элемент, из-за этого разрывается
текстовый узел, и KaTeX перестаёт видеть закрывающий `$` — формула не
отрендерится, а на листе останутся сырые доллары. Пиши пропуск рядом с
формулой, а не внутри неё:
- Плохо: `"$F = m___1___$"` (пропуск внутри математики ломает формулу)
- Хорошо (здесь LaTeX вообще не нужен — уравнение простое): `"Согласно F = ma, если m = 2 кг и a = 3 м/с², то F = "` + пропуск `___1___`
- Хорошо, если формула действительно составная: `"Согласно $$E_k=\frac{m\upsilon^2}{2}$$, если m = 2 кг и υ = 3 м/с, то $E_k=$ "` + пропуск `___1___` (пропуск всё равно снаружи `$...$`)

### `fill_blank_table` — заполнить таблицу
```json
{
  "type": "fill_blank_table",
  "prompt": "Заполните таблицу значений.",
  "headers": ["t, с", "υ, м/с", "s, м"],
  "rows": [
    ["0", "0", "0"],
    ["1", null, "1"],
    ["2", "2", null]
  ],
  "answers": {"1,1": "1", "2,2": "4"}
}
```
`null` в `rows` — пустая ячейка для заполнения. `answers` — ключ `"row,col"`
(0-индексация), используется только в тичер-версии. Если таблица не должна
заполняться (чисто справочная) — используй `table` из раздела "Информационные
компоненты" выше.

### `chart_fill` — построить график
```json
{
  "type": "chart_fill",
  "prompt": "Постройте график зависимости давления от объёма (изотерма).",
  "chart_spec": {
    "chart_type": "line",
    "x_label": "V, м³",
    "y_label": "p, Па"
  },
  "answer_chart_spec": {
    "chart_type": "line",
    "x_label": "V, м³",
    "y_label": "p, Па",
    "series": [{"label": "1→2", "points": [[1, 6],[2, 3],[3, 2]], "style": "solid"}]
  }
}
```
`chart_spec` — те же поля, что у `chart`, но без `series` (только оси/диапазон:
`x_label`/`y_label`/`x_range`/`y_range`) — ученику даются пустые оси, чтобы
начертить график самостоятельно. `answer_chart_spec` — полноценный `chart_spec`
с `series`, рисуется тем же `build_chart_svg`, но только в тичер-версии, поверх
тех же осей — это и есть эталонный ответ.

### `illustration_draw` — нарисовать схему/явление
```json
{
  "type": "illustration_draw",
  "prompt": "Дорисуйте силы, действующие на брусок на наклонной плоскости.",
  "svg_snippet": {"name": "inclined_plane", "params": {"angle": 30, "mass_label": "m = 2 кг"}},
  "answer_svg_snippet": {"name": "inclined_plane_forces", "params": {"angle": 30, "mass_label": "m = 2 кг"}},
  "answer": "F_тяж = mg, N — перпендикулярно плоскости, F_тр — вдоль плоскости против движения"
}
```
`svg_snippet`/`raw_svg` — опциональная база для рисования (например, наклонная
плоскость без стрелок сил); если её нет — ученику даётся просто подписанное
пустое место под рисунок. `answer_svg_snippet`/`answer_raw_svg` — опциональный
эталонный рисунок-ответ (тот же механизм, что у `illustration`, отдельный
генератор в `SVG_SNIPPETS`, если нужен), либо просто текстовое `answer` как
более простой вариант ответа без готового SVG-эталона. Рисуется/показывается
только в тичер-версии.

## Пример: один график, два разных вопроса по нему

Раньше это требовало дублировать `chart_spec` в двух самостоятельных типах
(`compound`, которого больше нет). Теперь график — один компонент, а вопросы —
любое число отвечаемых компонентов после него в том же списке:

```json
{
  "id": "task-10",
  "points": 5,
  "prompt": "Велосипедист разгоняется равноускоренно из состояния покоя. На графике показана зависимость его скорости от времени.",
  "components": [
    {
      "type": "chart",
      "chart_spec": {
        "chart_type": "line",
        "x_label": "t, с",
        "y_label": "υ, м/с",
        "x_range": [0, 5],
        "y_range": [0, 10],
        "series": [{"label": "Велосипедист", "points": [[0, 0], [4, 8]], "style": "solid"}]
      }
    },
    {
      "type": "text_with_solution",
      "prompt": "Найдите ускорение велосипедиста.",
      "solution_lines": 3,
      "points": 2,
      "answer": "a = Δυ/Δt = 8/4 = 2 м/с²"
    },
    {
      "type": "text_no_solution",
      "prompt": "Используя график, определите путь, пройденный велосипедистом за первые 4 с.",
      "answer_blank": true,
      "points": 3,
      "answer": "s = υt/2 = 8*4/2 = 16 м"
    }
  ]
}
```
Первый компонент (`chart`) без буквы — он информационный. Второй и третий —
`a)` и `b)`, оба видят один и тот же график выше по документу (`layout` не
задан — все три компонента идут в столбик, график сверху, вопросы под ним).

## Мини-превью одного задания

Не обязательно собирать весь лист, чтобы проверить одно задание:
```
python scripts/render_worksheet.py <папка> --task task-04
```
выводит `task-04.preview.html` — маленький HTML с одним этим заданием в реальных
стилях. Используй это после каждой правки задания вместо полной сборки — дешевле
и быстрее.
