# Дизайн-система документа

Это справочник-описание визуальной системы, которую держит код рендерера
(`BASE_CSS` в `worksheet_builder/assets.py`). Стиль зафиксирован кодом:
во время работы над документом здесь ничего не редактируется — правь
`blocks/*.json`, а не HTML/CSS. Если учитель просит изменить стиль всех
будущих документов (например, «сделай шрифт крупнее для 5 класса»),
объясни, что стиль встроен в скилл и меняется только новой версией скилла
от его разработчика; в рамках сессии такая правка не сохранится.

## Оболочка документа

Документ — **сплошной экранный документ**, а не имитация бумаги. Одна и та
же оболочка (колонка, шрифты, стиль блоков) для любого состава: конспект,
набор заданий, теория + задачи вперемешку. Свойства:

- Центрированная колонка читаемой ширины: `body { max-width: 800px;
  margin: 0 auto; padding: 24px 32px; }`.
- Все размеры в CSS — в `px` (экранные единицы); шрифты — в `pt`.
- Никакой вёрстки под печать/A4 нет вообще: ни `@page`, ни `@media print`,
  ни разбивки на страницы, ни настроек полей. Ctrl+P отработает как у
  обычной веб-страницы — браузер сам решит разрывы; проект это осознанно
  не инженерит.
- Клиентского JS в документе нет, кроме подключения KaTeX (формулы).

## Типографика

- Шрифт: `"PT Sans", "Segoe UI", Verdana, Arial, sans-serif` — гарантированная
  поддержка кириллицы даже без PT Sans (запасной стек — системные шрифты)
- Базовый размер текста: 12pt, интерлиньяж 1.4
- Заголовок документа (`title` из document.json): 16pt, bold
- Подзаголовок раздела (блок `heading`) и заголовок секции «Ответы»:
  13.5pt, bold
- Текст задания: 12pt normal
- Подписи/мелкий текст (баллы): 9pt; строки секции «Ответы»: 11pt

## Фон

Страница — абсолютно белая (`background: #fff` на `html` и `body`), без
серого/кремового оттенка от системной темы браузера.

## Ч/б-принцип: смысл — формой, не цветом

Все смысловые различия задаются **формой**, а не цветом: пунктир/штрихпунктир
для графиков, рамки для акцентов, жирность для номеров заданий. Это принцип
стиля (доступность, единый вид, копируемость на ч/б ксероксе), а не только
наследие печати: документ обязан быть полностью читаем, даже если цвет
пропадёт. Цвет допустим только как декоративный акцент, не несущий
уникальной информации.

## Шапка документа

Заголовок (`title`) печатается всегда, если задан. Анкета-часть появляется
только при наличии `header` в `document.json`:

1. Строка метаданных для заполнения от руки: `Школа/класс: _____ Дата: _____`
   и `Фамилия Имя: _______________` — рендерер сам рисует прочерки нужной
   длины, даже если `school`/`date` пустые. Подписи здесь — из `STRINGS`
   (см. "Локализация служебных строк" ниже) — не хардкодь текст, если
   правишь рендерер.
2. Под заголовком — подзаголовок из `subject` и `grade` + суффикс "класс"
   мелким шрифтом. Подзаголовок собирается только из заполненных частей:
   пустые `subject`/`grade` не оставляют висячих разделителей; если пусто
   всё — строки нет.
3. Если есть `instructions` — абзац курсивом под заголовком.

У конспекта без `header` шапка — только заголовок (без нижней
границы-анкеты она всё равно рисуется линией — общий блок `.sheet-header`).

## Нумерация заданий

- Сквозная нумерация `task`-блоков начиная с 1, порядок берётся из
  `document.json → order`, а не из имени файла; теория между заданиями
  (заголовки, текст, иллюстрации) нумерацию не сдвигает.
- Номер — просто жирная цифра с точкой (`1.`), без рамки или фона, **всегда
  на своей отдельной строке** сверху задания, без исключений — независимо от
  того, сколько элементов в задании и какого они типа. Если у задания есть
  `points`, баллы показываются мелким текстом сразу рядом с номером на этой
  же строке (`1. (2 б.)`). Суффикс "б." — из `STRINGS["points_suffix"]`,
  не литерал в разметке.
- Задание — это дерево `blocks` (компоненты, вопросы, подзадания-`part`), не
  один монолитный тип (см. `document-schema.md`). Вопрос не хранит ни текста,
  ни буквы, ни баллов: описательный текст (условие, инструкция) — это обычный
  `text`-блок рядом в дереве, а буквы/баллы живут на контейнерах (`task`,
  `part`).
- Буквы `а)`, `б)`... получают подзадания-`part`, по порядку следования —
  **кириллический** перечислительный ряд (константа `LETTERS` в
  `strings.py`, без ё/й/ъ/ы/ь), как принято в русских учебниках. Тот же ряд
  используют маркеры списков (`marker: "letter"`), сводка ответа `match` и
  буквы подзаданий в секции «Ответы» — печатная буква и буква в
  сводке/ответах всегда совпадают, источник один. Вычисляются буквы при
  сборке (`compute_part_labels` в `document.py`, чистая функция — без
  мутации блоков). У `part` — своя маленькая строка **только** из буквы
  и/или баллов (`а) (2 б.)`), без текста; если ни буквы, ни баллов нет —
  строки нет вообще, сразу содержимое. Одиночный вопрос без `part` и
  блоки-компоненты (текст, график, таблица, список) букв никогда не
  получают.

## Секция «Ответы»

Ответы заданий не печатаются в теле документа — рендерер собирает их в конце
(`build_answers_section` в `document.py`): секция `.answers-section` отбита
сверху линией, заголовок «Ответы» (13.5pt bold, `STRINGS["answers_title"]`),
затем по строке `.answers-item` на вопрос: жирный номер задания с буквой
подзадания слева (`3.` / `3. б)`), компактный ответ справа (11pt). Ответ
вида — одна строка (буква варианта, сводка `1-б, 2-в`, значения пропусков
через `;`), у `plot` — мини-график тем же `svg.visual-svg` (правило ширины
`.answers-body svg.visual-svg` повторяет `.task-block`). `explanation`
печатается курсивом серым (`.answers-explanation`) с подписью «Пояснение:»
после ответа. Выравнивание строк — `flex-start`, не `baseline`: у
ответа-графика первая базовая линия — подпись легенды под SVG, и номер
уезжал бы под график. Задания без единого ответа/пояснения строк не дают;
если их нет вообще (чистый конспект) — секции нет. Раздаточный вариант
(`--no-answers`) собирается без секции целиком.

## Раскладка блоков

Блоки задания идут один под другим на всю ширину колонки (`.task-block`).
Единственный способ поставить блоки рядом — layout-контейнер `row` (см.
`document-schema.md`): его дети рендерятся колонками `.task-col` внутри
грид-строки `.task-row` (`grid-auto-flow: column; grid-auto-columns: 1fr;
gap: 23px`) — колонки всегда равные, gap грид учитывает сам, никаких
инлайновых ширин из Python нет. Тем же грид-механизмом свёрстаны колонки
`match` (`.match-columns`) — один CSS-язык для любого "рядом"; тот же
`.task-row` используется и верхнеуровневым `row` документа. У `part`
внутри колонки левый отступ подзадания обнуляется (`.task-col .task-part`) —
колонку уже отделяет сама раскладка, а лишний отступ крал бы ширину узкой
колонки.

**Ширина графика:** чтобы график не растягивался на всю колонку, у
`svg.visual-svg` фиксированный `max-width: 330px` — единый размер для всех
графиков документа, ширина не скачет от задания к заданию. Поэтому одиночный
график **не** заворачивают в `row` ради ширины — `row` нужен только для
настоящего "рядом" (два подзадания с графиками и т.п.); внутри колонки
график занимает min(ширина колонки, 330px). SVG-генератор (`build_chart_svg`
в `worksheet_builder/visuals.py`) откалиброван именно под эту ширину
(шрифты, толщина линий, `viewBox` — см. `charts-and-graphs.md`); если
меняешь `max-width` в CSS, перепроверь калибровку рендером, а не считай её
универсальной. Селектор намеренно узкий (`svg.visual-svg`, не голый `svg`)
— чтобы не задевать маленькие svg-иконки легенды графика.

**Ширина прибора (`instrument`):** у каждого семейства приборов своя
целевая ширина, и висит она на обёртке, а не на SVG:
`.instrument-wrap.instrument-strip` (линейка) — 330px,
`.instrument-wrap.instrument-column` (мензурка/термометр/динамометр) —
105px, `.instrument-wrap.instrument-dial` (стрелочные) — 240px,
`.instrument-wrap.instrument-clock` (секундомер) — 180px,
`.instrument-wrap.instrument-vernier` (штангенциркуль) — 330px,
`.instrument-wrap.instrument-balance` (рычажные весы) — 255px,
`.instrument-wrap.instrument-digital` (цифровое табло) — 225px. SVG внутри
заполняет обёртку по правилу `svg.visual-svg`. Масштаб всех семейств —
~1.5px на единицу viewBox, тот же, что у графиков (220 → 330px), поэтому
шрифты всех SVG документа одного экранного размера. Подпись `caption`
центрируется под прибором (`.instrument-caption`, 9pt). Приборы ставят
рядом обычным `row`; одиночный прибор в `row` не заворачивают — его ширину
и так держит обёртка.

**Ширина бумаги (`paper`):** у места под работу ученика ширина бывает двух
родов, и класс обёртки говорит, какого именно. `.paper-wrap.paper-fixed` —
ширина из данных (`cols` у клетки/миллиметровки/точек): её несут атрибуты
самого SVG, а CSS лишь не даёт полю вылезти за узкую колонку `row`
(`max-width: 100%`, при сжатии поле уменьшается пропорционально, клетка
остаётся квадратной). `.paper-wrap.paper-fluid` — поле во всю колонку
(`lines`/`plain` без `cols`): ширину даёт колонка, а высоту — переменная
`--paper-h`, которую рендер кладёт на обёртку. Без неё сработало бы общее
`height: auto`, и в узкой колонке строки сплющились бы вместе с шириной —
высота места под ответ авторская, а не производная ширины. Оба правила
перебивают общее `svg.visual-svg` (max-width 330px) узко, по классу
обёртки — как и все остальные ширины SVG здесь.

Шаг разлиновки — в единицах viewBox при том же масштабе 1.5px/единица:
строка `lines` — 18 (27px), клетка `grid`/`dots` — 12 (18px), крупная
клетка `mm` — 30 (45px ≈ 1 см на экране). Сама разлиновка серая
(вспомогательная сетка, не смысловая линия — см. ч/б-принцип выше), кроме
`lines`: там линия под запись чёрная пунктирная, как была у прежней
`.solution-line`.

## Списки (`list_html`) — зебра-полоски

Одноколоночные списки (`.list-component.cols-single .list-row`) чередуют
белый фон и `#f2f2f2` (`nth-child(even)`) без зазоров между строками — это
помогает визуально не потерять, какому пункту соответствует какая
отметка/квадрат в длинном списке. Правило действует одинаково для всех видов
вопросов, использующих `list` (`choice`/`true_false`/`rank`/`classify`/
`match`) — единый визуальный язык, а не по одному правилу на каждый вид.
Двухколоночные (`cols-two`) и строчные (`cols-inline`) списки зебру не
получают.

## Настройка вёрстки — только через JSON, не в браузере

Единственный способ что-то настроить — соответствующее поле в JSON
(`ruling`/`rows`/`cols` на `paper`, `marker`/`columns` на `list`,
контейнер `row` для раскладки — см. `document-schema.md`) и пересборка `python -m worksheet_builder`.
HTML в браузере — чистый рендер этих значений, без JS-переключателей поверх
них; клиентского JS, кроме KaTeX, в документе нет.

## Локализация служебных строк

Все фиксированные надписи документа (шапка, "Ответ:", "Ответы",
"Пояснение:", "Верно"/"Неверно", суффикс баллов, `<title>`) идут через один
плоский словарь `STRINGS` (`worksheet_builder/strings.py`; документ только
русскоязычный, поэтому без языкового ключа и fallback-логики). Там же —
перечислительный ряд букв `LETTERS`. Не хардкодь эти строки в разметке
напрямую.

## Полный документ vs раздаточный вариант

Рендерер собирает оба файла из одних и тех же `blocks/*.json` — учитель не
должен вести два источника правды:
- Полный `document.html`: тела блоков + секция «Ответы» в конце + встроенный
  черновик (`<script id="document-source">`) для продолжения правок в новой
  сессии.
- Раздаточный `document-no-answers.html` (`--no-answers`): те же тела, но
  без секции ответов и без встроенного черновика (он раскрыл бы ответы
  через исходный код страницы). Тела заданий ответов не содержат по
  построению, поэтому больше ничего скрывать не нужно.
