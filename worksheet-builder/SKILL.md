# Worksheet Builder

Создаёт печатные рабочие листы (HTML, для печати на ч/б принтере через диалог
браузера) с гарантированно единым визуальным стилем: шрифт, поля, отступы,
нумерация, шапка — все листы, собранные этим skill'ом, выглядят как один
комплект, даже если готовились в разных сессиях.

## Модель работы: контент отдельно от вёрстки

Учитель редко формулирует задание идеально с первого раза — просит переделать
одно, добавить график в другое, убрать третье. Если бы весь лист был одним
HTML-документом, каждая такая правка требовала бы перечитать и переписать
целиком файл — дорого и рискованно для консистентности.

Поэтому рабочий лист собирается в два слоя:

1. **Черновик — JSON-файлы**, по одному на задание. Здесь и происходит вся
   работа с тобой в диалоге: обсуждение темы, формулировка задач, правки.
   Правишь только тот файл, который меняется — остальные не трогаешь и не
   перечитываешь.
2. **Сборка — детерминированный скрипт** (`scripts/render_worksheet.py`),
   который превращает JSON-черновики в готовый HTML. Скрипт, а не ты,
   отвечает за то, чтобы шрифты/отступы/нумерация были одинаковыми во всех
   заданиях — визуальную консистентность гарантирует код, а не память о
   том, что использовалось в прошлом сообщении.

**Никогда не пиши финальный HTML рабочего листа руками.** Твоя работа —
контент в JSON по схеме из `references/task-schema.md`; вёрстку делает скрипт.

## Фаза 1 — обсуждение и черновик

1. Проясни с учителем: тема, класс/возраст, цели урока, язык (`ru`/`kk`),
   примерный набор типов заданий и сколько их. Не нужно требовать это всё
   сразу единым брифом — можно начинать с одного-двух заданий и добавлять по
   ходу разговора.
2. Заведи папку черновика в текущей директории учителя, слаг по теме
   (например `kinematics-9th-grade/`), и `meta.json` внутри — см.
   `references/task-schema.md`.
3. На каждое задание — свой файл `tasks/task-NN.json`. Выбери тип задания под
   контент (текстовое, соответствие, правда/ложь, вопрос с вариантами ответа,
   заполнить пропуск/таблицу, график, иллюстрация) и заполни поля по схеме.
   Если задание естественно распадается на пункты а)/б)/в) с общим контекстом
   (например, общий график один на несколько вопросов) — используй тип
   `compound`, а не отдельные пронумерованные задания. Если учитель прислал
   готовую задачу — просто оформи её в нужный тип. Если попросил "придумай 3
   задачи по теме X" — сочиняй сам, ориентируясь на класс/уровень.
4. Греческие буквы, знаки сравнения, единицы измерения, простые степени/индексы
   и даже простые уравнения без дробей/корней — пиши обычным текстом (`α`,
   `≠`, `м/с²`, `υ₀`, `υ = υ₀ + at`), не LaTeX. Скорость обозначай греческой
   `υ` (ипсилон), не латинской `v` — см. предупреждение о похожих буквах в
   `references/symbols.md`. Там же — полный список готовых символов и когда
   индекс/степень не выразить Unicode-символом (нужны `<sup>`/`<sub>`) и когда
   выражение уже достаточно сложное, чтобы оправдать LaTeX (дробь, корень с
   содержимым, система уравнений — например, `$$E_k=\frac{m\upsilon^2}{2}$$`).
   Единицы измерения — СИ по
   умолчанию.
5. Для графиков — не рисуй SVG сам, дай данные в `chart_spec` (см.
   `references/charts-and-graphs.md`). Для иллюстраций — сначала проверь,
   нет ли готового генератора в словаре `SVG_SNIPPETS` внутри
   `scripts/render_worksheet.py`.
6. Правка = редактирование одного `task-NN.json`. Не открывай и не переписывай
   другие файлы или уже собранный HTML ради одной правки.
7. Если учитель хочет посмотреть, как будет выглядеть конкретное задание
   прямо сейчас — необязательно собирать весь лист:
   ```
   python scripts/render_worksheet.py <папка> --task task-03
   ```
   выдаёт `task-03.preview.html` с этим заданием в реальных стилях.

## Фаза 2 — сборка

Когда учитель говорит "собери лист"/"готово, покажи целиком" — запусти:
```
python scripts/render_worksheet.py <папка>
```
Это создаст `<папка>/output/worksheet-student.html` (для учеников, без
ответов) и `<папка>/output/worksheet-teacher.html` (с ответами, выделенными
под каждым заданием). Оба файла — самодостаточный HTML, печатаются через
Ctrl+P в браузере (A4, поля и разбивка страниц уже настроены под ч/б печать).
На экране страницы уже видно, сколько листов получится при печати (см.
"Page-view" в `design-system.md`), а панель "Поля печати" вверху страницы
позволяет тут же, в браузере, переключить поля на "По умолчанию"/"Нет"/
"Минимум" — те же варианты, что в диалоге печати Chrome; выбор сразу видно
на экране и он же применяется при печати, если поля в самом диалоге Chrome
оставить как есть ("По умолчанию").

Если в диалоге печати Chrome включена галочка "Заголовки и нижние
колонтитулы" (включена по умолчанию), браузер сам допечатает мелкую строку
с датой/адресом страницы/номером страницы в поля — это настройка самого
Chrome, а не рабочего листа, и в HTML/CSS её не отключить; если учителю она
не нужна, надо снять галочку в диалоге печати ("Ещё настройки").

Скажи учителю, что оба файла готовы и где они лежат; предложи открыть в
браузере, чтобы проверить перед печатью. Упомяни, что часть блоков (график,
иллюстрация, текст с решением, вопрос с вариантами) прямо в браузере имеет
маленький тулбар под собой — можно на месте покрутить ширину/положение
рисунка, скрыть/показать место для решения или переключить раскладку
вариантов ответа, без пересборки; при печати эти тулбары не попадают на
бумагу (см. "Интерактивные элементы вёрстки" в `design-system.md`).

**Статус: экспорт в Word приостановлен, не предлагай его учителю проактивно.**
Флаг `--docx` (`python scripts/render_worksheet.py <папка> --docx`,
реализация в `scripts/render_worksheet_docx.py`) существует и на автотестах
(программная проверка структуры получившегося `.docx` через `python-docx` —
число параграфов/таблиц/картинок, ru/kk-локализация) работает без ошибок, но
**ни разу не проверялся визуально в настоящем Word/LibreOffice** — только
структурно. Пока эта проверка не пройдена и работа не возобновлена явно, не
упоминай `--docx` в разговоре с учителем сам; если он попросит Word-версию
напрямую — можно предложить попробовать, но сразу предупреди, что вёрстка не
проверена глазами и может выглядеть не так, как задумано. Подробности того,
что уже сделано и какие упрощения в ней осознанные (не баги) — раздел
"Экспорт в Word" в `design-system.md`.

## Локализация: русский/казахский

Служебные подписи листа (шапка, "Ответ:", "Верно"/"Неверно", тулбар)
переключаются автоматически полем `meta.json → "language"` (`"ru"`/`"kk"`) —
ничего вручную переводить не надо. Если учитель просит казахскую (или
обратно русскую) версию **содержимого** уже готового листа — это отдельный
ручной перевод в новую соседнюю папку, не в оригинал; см.
`references/translation.md` за пошаговым воркфлоу и списком, какие поля
task-*.json переводятся, а какие остаются как есть.

## После сборки — правки

Если после просмотра собранного листа нужно что-то поменять: правь
соответствующий `task-NN.json` (или `meta.json`, если это шапка/порядок) и
запусти сборку заново. Пересборка — мгновенная и бесплатная (детерминированный
скрипт, не LLM-генерация), можно повторять сколько угодно раз, не тратя
контекст на чтение HTML.

## Справочники

- `references/task-schema.md` — полная схема `meta.json` и всех типов заданий.
  Читай перед созданием/правкой JSON, особенно для типов, которые давно не
  использовал.
- `references/symbols.md` — готовые Unicode-символы (операторы, сравнение,
  греческий алфавит, над/подстрочные цифры) и правило, когда переходить на
  `<sup>`/`<sub>` или на LaTeX. Проверяй здесь перед тем, как писать `$...$`
  ради одной буквы или значка.
- `references/design-system.md` — визуальная система (шрифты, поля, нумерация,
  шапка). Обычно не нужен для повседневной работы — редактируется только если
  учитель просит поменять стиль для *всех будущих* листов, а не для одного
  задания.
- `references/charts-and-graphs.md` — формат `chart_spec`, ч/б-безопасный
  визуальный код графиков, и правила для `raw_svg`-иллюстраций, если готового
  генератора в `SVG_SNIPPETS` нет.
- `references/translation.md` — воркфлоу перевода содержимого листа на
  казахский (или обратно на русский): что переводится, что нет, куда класть
  результат.
- `scripts/render_worksheet.py` — сам рендерер; `--help` покажет все опции.
- `examples/kinematics-9th-grade/` — рабочий пример черновика, покрывающий все
  типы заданий (включая график и иллюстрацию наклонной плоскости, составное
  задание `compound` с пунктами а)/б) и `multiple_choice`), плюс задание 9,
  которое демонстрирует иерархию текст/`<sup>`-`<sub>`/LaTeX из `symbols.md`
  на практике. Запусти на нём рендерер, если нужно быстро посмотреть, как
  выглядит готовый лист, или использовать как образец при написании нового
  `task-NN.json`.
- `examples/kinematics-9th-grade-kk/` — казахский перевод двух заданий из
  примера выше (`task-01`, `task-04`), образец для `references/translation.md`:
  как выглядит переведённая пара `meta.json`/`tasks/*.json` в отдельной папке.
