# Структура документа

Черновик — это папка:

```
kinematics-9th-grade/
  document.json          манифест: порядок блоков и заголовок вкладки
  blocks/
    theory-intro.json    по файлу на верхнеуровневый блок
    task-01.json
    task-02.json
```

Имя файла = `id` блока = запись в `order`. Расхождение — ошибка сборки.

## `document.json`

Обычный манифест — только порядок блоков:

```json
{ "order": ["task-01"] }
```

| поле | обяз. | смысл |
|---|---|---|
| `title` | нет | заголовок вкладки браузера; на листе ничего не печатает |
| `order` | нет | порядок блоков; без него берутся все файлы `blocks/` по алфавиту |

**Всё, что видно на листе, — блоки.** Шапки как поля манифеста не
существует: название, предмет и инструкция собираются из обычных блоков и
стоят в `order` первыми — сколько нужно и в каком угодно порядке. Поэтому
шапка бывает любой: работе на урок — с предметом и классом, конспекту — с
одним названием, а одиночному заданию — никакой.

```json
{ "type": "heading", "level": 1, "text": "Кинематика: равномерное движение" }
{ "type": "text", "body": "Физика · 9 класс. Внимательно прочитайте условие каждой задачи." }
{ "type": "divider" }
```

**Полей «Фамилия», «Класс», «Дата» скилл не ставит.** Ни строчками под
запись, ни таблицей — где ученик подписывается, решает учитель, и просит об
этом отдельно.

**Место для записи в строке — подчёркивания.** Три подряд и больше в тексте
превращаются в линию под запись, длиной ровно во столько же знаков: `Вывод:
______________`. Это разметка бумаги, ответа у неё нет и в «Ответы» она не
попадает; пропуск с ответом — это `___имя___` в вопросе `fill_text`, и в
`text` он запрещён.

## Верхний уровень

Один файл в `blocks/` = один блок. На верхнем уровне бывают:

- `heading` — название документа (`level` 1) или заголовок раздела (`level` 2);
- любой **компонент** (список ниже) — теория, иллюстрация, место под запись;
- `task` — нумерованное задание;
- `row` — несколько компонентов в одну строку.

Вопросы и `part` на верхнем уровне **не бывают** — только внутри `task`.
Задания нумеруются сквозняком по порядку появления; теория между ними
номера не сдвигает.

## Компоненты

Компонент ничего не знает про вопрос и ответ — он просто рисует то, что ему
передали. Полей `answer`/`correct` у компонента не бывает.

{{COMPONENT_TABLE}}

```json
{ "type": "text", "body": "Автомобиль движется равномерно со скоростью υ = 72 км/ч." }
{ "type": "heading", "text": "Практика: приборы и погрешности" }
{ "type": "list", "items": ["путь", "скорость", "время"], "marker": "number" }
{ "type": "table", "headers": ["t, с", "s, м"], "rows": [["0", "0"], ["2", "20"]] }
{ "type": "answer_line" }
{ "type": "divider" }
```

`heading`: `level` — 1 у названия документа, 2 (по умолчанию) у раздела.
Третьего уровня нет.

`list`: `marker` — `none`/`number`/`letter`, `columns` — `single`/`two`/`inline`.
В двух колонках пункты идут сверху вниз: из восьми пунктов 1–4 слева, 5–8 справа.
`table`: длина каждой строки равна числу заголовков.

Иллюстрации (`graph`, `instrument`, `paper`) — тоже компоненты, их поля
описаны в `visuals.md`.

## Задание

`task` — дерево блоков. Внутри: компоненты, ровно один вопрос **или**
несколько подзаданий `part`, и layout-контейнер `row`.

```json
{
  "type": "task",
  "id": "task-01",
  "blocks": [
    { "type": "text", "body": "Какой путь пройдёт автомобиль за 15 минут?" },
    { "type": "open", "answer": "18 км" },
    { "type": "paper", "ruling": "lines", "rows": 3 }
  ]
}
```

С подзаданиями:

```json
{
  "type": "task",
  "id": "task-10",
  "blocks": [
    { "type": "text", "body": "На графике показана скорость велосипедиста." },
    { "type": "graph", "x_label": "t, с", "y_label": "υ, м/с",
      "x_range": [0, 4], "y_range": [0, 10],
      "series": [{ "points": [[0, 0], [4, 8]] }] },
    { "type": "part", "blocks": [
      { "type": "text", "body": "Найдите ускорение." },
      { "type": "open", "answer": "a = 2 м/с²" },
      { "type": "answer_line" }
    ]},
    { "type": "part", "blocks": [
      { "type": "text", "body": "Найдите путь за 4 с." },
      { "type": "open", "answer": "s = 16 м" },
      { "type": "paper", "ruling": "lines", "rows": 3 }
    ]}
  ]
}
```

Правила состава — они же причина, по которой нумерация подзаданий остаётся
тривиальной («буква = `part`, по порядку»):

- у каждого вопроса на пути к корню задания есть блок `text` с условием;
- `part` и голый вопрос не бывают соседями: либо один вопрос на задание,
  либо каждый завёрнут в свой `part`;
- в `part` — ровно один вопрос; `part` в `part` не вкладывается;
- буквы выдаются автоматически (`а`, `б`, `в`…); явный `label` возможен, и
  автоматические буквы его пропускают;
- `id` внутри задания уникальны.

**Однотипная серия — одно задание.** Десять примеров «переведите в СИ» или
«выполните действия со степенью 10» под общей формулировкой — это один
`task` с подзаданиями, а не десять заданий подряд: номер задания — единица
работы, буква подзадания — единица упражнения. У каждого пункта своё место
для записи и своя строка в «Ответах», а раскладываются они в две колонки
строкой `row` — сразу ниже.

## Строка `row`

Дети `row` делят строку поровну. Это **только раскладка**: для инвариантов
состава и для букв подзаданий `row` прозрачен — его дети считаются стоящими
на уровне родителя.

| поле | обяз. | смысл |
|---|---|---|
| `blocks` | да | дети: компоненты, вопросы, `part` |
| `columns` | нет | 2–4 колонки; без него — по колонке на каждого ребёнка |

```json
{ "type": "row", "blocks": [
  { "type": "part", "blocks": [
    { "type": "text", "body": "Определите цену деления." },
    { "type": "instrument", "kind": "speedometer", "unit": "км/ч",
      "min": 0, "max": 200, "step": 5, "value": 95 },
    { "type": "open", "answer": "5 км/ч" }
  ]},
  { "type": "part", "blocks": [
    { "type": "text", "body": "Запишите длину бруска." },
    { "type": "instrument", "kind": "ruler", "unit": "см",
      "min": 0, "max": 10, "step": 0.1, "value": 6.4 },
    { "type": "open", "answer": "6,4 ± 0,05 см" }
  ]}
]}
```

С `columns` дети переносятся по колонкам построчно — это форма для серии
однотипных коротких подзаданий, которые иначе тянутся вниз страницы одним
столбиком:

```json
{ "type": "row", "columns": 2, "blocks": [
  { "type": "part", "blocks": [
    { "type": "fill_text", "template": "10³ · 10² = ___r___",
      "blanks": { "r": "10⁵" } }
  ]},
  { "type": "part", "blocks": [
    { "type": "fill_text", "template": "10⁶ : 10² = ___r___",
      "blanks": { "r": "10⁴" } }
  ]}
]}
```

**Короткий пункт со знаком равенства — это пропуск, а не `answer_line`.**
Место для записи встаёт в ту же строку сразу за «=», отдельная строка
«Ответ: ____» под однострочным пунктом только съедает лист. Условие такому
подзаданию не нужно — его несёт `text` на уровне задания («Выразите величины
в единицах СИ»), а единица измерения печатается в шаблоне после пропуска:
`"72 км/ч = ___v___ м/с"`. `open` с `answer_line` остаётся для настоящих
задач, где ответу предшествует решение.

Восемь таких подзаданий кладутся в **один** `row` с `"columns": 2`, а не
разбиваются на четыре `row` по паре: раскладка — дело рендерера, автор
перечисляет пункты подряд. Колонки заполняются сверху вниз: из восьми
подзаданий а)–г) встанут в левой колонке, д)–з) в правой.

`row` в `row` не вкладывается. На верхнем уровне документа в `row` можно
класть только компоненты и подзаголовки — `columns` там работает так же.

## Вопросы

Вопрос несёт содержимое и правильный ответ **вместе, в одном объекте**.
В теле задания ответ не печатается никогда — рендерер собирает ответы в
секцию «Ответы» в конце документа.

{{QUESTION_TABLE}}

Общее у всех видов: `type`, необязательный `id`, необязательный
`explanation` — пояснение к ответу, печатается в секции «Ответы» под ним.
Нумерация на вопросе не живёт: номер задания даёт порядок в документе, букву
подзадания — контейнер (`part.label`). Баллов в документе нет вовсе: лист
печатается без них, поля для оценки не существует.

Поля каждого вида и примеры — в `questions.md`.

### Набор, из которого выбирает ученик

Четыре вида предлагают готовый набор: `options` у `choice`, `right` у
`match`, `categories` у `classify`, `bank` у `fill_text` и `fill_table`.
Поле у каждого своё, но правила у всех одни:

- **лишнее значение — дистрактор.** Единица, к которой не подходит ни одна
  величина; слово в банке, которого нет ни в одном пропуске; группа, в
  которую никто не попал. Просят «добавь пару лишних» — это оно, и работает
  оно во всех четырёх видах одинаково;
- **значения не повторяются** — два одинаковых варианта или два одинаковых
  слова в банке схема отвергнет;
- **правильный ответ обязан быть в наборе.** Банк без нужного слова — лист,
  который нельзя заполнить, поэтому это ошибка, а не предупреждение;
- **`options` и `right` печатаются буквами**, поэтому в них не больше 28
  пунктов.

Одно значение может отвечать нескольким пунктам: у двух величин бывает одна
единица измерения, в одну группу попадает сколько угодно объектов.

## Текст и экранирование

Во всех текстовых полях пиши **обычный текст**. Рендерер экранирует его сам,
поэтому HTML-разметка в JSON не нужна и не сработает — кроме двух тегов:

- `<sup>…</sup>` и `<sub>…</sub>` — верхний и нижний индекс;
- `$…$` и `$$…$$` — формула LaTeX (в HTML нужен интернет при открытии
  файла; в Word переводится закрытый набор конструкций, остальное приедет
  текстом — список в `symbols.md`).

Приоритет — от простого к сложному, подробно в `symbols.md`.

Пропуск `___имя___` внутри `$…$` — ошибка сборки: формула так не собирается.
Пропуск ставится рядом с формулой, а не внутри неё.

## Что схема отвергнет

Ошибка называет путь до значения и подсказывает похожее имя:

```
task-10 -> blocks[2] -> series[0] -> points: нужно хотя бы 1 элемент(ов), получено 0
task-03: неизвестное поле 'x_labels'; возможно, имелось в виду 'x_label'
task-07 -> blocks[1]: у вопроса нет условия — добавь блок 'text' с формулировкой
```

Все ошибки черновика печатаются одним списком — чини за один проход.

## Явно вне scope

- **Иллюстрации, кроме перечисленных в `visuals.md`.** Схема опыта,
  электрическая цепь, наклонная плоскость пока не поддерживаются — опиши
  условие текстом и скажи об этом учителю.
- **Вёрстка под печать.** Документ — экранный; полей A4, разрывов страниц
  и `@media print` нет намеренно.
- **Изменение стиля.** Шрифты, отступы, цвета зафиксированы кодом
  рендерера и в сессии не меняются.
- **Инлайн-ответы под вопросом.** Ответы бывают только секцией в конце.
