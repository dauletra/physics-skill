# Worksheet Builder

Создаёт рабочие листы — самодостаточный HTML с гарантированно единым
визуальным стилем: шрифт, отступы, нумерация, шапка — все листы, собранные
этим skill'ом, выглядят как один комплект, даже если готовились в разных
сессиях. Лист — сплошной читаемый документ в центрированной колонке
(~800px), открывается в любом браузере.

## Установка (один раз)

Для запуска нужен только **uv** — Python на машине не обязателен: uv сам
скачает управляемый CPython и зависимости при первом запуске (первый запуск
может занять пару минут на скачивание, дальше — мгновенно из кэша).
Если команда `uv --version` не находится, предложи учителю установить uv
одной командой PowerShell (после установки — перезапустить терминал):

```
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

(альтернатива, если есть winget: `winget install --id=astral-sh.uv -e`).
Ничего больше ставить не нужно — ни Python, ни pip, ни пакет рендерера.

Все команды рендерера запускай через uv, указывая путь к папке этого skill:

```
uv run --project <путь-к-skill> render-worksheet <папка-черновика>
```

Фолбэк для машин, где uv нет, а Python 3.10+ уже есть:
`pip install -e <путь-к-skill>` — после этого те же команды доступны
напрямую (`render-worksheet …` или `python -m worksheet_builder …`).

## Модель работы: контент отдельно от вёрстки

Учитель редко формулирует задание идеально с первого раза — просит переделать
одно, добавить график в другое, убрать третье. Если бы весь лист был одним
HTML-документом, каждая такая правка требовала бы перечитать и переписать
целиком файл — дорого и рискованно для консистентности.

Поэтому рабочий лист собирается в два слоя:

1. **Черновик — JSON-файлы**, по одному на задание. Здесь и происходит вся
   работа с тобой в диалоге: обсуждение темы, формулировка задач, правки.
   Правишь только тот файл, который меняется — остальные не трогаешь и не
   перечитываешь.
2. **Сборка — детерминированный рендерер** (`render-worksheet` через uv),
   который превращает JSON-черновики в готовый HTML. Рендерер, а не ты,
   отвечает за то, чтобы шрифты/отступы/нумерация были одинаковыми во всех
   заданиях — визуальную консистентность гарантирует код, а не память о
   том, что использовалось в прошлом сообщении.

**Никогда не пиши финальный HTML рабочего листа руками.** Твоя работа —
контент в JSON по схеме из `references/task-schema.md`; вёрстку делает
рендерер. Схема проверяется при сборке (pydantic): опечатка в имени поля,
неизвестное значение перечисления, битая ссылка — всё это ошибки с точным
путём до блока, и рендерер перечисляет их все разом.

## Фаза 1 — обсуждение и черновик

1. Проясни с учителем: тема, класс/возраст, цели урока, примерный набор
   типов заданий и сколько их. Не нужно требовать это всё
   сразу единым брифом — можно начинать с одного-двух заданий и добавлять по
   ходу разговора.
2. Заведи папку черновика в текущей директории учителя, слаг по теме
   (например `kinematics-9th-grade/`), и `meta.json` внутри — см.
   `references/task-schema.md`.
3. На каждое задание — свой файл `tasks/task-NN.json`; `id` внутри файла
   обязан совпадать с именем файла, а если в `meta.json` задан `order` — файл
   обязан быть в нём перечислен (иначе сборка упадёт с ошибкой, а не молча
   пропустит задание). Задание — это дерево
   `blocks`, а не один тип на всё задание: блок — либо чистый компонент
   (`text`/`table`/`graph`/`list` — просто показывается, без буквы, без
   ответа), либо вопрос (один из 9 педагогических видов: `open`, `choice`,
   `match`, `fill_text`, `fill_table`, `plot`, `true_false`, `rank`,
   `classify` — несёт контент и ответ вместе, ответ инлайн, своей формой JSON
   для каждого вида), либо контейнер-подзадание `part` (см.
   `references/task-schema.md`, принципы — в
   `references/schema-design-principles.md`). Простое задание — компоненты
   условия + один вопрос, без `part`. Задание из нескольких пунктов а)/б)/в)
   — общий контекст (текст, график) на уровне задания, а затем по одному
   `part` на пункт: внутри — компоненты условия этого пункта + ровно один
   вопрос; буквы (кириллические а), б), в)…) расставляются сами, баллы
   пункта — `points` на `part`. Голый вопрос рядом с `part` не ставится —
   если пунктов больше одного, каждый оборачивается в свой `part`. Если
   учитель прислал готовую задачу — просто оформи её в нужный вид вопроса.
   Если попросил "придумай 3 задачи по теме X" — сочиняй сам, ориентируясь
   на класс/уровень. Иллюстрации/схемы (наклонная плоскость, электрическая
   цепь и т.п.) сейчас не поддерживаются — только графики (`graph`/`plot`);
   если задача требует рисунка, опиши её условие текстом без изображения.
   Если блоки должны стоять рядом (два подзадания с графиками, две таблицы)
   — оберни их в layout-контейнер `row`: дети всегда делят строку поровну,
   `row` прозрачен для букв и инвариантов. Одиночный график в `row` не
   заворачивай — его ширина и так ограничена дизайн-системой.
4. Греческие буквы, знаки сравнения, единицы измерения, простые степени/индексы
   и даже простые уравнения без дробей/корней — пиши обычным текстом (`α`,
   `≠`, `м/с²`, `υ₀`, `υ = υ₀ + at`), не LaTeX. Скорость обозначай греческой
   `υ` (ипсилон), не латинской `v` — см. предупреждение о похожих буквах в
   `references/symbols.md`. Там же — полный список готовых символов и когда
   индекс/степень не выразить Unicode-символом (нужны `<sup>`/`<sub>`) и когда
   выражение уже достаточно сложное, чтобы оправдать LaTeX (дробь, корень с
   содержимым, система уравнений — например, `$$E_k=\frac{m\upsilon^2}{2}$$`).
   Единицы измерения — СИ по
   умолчанию.
5. Для графиков (`graph`/`plot`) — не рисуй SVG сам, дай данные в
   `x_range`/`y_range`/`series` (см. `references/charts-and-graphs.md`).
6. Правка = редактирование одного `task-NN.json`. Не открывай и не переписывай
   другие файлы или уже собранный HTML ради одной правки.
7. Если учитель хочет посмотреть, как будет выглядеть конкретное задание
   прямо сейчас — необязательно собирать весь лист:
   ```
   uv run --project <путь-к-skill> render-worksheet <папка> --task task-03
   ```
   выдаёт `task-03.preview.html` с этим заданием в реальных стилях. По
   умолчанию превью тичерское (с ответами); `--mode student` — версия
   ученика.

## Фаза 2 — сборка

Когда учитель говорит "собери лист"/"готово, покажи целиком" — запусти:
```
uv run --project <путь-к-skill> render-worksheet <папка>
```
Это создаст `<папка>/output/worksheet-student.html` (для учеников, без
ответов) и `<папка>/output/worksheet-teacher.html` (с ответами, выделенными
под каждым заданием). Оба файла — самодостаточный HTML, открываются в любом
браузере (для формул нужен интернет — KaTeX подключается с CDN).

Если в черновике есть ошибки схемы, сборка упадёт со списком **всех**
нарушений разом (каждое — с путём до блока вида
`task-03 -> blocks[1] -> choice -> options[0]: …`) — исправь указанные
файлы и запусти сборку снова.

Скажи учителю, что оба файла готовы и где они лежат; предложи открыть в
браузере проверить. В браузере ничего в вёрстке поправить нельзя (никаких
тулбаров) — любая правка (место для решения, раскладка вариантов ответа,
раскладка компонентов) идёт через соответствующее поле JSON и пересборку.

## После сборки — правки

Если после просмотра собранного листа нужно что-то поменять: правь
соответствующий `task-NN.json` (или `meta.json`, если это шапка/порядок) и
запусти сборку заново. Пересборка — мгновенная и бесплатная (детерминированный
рендерер, не LLM-генерация), можно повторять сколько угодно раз, не тратя
контекст на чтение HTML.

## Справочники

- `references/task-schema.md` — полная схема `meta.json`, дерева блоков
  (`part`, `row`, 4 чистых компонента `text`/`table`/`graph`/`list`) и всех
  9 видов вопросов. Читай перед созданием/правкой JSON, особенно для видов,
  которые давно не использовал. Машиночитаемая копия —
  `references/task.schema.json` (генерируется командой
  `python -m worksheet_builder --emit-schema`).
- `references/schema-design-principles.md` — принципы, по которым устроена
  схема. Нужен, только если проектируешь новый вид блока (компонент/вопрос),
  а не при повседневном составлении заданий.
- `references/symbols.md` — готовые Unicode-символы (операторы, сравнение,
  греческий алфавит, над/подстрочные цифры) и правило, когда переходить на
  `<sup>`/`<sub>` или на LaTeX. Проверяй здесь перед тем, как писать `$...$`
  ради одной буквы или значка.
- `references/design-system.md` — визуальная система (оболочка листа, шрифты,
  нумерация, шапка). Обычно не нужен для повседневной работы — редактируется
  только если учитель просит поменять стиль для *всех будущих* листов, а не
  для одного задания.
- `references/charts-and-graphs.md` — формат данных графика (`x_range`/
  `y_range`/`series`) и ч/б-безопасный визуальный код рендерера.
- `references/artifacts/` — библиотека подробных справочников по SVG-артефактам,
  открывается по требованию (нужны нюансы конкретного вида, а не обзор):
  `README.md` — индекс + общие SVG-конвенции + чек-лист нового артефакта;
  `graphs.md` — разбор `line`/`bar`/`scatter`/`plot` по каждому типу.
- `worksheet_builder/` — пакет рендерера (`uv run --project <путь-к-skill>
  render-worksheet --help` покажет все опции): `models.py` (pydantic-валидация всей схемы),
  `components.py` (чистые компоненты), `questions.py` (9 педагогических
  видов), `document.py`, `render_helpers.py`, `visuals.py`, `assets.py`,
  `strings.py`, `cli.py`.
- `tests/` — golden-снапшоты рендера и негативная таблица валидации
  (`python -m pytest tests` из папки skill; пересъём эталонов —
  `REGEN_GOLDEN=1`, только при намеренном изменении рендера).
- `examples/kinematics-9th-grade/` — рабочий пример черновика, покрывающий
  все 9 видов вопросов и оба чистых визуальных компонента (`text`/`graph`) —
  включая задание с двумя подзаданиями-`part` а)/б) вокруг одного общего
  графика (`task-10`), задание с `row` из двух `part` бок о бок (50/50),
  каждый со своим `plot`, для построения графика p-V/p-T по данному V-T
  (`task-13`), и задание 9, которое демонстрирует иерархию
  текст/`<sup>`-`<sub>`/LaTeX из `symbols.md` на практике. Запусти на нём
  рендерер, если нужно быстро посмотреть, как выглядит готовый лист, или
  использовать как образец при написании нового `task-NN.json`.
