# Структура документа

Черновик — это папка:

```
kinematics-9th-grade/
  document.json          манифест: порядок блоков, при надобности шапка
  blocks/
    theory-intro.json    по файлу на верхнеуровневый блок
    task-01.json
    task-02.json
```

Имя файла = `id` блока = запись в `order`. Расхождение — ошибка сборки.

## `document.json`

Обычный манифест — только порядок блоков:

```json
{ "order": ["task-01"] }
```

| поле | обяз. | смысл |
|---|---|---|
| `title` | нет | название документа; одиночному заданию не нужно |
| `header` | нет | анкета-шапка: только раздаточной работе на несколько заданий |
| `order` | нет | порядок блоков; без него берутся все файлы `blocks/` по алфавиту |

`title` и `header` добавляются, когда документ раздают ученикам как
самостоятельную работу, — не по умолчанию:

```json
{
  "title": "Кинематика: равномерное движение",
  "header": {
    "school": "",
    "date": "",
    "subject": "Физика",
    "grade": "9",
    "instructions": "Внимательно прочитайте условие каждой задачи."
  },
  "order": ["theory-intro", "task-01", "task-02"]
}
```

Пустые поля `header` просто не печатаются: `school`/`date` дают пустые
строчки для заполнения от руки, `subject`/`grade` собираются в подзаголовок,
`instructions` — курсивная строка под ним.

## Верхний уровень

Один файл в `blocks/` = один блок. На верхнем уровне бывают:

- `heading` — подзаголовок раздела;
- любой **компонент** (список ниже) — теория, иллюстрация, место под запись;
- `task` — нумерованное задание;
- `row` — несколько компонентов в одну строку.

Вопросы и `part` на верхнем уровне **не бывают** — только внутри `task`.
Задания нумеруются сквозняком по порядку появления; теория между ними
номера не сдвигает.

## Компоненты

Компонент ничего не знает про вопрос и ответ — он просто рисует то, что ему
передали. Полей `answer`/`correct` у компонента не бывает.

{{COMPONENT_TABLE}}

```json
{ "type": "text", "body": "Автомобиль движется равномерно со скоростью υ = 72 км/ч." }
{ "type": "heading", "text": "Практика: приборы и погрешности" }
{ "type": "list", "items": ["путь", "скорость", "время"], "marker": "number" }
{ "type": "table", "headers": ["t, с", "s, м"], "rows": [["0", "0"], ["2", "20"]] }
{ "type": "answer_line" }
```

`list`: `marker` — `none`/`number`/`letter`, `columns` — `single`/`two`/`inline`.
`table`: длина каждой строки равна числу заголовков.

Иллюстрации (`graph`, `instrument`, `paper`) — тоже компоненты, их поля
описаны в `visuals.md`.

## Задание

`task` — дерево блоков. Внутри: компоненты, ровно один вопрос **или**
несколько подзаданий `part`, и layout-контейнер `row`.

```json
{
  "type": "task",
  "id": "task-01",
  "points": 2,
  "blocks": [
    { "type": "text", "body": "Какой путь пройдёт автомобиль за 15 минут?" },
    { "type": "open", "answer": "18 км" },
    { "type": "paper", "ruling": "lines", "rows": 3 }
  ]
}
```

С подзаданиями:

```json
{
  "type": "task",
  "id": "task-10",
  "blocks": [
    { "type": "text", "body": "На графике показана скорость велосипедиста." },
    { "type": "graph", "x_label": "t, с", "y_label": "υ, м/с",
      "x_range": [0, 4], "y_range": [0, 10],
      "series": [{ "points": [[0, 0], [4, 8]] }] },
    { "type": "part", "points": 2, "blocks": [
      { "type": "text", "body": "Найдите ускорение." },
      { "type": "open", "answer": "a = 2 м/с²" },
      { "type": "answer_line" }
    ]},
    { "type": "part", "points": 3, "blocks": [
      { "type": "text", "body": "Найдите путь за 4 с." },
      { "type": "open", "answer": "s = 16 м" },
      { "type": "paper", "ruling": "lines", "rows": 3 }
    ]}
  ]
}
```

Правила состава — они же причина, по которой нумерация подзаданий остаётся
тривиальной («буква = `part`, по порядку»):

- у каждого вопроса на пути к корню задания есть блок `text` с условием;
- `part` и голый вопрос не бывают соседями: либо один вопрос на задание,
  либо каждый завёрнут в свой `part`;
- в `part` — ровно один вопрос; `part` в `part` не вкладывается;
- буквы выдаются автоматически (`а`, `б`, `в`…); явный `label` возможен, и
  автоматические буквы его пропускают;
- `id` внутри задания уникальны.

## Строка `row`

Дети `row` делят строку поровну. Это **только раскладка**: для инвариантов
состава и для букв подзаданий `row` прозрачен — его дети считаются стоящими
на уровне родителя.

```json
{ "type": "row", "blocks": [
  { "type": "part", "blocks": [
    { "type": "text", "body": "Определите цену деления." },
    { "type": "instrument", "kind": "speedometer", "unit": "км/ч",
      "min": 0, "max": 200, "step": 5, "value": 95 },
    { "type": "open", "answer": "5 км/ч" }
  ]},
  { "type": "part", "blocks": [
    { "type": "text", "body": "Запишите длину бруска." },
    { "type": "instrument", "kind": "ruler", "unit": "см",
      "min": 0, "max": 10, "step": 0.1, "value": 6.4 },
    { "type": "open", "answer": "6,4 ± 0,05 см" }
  ]}
]}
```

`row` в `row` не вкладывается. На верхнем уровне документа в `row` можно
класть только компоненты и подзаголовки.

## Вопросы

Вопрос несёт содержимое и правильный ответ **вместе, в одном объекте**.
В теле задания ответ не печатается никогда — рендерер собирает ответы в
секцию «Ответы» в конце документа.

{{QUESTION_TABLE}}

Общее у всех видов: `type`, необязательный `id`, необязательный
`explanation` — пояснение к ответу, печатается в секции «Ответы» под ним.
Нумерация и баллы на вопросе не живут: это поля контейнеров (`task.points`,
`part.label`, `part.points`).

Поля каждого вида и примеры — в `questions.md`.

## Текст и экранирование

Во всех текстовых полях пиши **обычный текст**. Рендерер экранирует его сам,
поэтому HTML-разметка в JSON не нужна и не сработает — кроме двух тегов:

- `<sup>…</sup>` и `<sub>…</sub>` — верхний и нижний индекс;
- `$…$` и `$$…$$` — формула LaTeX (нужен интернет при открытии файла).

Приоритет — от простого к сложному, подробно в `symbols.md`.

Пропуск `___имя___` внутри `$…$` ломает формулу — не заворачивай в LaTeX
шаблон `fill_text`.

## Что схема отвергнет

Ошибка называет путь до значения и подсказывает похожее имя:

```
task-10 -> blocks[2] -> series[0] -> points: нужно хотя бы 1 элемент(ов), получено 0
task-03: неизвестное поле 'x_labels'; возможно, имелось в виду 'x_label'
task-07 -> blocks[1]: у вопроса нет условия — добавь блок 'text' с формулировкой
```

Все ошибки черновика печатаются одним списком — чини за один проход.

## Явно вне scope

- **Иллюстрации, кроме перечисленных в `visuals.md`.** Схема опыта,
  электрическая цепь, наклонная плоскость пока не поддерживаются — опиши
  условие текстом и скажи об этом учителю.
- **Вёрстка под печать.** Документ — экранный; полей A4, разрывов страниц
  и `@media print` нет намеренно.
- **Изменение стиля.** Шрифты, отступы, цвета зафиксированы кодом
  рендерера и в сессии не меняются.
- **Инлайн-ответы под вопросом.** Ответы бывают только секцией в конце.
